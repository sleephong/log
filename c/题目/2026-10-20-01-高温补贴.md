# L1-107 高温补贴

> 来源：PTA 团体程序设计天梯赛练习集 L1-107
> 平台：PTA，gcc（C99）
> 通用语法见 [notes/19-C语言基础.md](../../notes/19-C语言基础.md)；本篇只讲这道题。

## 一、题干

输入一行三个整数：

- T：当日最高气温，取值 [-40, 50]
- S：工作场所状态，1 表示露天，0 表示室内
- t：工作场所温度，取值 [-40, 50]

补贴的条件：气温 35 度以上（`T > 35`）**且**工作场所温度降不到 33 以下（`t >= 33`）**且**露天作业（`S = 1`）。

| 情况 | 判定 | 第一行 | 第二行 |
|---|---|---|---|
| 两个温度都超标，露天 | `T > 35` 且 `t >= 33` 且 `S = 1` | `Bu Tie` | T |
| 两个温度都超标，室内 | `T > 35` 且 `t >= 33` 且 `S = 0` | `Shi Nei` | T |
| 没超标，露天 | (`T <= 35` 或 `t < 33`) 且 `S = 1` | `Bu Re` | t |
| 没超标，室内 | (`T <= 35` 或 `t < 33`) 且 `S = 0` | `Shu Shi` | t |

两个容易反的点：

- 输出是拼音：Bu Tie = 补贴，Shi Nei = 室内，Bu Re = 不热，Shu Shi = 舒适
- 第二行有时是 **T**（温度超标时），有时是 **t**（不超标时）。超标时怪天气，所以报气温；不超标时怪场所，所以报场所温度

## 二、我的代码（原样）

```c
#include<stdio.h>
int main(){
    int T,s,t;
    scanf("%d %d %d",&T,&s,&t);
    if(T>35&&t>=33){
        if(s==1)
            printf("Bu Tie\n%d",T);
        else
            printf("Shi Nei\n%d",T);
    }
    else if((T<=35||t<33)&&s==1)
        printf("Bu Re\n%d",t);
    else if((T<=35||t<33)&&s==0)
        printf("Shu Shi\n%d",t);
    else
        printf("Bu Bu Tie");
}
```

## 三、逐段讲

`#include<stdio.h>`
    引入标准输入输出的声明，`scanf` / `printf` 都来自这里。

`int main(){ ... }`
    程序入口。函数体最后没写 `return 0;`，C99 下编译器会自动补一个 0，所以不算错。

`int T,s,t;`
    三个 int。T 是气温，s 是场所状态，t 是场所温度。T 和 t 只差大小写，读代码时容易看串，这是后话。

`scanf("%d %d %d",&T,&s,&t);`
    按顺序读三个整数。格式串里的空格作用是"跳过任意空白"，所以输入里是一个空格、多个空格还是换行都不影响。

`if(T>35&&t>=33)`
    把题面的两个温度条件合成一个判断。注意边界写法：气温是 `>`（35 度本身不算高温），场所温度是 `>=`（正好 33 度算"降不到 33 以下"）。

里面的 `if(s==1) ... else ...`
    温度已经超标，再分露天和室内：露天拿补贴，室内只是"因为室内才没有"，所以报 `Shi Nei`，第二行仍然输出 T，因为气温确实超标。

`else if((T<=35||t<33)&&s==1)`
    `T<=35||t<33` 正好是第一个条件的取反（德摩根定律），含义是"至少有一个温度没超标"。露天但温度不达标，输出 `Bu Re`，第二行 t。

`else if((T<=35||t<33)&&s==0)`
    同样的取反条件，室内，输出 `Shu Shi`，第二行 t。

最后的 `else`
    走不到。见第五节。

## 四、判断矩阵

把 T 和 t 各分成"超标 / 不超标"两档，S 两个取值，全部情况只有 4 种（不是 8 种，因为 T 与 t 在判断里是"同时成立"才超标）：

| T | t | S | 命中 | 输出 |
|---|---|---|---|---|
| 36 | 40 | 1 | 第一层 if，内层 if | `Bu Tie` / 36 |
| 36 | 40 | 0 | 第一层 if，内层 else | `Shi Nei` / 36 |
| 36 | 30 | 1 | 第一个 else if | `Bu Re` / 30 |
| 36 | 30 | 0 | 第二个 else if | `Shu Shi` / 30 |
| 35 | 40 | 1 | 第一个 else if（T 正好 35，不算高温） | `Bu Re` / 40 |
| 33 | 33 | 0 | 第二个 else if | `Shu Shi` / 33 |
| 50 | 33 | 1 | 第一层 if（t 正好 33，算超标） | `Bu Tie` / 50 |
| -40 | -40 | 0 | 第二个 else if | `Shu Shi` / -40 |

4 行就把所有情况用完了，所以最后那个 `else` 一次都不会执行。

## 五、问题与改法

| # | 问题 | 为什么要改 |
|---|---|---|
| 1 | 最后 `else printf("Bu Bu Tie")` 是死分支，而且这个字符串题面里没有 | 四支已经覆盖 S 的全部取值。死代码会让你误以为还漏了情况；真漏时它又吞掉错误，PTA 报 WA 但看不出原因 |
| 2 | 取反条件 `(T<=35||t<33)` 手抄了两遍 | 抄错一个 `<=` 或 `\|\|` 就悄悄错一支，而且很难看出来 |
| 3 | `scanf` 没检查返回值 | PTA 输入合法所以没事；一旦输入不完整，T/s/t 是未初始化的垃圾值，行为不可预期 |
| 4 | 没写 `return 0;` | 不算错（C99 隐式返回 0），但显式写出来更自解释 |
| 5 | 内层 if 没写花括号 | 现在没错，但以后想在内层加一行就很容易加错位置 |

## 六、参考写法

写法 A：条件只写一次，`else` 链的最后一支是真实情况（推荐）

```c
#include <stdio.h>

int main(void)
{
    int T, S, t;
    if (scanf("%d %d %d", &T, &S, &t) != 3) {
        return 0;
    }

    int too_hot = (T > 35 && t >= 33);   /* 两个温度都超标 */

    if (too_hot && S == 1) {
        puts("Bu Tie");
        printf("%d\n", T);
    } else if (too_hot) {
        puts("Shi Nei");
        printf("%d\n", T);
    } else if (S == 1) {
        puts("Bu Re");
        printf("%d\n", t);
    } else {
        puts("Shu Shi");
        printf("%d\n", t);
    }
    return 0;
}
```

改了什么：

- `too_hot` 把条件命名，else 分支不用再手写取反
- 最后一支 `else` 对应"室内 + 没超标"，是真实存在的情况，不是兜底死代码
- `puts` 输出字符串并自动换行，数字单独 `printf`，比 `"Bu Tie\n%d"` 少一次拼接

写法 B：保留嵌套，只修死分支（改动最小）

```c
if (T > 35 && t >= 33) {
    if (S == 1) {
        puts("Bu Tie");
    } else {
        puts("Shi Nei");
    }
    printf("%d\n", T);
} else {
    if (S == 1) {
        puts("Bu Re");
    } else {
        puts("Shu Shi");
    }
    printf("%d\n", t);
}
```

要点：外层只管"超标 / 不超标"，内层只管"露天 / 室内"，第二行输出按外层统一写一次。条件不用取反，也不会有死分支。
