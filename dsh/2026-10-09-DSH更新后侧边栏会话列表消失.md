## 二、知识点

### 1. 「数据没丢」和「界面看不见」要分开查

两条线各查各的，别混在一起猜：

```
数据层：磁盘日志（sessions\<id>\session.v4.jsonl.zstd）+ 投影缓存 + workspace.json 登记
界面层：客户端插件清单 → 插槽占用 → 渲染
```

这次数据层用两分钟就排除了（帧完整性校验 + 主机 RPC 直接列会话），后面所有时间都花在界面层。

### 2. Cordis 插槽是"单占位"的，占死就是空白

`sidebar.workspaces` 是 `kind: "single"` 的插槽：**一个占用者挂载失败 = 整个区域空白**，
不是"退回上一个占用者"。所以判断"某个插件坏没坏"，要看它有没有抢 UI 插槽。

### 3. peerDependencies 是硬门槛，先对版本再谈功能

插件跑不起来不等于功能有 bug，常常是版本区间不覆盖：

| 插件版本 | `dsh-session` peer 范围 | 当前 harness | 结果 |
|---|---|---|---|
| `@michengai/dsh-automation@0.1.44` | 最高 `0.1.6-alpha.1` | `0.1.7-rc.2` / `0.2.0-rc.2` | 不可用 |
| `@michengai/dsh-automation@0.1.61` | 含 `0.1.7-rc.2`、`0.2.0-rc.2` | 同上 | 可用 |

**先 `npm view <pkg> peerDependencies` 对区间，再看代码。**

### 4. Windows 上通知要两条腿走路

`notify.ps1` 的设计值得记：Toast 通知**会被专注助手（勿扰）吞掉**，
所以额外加一个 `TopMost` 弹窗 —— 置顶窗口不受专注助手影响。
实战结论：**只靠 Toast 会静默失败。**

## 三、案例 / payload

### 1. 直接问主机 RPC（绕过坏掉的界面）

界面坏了但主机是好的，可以直接调主机接口（和界面同一条通道）：

```powershell
# 从日志里拿启动 token
Select-String -Path "$env:APPDATA\dsh-desktop\logs\harness.log" -Pattern 'dsh web: http' | Select-Object -Last 1

# 用 token 换鉴权 cookie，再 POST 到 /api/<namespace>/<method>
# 请求体是 client-request 信封：{type, rpcId, method, payload}
# session/list 需要 {args:{_request:{}}}
```

拿到的会话列表和界面应该显示的一致 —— 用它就能证明"数据在不在"。

### 2. 让 DSH 下次启动直接打开指定会话

界面状态存在 `profiles\web\desktop-storage.json` 的 `dsh.sessions.current`（形如 `{"sessionId":"session-xxx"}`）：

```json
"dsh.sessions.current": "{\"sessionId\":\"session-454798f3-f5b4-47a9-a5bf-1d47d22e1460\"}"
```

改完重启 DSH 就落在那个会话 —— 界面再怎么坏，会话照样能打开。

### 3. 停用插件的正确姿势

改 profile 的 `cordis.patch.yml`（不是 `cordis.yml`）：

```yaml
- id: dsh-automation
  disabled: true
```

主机**会监听这个文件并热加载**，但：
- 宿主侧立即生效，**浏览器侧要刷新页面**（Ctrl+R）才会用上新插件清单
- 热"启用"一个会挂载失败的插件，会当场把界面搞坏 —— **启用类改动请重启，不要热切换**

### 4. 独立提醒脚本 + 计划任务

```powershell
# 注册：每天 23:00，仅在用户登录时运行（提醒要弹在桌面上）
$action  = New-ScheduledTaskAction -Execute 'powershell.exe' `
             -Argument "-NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File `"$script`""
$trigger = New-ScheduledTaskTrigger -Daily -At 23:00
$settings = New-ScheduledTaskSettingsSet -StartWhenAvailable -ExecutionPolicy Bypass
$principal = New-ScheduledTaskPrincipal -UserId "$env:USERDOMAIN\$env:USERNAME" `
               -LogonType Interactive -RunLevel Limited
Register-ScheduledTask -TaskName 'DSH-DailyNoteReminder' -Action $action -Trigger $trigger `
  -Settings $settings -Principal $principal
```

| 以为会话丢了 | 把"界面不显示"当成"数据没了" | 先验证数据层（帧完整性 + RPC 列表），再查界面 |
| 一开始归因到"折叠 5 条" | 症状相似（都像"只剩几条"） | 去日志里找报错，别靠症状猜 |

| 热切换插件把界面搞坏 | 失败的占用者当场抢走 `sidebar.workspaces` | 启用/停用插件后**重启**，别热切换 |
| 弹窗脚本退出码 1，以为失败 | stderr 里混着 `libpng warning: iCCP` 告警 | 看 stdout 的 `TOAST_OK` / `POPUP_OK`，别只看退出码 |

| 跨零点的日志容易记错天 | 凭"现在几点"判断 | 按**开始时间**归属：23:31 开始的记 10-09 |
