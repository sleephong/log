# C 语言基础（PTA 刷题沉淀）

## 1. 程序骨架

```c
#include <stdio.h>          /* 预处理：把 stdio.h 的声明原样抄进来 */

int main(void)              /* 入口；void 表示不收命令行参数 */
{
    int T, S, t;            /* 声明集中放在块首，好读 */

    if (scanf("%d %d %d", &T, &S, &t) != 3) {
        return 0;
    }

    printf("%d\n", T);
    return 0;               /* 告诉系统：正常结束 */
}
```

- `#include <stdio.h>`：`printf` / `scanf` / `puts` 的声明都在这里。漏了会报 `implicit declaration of function`
- `int main()` 与 `int main(void)`：C 里空括号表示"参数未指定"，不是"没有参数"；写 `void` 语义明确
- `return 0;`：C99 规定 main 不写也会返回 0，但显式写出来，读代码的人不用去查标准
- 不要在 PTA 的代码里加 `system("pause")`、`getch()`：多余输出会被判格式错误

## 2. 输入：scanf

```c
int a, b;
if (scanf("%d %d", &a, &b) != 2) {
    return 0;
}
```

| 点 | 说明 |
|---|---|
| `&` 取地址 | scanf 要把值写回变量，必须给地址。写成 `scanf("%d", a)` 是把 a 的值当地址用，一般直接段错误 |
| 返回值 | 成功赋值的项数；一个都没读到时返回 0，遇到输入结束返回 EOF（-1） |
| 格式串里的空格 | 不是"匹配一个空格"，而是"跳过任意多个空白字符（可以是 0 个）" |
| 类型要配对 | `%d` 对应 int，`%f` 对应 float，`%lf` 对应 double（读 double 必须用 `%lf`），`%c` 单个字符，`%s` 读到空白为止 |
| `%c` 的坑 | 前一次 `scanf("%d")` 留下的换行会被下一个 `%c` 吃掉；要读非空白字符用 `" %c"`（空格开头） |
| 格式串里的普通字符 | `:` `,` `-` 这些不是占位符，输入里必须原样出现，位置也要对；匹配不上时后面的转换会失败，变量保持原样（很可能是垃圾值） |

> PTA 的输入总是合法的，所以不写检查也能过；但自己写小工具时，这是最常见的崩溃来源。

### 2.1 `%s` 与字符数组

```c
char name[20];
scanf("%19s", name);        /* 正确：数组名本身就是首元素地址，不加 & */
```

- `%s` 要的是 `char *`。数组名传进去已经退化成 `&name[0]`，**再加 `&` 就错了**：`&name` 的类型是 `char (*)[20]`（指向整个数组的指针），gcc 会给 `-Wformat` 警告；因为两个地址的数值相同，运行时"碰巧能跑"，换编译器或者开 `-Werror` 就露馅
- 限宽：`%19s` 最多写 19 个字符，最后一位留给 `'\0'`。不写宽度时，输入超过数组长度就会写坏栈上的其他变量
- 数组长度要按题目的上限来定：`char name[20]` 只保证 19 个字符加 1 个结尾符
- `%s` 读到空白就停，存不了含空格的字符串；含空格要用 `fgets` 或 `scanf("%[^\n]", ...)`

## 3. 输出：printf

```c
printf("Bu Tie\n%d\n", T);   /* 两行一次输出 */
printf("%.2f\n", 3.14159);   /* 保留两位小数 */
```

- `\n` 是换行；写在字符串中间就把输出分成两行
- PTA 判题比对的是字符，**多一个空格、少一个换行都算错**（有时报"格式错误"而不是"答案错误"）
- 整数用 `%d`，长整型用 `%ld`（`long long` 用 `%lld`），浮点输出 `%f` 默认 6 位
- 只想输出一个字符串加换行，用 `puts("abc")` 比 `printf("abc\n")` 少打字符

## 4. 关系运算与逻辑运算

| 运算 | 写法 | 结果 |
|---|---|---|
| 比较 | `>` `>=` `<` `<=` `==` `!=` | 成立为 1，不成立为 0 |
| 与 | `&&` | 两边都非 0 才为 1 |
| 或 | `\|\|` | 有一边非 0 就为 1 |
| 非 | `!` | 0 变 1，非 0 变 0 |

优先级从高到低：`!` → 比较运算 → `&&` → `||`。

所以 `T <= 35 || t < 33 && S == 1` 实际是 `T <= 35 || (t < 33 && S == 1)`。
想表达"(温度不达标) 且 (露天)"，括号必须自己写：`(T <= 35 || t < 33) && S == 1`。

- 短路求值：`A && B` 里 A 为假就不算 B；`A || B` 里 A 为真就不算 B。`p != NULL && p->x` 靠这个才不会崩
- 判断相等是 `==`，不是 `=`。`if (x = 0)` 不报错，但条件永远是假（赋完值是 0）
- `-1 < x < 1` 在 C 里是 `(-1 < x) < 1`，永远为真；要写 `x > -1 && x < 1`

## 5. 把条件取反：德摩根

| 原条件 | 取反 |
|---|---|
| `A && B` | `!A \|\| !B` |
| `A \|\| B` | `!A && !B` |
| `T > 35 && t >= 33` | `T <= 35 \|\| t < 33` |

规律：`&&` 与 `||` 互换，每个比较符取反（`>` 换 `<=`，`>=` 换 `<`）。

边界最容易错：`T > 35` 的取反是 `T <= 35`，**不是** `T < 35`。T 正好 35 时属于"不超标"。

## 6. 分支结构

| 形态 | 适用 |
|---|---|
| `if (c) {...}` | 只有一种情况要处理，其余不做事 |
| `if (c) {...} else {...}` | 非此即彼 |
| `if (c1) {...} else if (c2) {...} else {...}` | 多种互斥情况，从上往下第一个成立的生效 |
| 嵌套 `if` | 情况有层次：先分组，再在组内分 |

- `else if` 链的每个条件都在前面全部不成立的前提下判断，所以条件里不必再"排除"前面几种
- 花括号：单条语句可以省，但**以后加一行**时最容易出错；同一个文件里要么全写，要么只在单行时省
- 悬垂 else：`else` 永远配**最近的**那个没配对的 `if`，缩进不改变配对关系
- 三分支以上、且每种输出能用一个表达式算出来的，可以考虑 `?:`；输出行数多的时候不要用，反而难读
- 独立 `if` 与 `else if` 的区别：条件**互斥**（一次只会发生一种）用 `else if`；条件**可能同时成立、每个都要查一遍**时用独立的 `if`。胎压监测那道题就是四个轮胎逐个检查，写成 `else if` 只会查到第一个出问题的轮胎

## 7. else 是"其余"，不是"其他情况"

`else` 的含义是"上面所有条件都不成立"，不是"我想象中的其他情况"。

- 如果前面几支已经把变量的全部取值覆盖完，最后的 `else` 就是**死分支**，永远不会执行
- 死分支的害处有两层：一是在你想清楚之前它掩盖了"到底漏没漏"；二是真漏了的情况会被它悄悄吞掉，输出一个自造的结果，PTA 报答案错误，你却找不到错在哪
- 检查办法：列出所有输入维度的取值组合（判断矩阵），逐行看命中哪一支。例子见 [高温补贴](../c/题目/2026-10-20-01-高温补贴.md) 第四节

## 8. 给条件起个名字

```c
int too_hot = (T > 35 && t >= 33);   /* 两个温度都超标 */

if (too_hot && S == 1) {
    /* ... */
} else if (too_hot) {
    /* ... */
}
```

- 条件只写一遍，取反不用手抄，避免抄错一个 `>` 或 `||`
- 名字本身就是注释，读代码不用心算
- 代价是一个 int；收益是每次改条件只改一处

## 9. 常见报错对照

| 现象 | 原因 |
|---|---|
| `implicit declaration of function 'printf'` | 没 `#include <stdio.h>` |
| 运行时崩溃 | `scanf` 少了 `&`，或数组越界 |
| 编译报 `stray '\xxx'` | 代码里混进了中文标点（全角括号、逗号） |
| 答案错误但逻辑看着对 | 死分支吞掉了漏掉的情况，或边界写错（`>` 与 `>=`） |
| 格式错误 | 多输出空格、少换行、多了提示语 |
| 只过部分测试点 | int 溢出，或多组输入只读了一组 |
| 死循环 | `while (scanf(...) != EOF)` 的循环体没有推进，或 `while (1)` 没有出口 |
| 只有 warning，程序照样跑 | `scanf("%s", &x)` 多写了一个 `&`，类型变成 `char (*)[20]`，地址数值相同所以碰巧能跑 |

## 10. 整数拆位与定宽输出

```c
int n = 199808;
int hi = n / 100;              /* 1998：丢掉低两位 */
int lo = n % 100;              /* 8：留下低两位 */
printf("%d-%02d\n", hi, lo);   /* 1998-08 */
```

- `/ 100` 和 `% 100` 是一对：一个取高位，一个取低位。换成 1000 就是取三位，换个除数就是换个进制位的边界
- 拆位对**前导零**是友好的：`0508` 读成 508，`508 / 100 = 5`、`508 % 100 = 8`，和按字符串拆一样。前提是高位的零对 `/`、`%` 都没有贡献，也就是"高位在前、低位固定位数"
- `%02d` 不足两位补 0，`%2d` 不足两位补空格，`%d` 不补。日期、时间、编号一律用补 0 的写法
- `%4d` / `%04d`：输出定宽年份，`1000` 和 `2021` 都是 4 位
- 用**数值大小**判断"几位数"只在特定输入范围里成立（4 位数最大 9999，6 位数最小 100000，中间有空档）。靠位数做逻辑时，读成字符串再 `strlen` 最稳

## 11. 打擂台、计数与记录位置

```c
int max = p1;                  /* 第一个先当擂主 */
if (p2 > max) max = p2;        /* 后面逐个挑战，赢了就换 */
if (p3 > max) max = p3;
if (p4 > max) max = p4;

int cnt = 0, pos = 0;
if (p1 < low || max - p1 > y) { cnt++; pos = 1; }   /* 命中就同时更新计数与位置 */
```

- 打擂台：先假定第一个是最大值，再让后面每个来挑战。比较用 `>`；相等时换不换都不影响结果
- 计数和位置要**一起更新**。常见错法是把取位置写成 `if (cnt == 1) pos = i;` 放进循环：后面的轮胎即使正常，也会把 `pos` 覆盖成自己的编号，最后报错的位置就不是出问题的那个
- 位置只在最后用一次，中途被覆盖无所谓。想更稳，可以把 `pos` 的更新放在命中条件里面，而不是在循环里另起一个判断
- 题目编号与数组下标差 1：`pos = i + 1`
- 这类"四段几乎一样的代码"是数组 + 循环的典型场景，学了数组再回来压，见 [胎压监测](../c/题目/2026-10-20-03-胎压监测.md) 第六节

## 12. 按题面写，不按常识

- 判题比对的是**题面**，不是现实世界的习惯。最典型的是"中午 12 点和 0 点算上午还是下午"：英文习惯里 0 点是 12:00 AM，但 PTA 7-7 明确要求 `0:0 AM`
- 这类约定（中午算哪半天、0 点怎么叫、四舍五入还是截断、能不能重复）先看题面；题面没写就看样例；样例也没有，就选最保守的写法，并在注释里写清依据
- 写"通用公式"之前先确认它在本题约定下成立：`h % 12` 对 0 点和 12 点都会给出 0，需要再补特判
- 反例的价值：同一个数据，题面里写错的答案就是错的，而你觉得"常识上对"。所以宁可多读一遍题面的那一句"注意"
