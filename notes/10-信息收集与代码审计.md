# 一、信息收集（**CTF 第一步**）

> **口诀：先翻源码，再扫敏感文件。** flag 常藏在"开发者没想到你会看到"的地方。

## 1.1 网页源码

```
Ctrl+U → 看 HTML 注释 <!-- -->
```
**注释里常藏**：提示、隐藏文件名、base64 编码的数据、甚至 flag。

**⚠️ 浏览器渲染 ≠ 源码**，必须看原始 HTML。

## 1.2 robots.txt / sitemap.xml

```
http://target/robots.txt        ← 常列出 Disallow 的敏感目录
http://target/sitemap.xml       ← 列出所有页面
```

**⚠️ 但很多题的 robots.txt 是"模板"，路径全 404，别死磕。**

## 1.3 备份文件（**极高频**）

| 备份名 | 说明 |
|---|---|
| `www.zip` / `web.zip` / `backup.zip` | 整站源码 |
| `index.php.bak` / `.php.bak` | 源码备份 |
| **`.swp`** / `.swo` / `.swn` / `~` / `.un~` | **vim 编辑器残留**（命名规则固定，一次全试） |
| `.DS_Store` | macOS 目录索引 |

**⚠️ 下载后先看魔数，后缀会撒谎**：
```
PK\x03\x04              → ZIP
Rar!\x1a\x07\x00        → RAR4
Rar!\x1a\x07\x01\x00    → RAR5
7z\xbc\xaf\x27\x1c       → 7z
\x1f\x8b                 → gzip
\x89PNG                 → PNG
```

**⚠️ `7zr.exe`（精简版）不支持 RAR5**，要完整版 `7z.exe`。

### ⭐ vim 交换文件命名规则（编辑 `index.php` 时）

```
.index.php.swp        ← 主交换文件（最常考）
.index.php.swo        ← 同名冲突时的第二个
.index.php.swn
index.php~            ← 备份文件
.index.php.un~        ← undo 历史
```

> **PolarCTF「swp」题就是靠 `GET /.index.php.swp` 直接拿到全部源码的**（返回 200 + 340 字节 = 源码泄露）。
> **候选集是有限的，一次全试完，别只试 `.swp`。**

## 1.4 Git 泄露

```
/.git/config          ← 第一步，看存不存在
/.git/HEAD
/.git/logs/HEAD       ← 能看到所有 commit
```

**工具**：`GitHack`、`git-dumper`

**⚠️ `.git` 泄露能扒出**全部源码 + 历史 commit**（里面常有被删的密码/flag）。**

## 1.5 目录/文件爆破

**工具**：`dirsearch`、`御剑`、Burp Intruder

**常见路径**：
```
robots.txt  sitemap.xml  www.zip  .git  .svn  .DS_Store
index.php.bak  index.php~  flag.php  admin.php  config.php
/api/  /admin/  /upload/  /backup/
```

## 1.6 前端 JS（**找接口必看**）

```
F12 → Sources → 看 .js 文件
搜: fetch / axios / /api/ /url
```

**JS 里 JS 常硬编码接口路径**：
```javascript
fetch('/api/user/info')
axios.get('/api/messages')
```

**⚠️ 看 JS 的四种方式**：
```
① Ctrl+U → Ctrl+F 搜 "fetch"     ← 看内联 JS、注释 ⭐
② F12 → Elements → Ctrl+F
③ F12 → Sources                    ← 调试、格式化
④ F12 → Network → 点按钮           ← 看实际请求 ⭐
```

## 1.7 ⭐ 信息面是「整个报文」，不只是 body

PolarCTF「seek flag」把 flag **拆成三段**，藏在三个不同层面 —— 这是「信息收集要覆盖全报文」最典型的教学题：

| 片段 | 位置 | 长度 |
|---|---|---|
| flag1 | **响应体**（且需 `Cookie: id=1` 才回显） | 5 |
| flag2 | **响应头** `Flag2:` | 15 |
| flag3 | **`robots.txt`** 的注释 | 12 |

**5 + 15 + 12 = 32** 位十六进制 —— 正好凑满平台标准 flag 格式（**拼起来才知道齐不齐**）。

**侦察优先级**：
```
响应头  >  静态资源(robots.txt)  >  Cookie  >  页面正文/注释
```

**看响应头的姿势**：
```bash
curl -s -D - -o /dev/null "$URL" | grep -i '^Flag'
# 或 F12 → Network → 点请求 → Response Headers
# 或 Shift+Ctrl+U 无缓存刷新，避免看到缓存的响应头
```

## 1.8 ⭐ Cookie 越权（水平 / 垂直）

**识别信号**（三个同时出现就该动手）：

| 信号 | 说明 |
|---|---|
| ① `Set-Cookie` 下发的是**身份/状态**参数 | 不是 `PHPSESSID`、不是 csrf token，而是**裸的** `id=0` |
| ② 值是**裸数字** | `0` 常表示「默认 / 游客 / 第一个」→ `1` 大概率是「另一个对象」 |
| ③ 由**客户端持有** | 改它服务端收不收、认不认，一试便知 |

**试值顺序**（命中率从高到低）：
```
0  1  2  -1  01  1.0  1e0  true  false  admin  null  999
```
> 实测：`id=1` / `id=01` / `id=1.0` / `id=1e0` **都能出 flag**（PHP 弱类型 `if($id==1)`）；
> 但 `ID=1`（**改大小写**）和 `flag=1`（**改参数名**）都无效 —— 参数名和值都是大小写敏感的。

**三步固定套路**：
```
① 找身份参数：Cookie / URL 里的 id、uid、role、admin、level
② 删掉它看行为变不变 → 变了说明真的进了判断逻辑
③ 只改这一个值，遍历候选表，对比响应长度/状态码 → 346→362 字节就是铁证
```

**探测脚本**（用响应长度当信号）：
```python
VALUES = ["0","1","2","-1","01","1.0","1e0","true","false","admin","null","999"]
base = None
for v in VALUES:
    r = requests.get(url, cookies={"id": v})
    if base is None: base = len(r.text)
    print("id=%-6s -> %d bytes %s" % (v, len(r.text), "⭐" if len(r.text) != base else ""))
# id=0    -> 346
# id=1    -> 362 ⭐   ← 长度变了 = 有东西回显
```

**⚠️ 越权 ≠ 只改 Cookie**：URL 参数、POST 字段、请求头里出现 `id` / `user` / `role` 都是同一个考点。

# 二、代码审计

> **本质：找"用户可控输入（source）"是否流到了"危险函数（sink）"，且中间**没被过滤**。**

## 2.1 高危函数清单（**看到就要警觉**）

| 类别 | 函数 |
|---|---|
| **命令执行** | `system` `exec` `shell_exec` `passthru` `popen` `` `命令` `` |
| **代码执行** | `eval` `assert` `create_function`；`preg_replace` 带 `/e` |
| **文件包含** | `include` `require` `include_once` `require_once` |
| **读文件** | `file_get_contents` `fopen` `readfile` |
| **写文件** | `file_put_contents` `unlink` |
| **SQL** | `mysqli_query` `PDO::query`（字符串拼接） |
| **上传** | `move_uploaded_file` |
| **反序列化** | `unserialize` |

## 2.2 输入来源（source）

```
$_GET  $_POST  $_REQUEST  $_COOKIE  $_FILES  $_SERVER
文件上传、XML 解析、反序列化串
```

## 2.3 两个审计方向

| 方向 | 做法 | 速度 |
|---|---|---|
| **source → sink** | 拿 `$_GET['x']` 追踪它流向哪 | 慢 |
| **sink ← source** | ⭐ **搜 `system(` `include(` `eval(` 等** → 看参数是否可控 | **快** |

## 2.4 审计四步

```
① 搜危险函数：grep system/eval/include/query/unserialize/move_uploaded_file
② 看它的参数：是否拼了用户输入
③ 看有没有过滤：addslashes/黑名单/白名单/preg_match，能否绕过
④ 构造 payload 验证
```

## 2.5 快速示例

```php
$id = $_GET['id'];
$sql = "SELECT * FROM users WHERE id=$id";     // source → sink: SQL 注入
mysqli_query($conn, $sql);
```
```php
$file = $_GET['file'];
include($file);                                 // sink: LFI / php://filter
```
```php
$cmd = $_GET['cmd'];
system($cmd);                                   // sink: 命令注入
```

## 2.6 面试常问

```
"给你一段代码，漏洞在哪？"
→ 说出 source→sink 和漏洞类型
→ 常见：include($_GET)、system($_GET)、SQL 拼接、eval($_POST)、
        unserialize($_GET)、上传无校验、== 弱比较
```

## 2.7 ⭐ 分层题的「卡在第几关」诊断法

有些题把多个条件串成一条链（geekchallenge2024 六级链），**每关失败会回显当前最高的 `LevelN`** —— 这就是出题人送的调试器：

| 卡在 | 说明 |
|---|---|
| L1 | 第一个参数名/值不对 |
| L2 | 第二个参数不对 |
| L3 | 某个**请求头**缺失或值不对（注意 `https`、`www` 的大小写） |
| L4 | 另一个请求头不对（**IP 头要枚举，别只试 XFF**） |
| L5 | **最后一关**：头都带对了还卡这里 → 问题在**最后那个载体**（Cookie / token） |

**⭐ 最有价值的一条规律**：
> **「最后一个会报错的关卡」会把后面所有错误都吸过来。**

所以卡在 L5 时**别再去改头** —— 要怀疑最后一个载体：token 丢点（段数不对）、字段名拼错、目标值没改、过期。

**通用做法**：
```
① 先把"每关要什么"列成表（从题面 / 报错 / 回显源码里抠）
② 一次只改一个变量，看 LevelN 有没有前进 → 前进了就是这一关通了
③ 把"最高的 LevelN"当进度条用
```

# 三、一句话

> **信息收集：先翻源码（Ctrl+U 看注释）、再扫敏感文件（备份/.git/robots/swp），而且要看"整个报文"—— 响应头、robots.txt、Cookie 都可能是 flag 的一部分**。
> **Cookie 越权三信号：服务端主动下发身份参数 + 值是裸数字 + 客户端持有** → 遍历候选值看响应长度。
> **代码审计：找"用户输入"怎么流进"危险函数"** —— **先背危险函数清单，再看参数是否可控、能否绕过过滤**。
> **分层题用"卡在第几关"当进度条；卡在最后一关时，问题通常在最后一个载体上。**
