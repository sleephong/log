## 二、知识点

### 1. Misc / 密码 六题速览

| 题 | 考点 | 关键动作 |
|---|---|---|
| **哈基米与大狗嚼** | AES-CTR nonce 复用 | 已知 romio 明文 → `c1^c2^明文1 = 明文2` → `SYC{black_dog_and_white_cat}` |
| **好多骆驼** | emoji 编码 | 一眼是 base100，解码得一串 hex，再解一层 |
| **你看见bigx了吗** | 多图异或 | 六张都是 600×600 → Stegsolve 逐对异或，**图 1 异或图 6** 出图 |
| **真相只有喵知道** | 音频频谱二维码 | Audacity 看频谱、调高频段 → 看到二维码造型 → **点格子复原** |
| **ez_office** | docx 隐写 | 解压得前半 flag `SYC{w0rd_xmL_`；`image/` 里有 `SYC-blind.BMP`，按提示 blind → ImageJ 处理 |
| **消失的美味旅途** | OSINT | 图片文字线索 → 小红书/高德搜大盘鸡店 → 按「距离最近、新开」筛 |

**两道题的关键判断**：

**① 「你看见bigx了吗」为什么先试异或**

```
六张图，尺寸完全一致（600×600）
→ 尺寸一致通常意味着"可以叠加"
→ 异或是最常见的叠加方式（相同像素变黑，不同变亮）
```

**如果六张尺寸不一样，异或就没法做**，得先想别的。**尺寸一致本身就是一个提示。**

**② 「ez_office」的 blind 提示指什么**

docx 里藏的是 `SYC-blind.BMP`，文件名里的 **blind** 是提示：不是"看不见"，而是指**盲水印**（blind watermark）——在频域里嵌入的信息，肉眼看不出，要用特定算法提取。

**这题教会一件事：附件里的文件名也是提示**，不要只当垃圾看。

### 2. 静态资源后缀绕过：六类手法（面试高频）

这一节值得单独记，因为 Web 面试常问「为什么 `.jsp;.jpg` 能绕过」。

**根源**：**校验器看后缀的方式，和服务器解析后缀的方式不一致**。

| # | 手法 | 原理 | 典型环境 |
|---|---|---|---|
| **1** | **分号截断** | 服务器把 `file.jsp;.jpg` 里的 `;` 之后当路径参数丢掉，只看 `.jsp`；而校验器看到的是 `.jpg` | **Tomcat / Java 系最经典** |
| **2** | **路径附加** | 让后缀出现在"路径"而不是"文件名"里：`/upload/shell.jpg/x.jsp` | 路由匹配和文件系统不一致时 |
| **3** | **编码与特殊字符** | `%00`（旧版截断）、`%2e`（点）、`\x00` | PHP < 5.3.4 / Java 旧版 |
| **4** | **大小写与后缀变体** | `.JSP` `.jspx` `.jspf` | 校验用小写比较、解析器不区分大小写 |
| **5** | **双写与重复后缀** | `.jsp.jpg` `.jpg.jsp` —— 一个看第一个后缀、一个看最后一个 | 两边方向相反时 |
| **6** | **静态目录穿越** | 配合 nginx `alias`：`/static../` 穿越出静态目录 | nginx 配置 `alias` 且没校验路径 |

**怎么判断绕过成功**：

```
① 上传返回成功（不是 200 也可能是 302/400，要看具体逻辑）
② 访问时返回的是"执行结果"而不是源码
③ 对比：正常 jpg 访问返回 Content-Type: image/jpeg；绕过成功会变成 text/html
```

**第 ④ 条最可靠**：**看响应头里的 Content-Type**，不要只看页面内容。

### 3. XXE 的三类形态

| 类型 | 前提 | 怎么打 |
|---|---|---|
| **有回显** | 页面会打印解析结果 | 直接 `<!ENTITY xxe SYSTEM "file:///flag">` 然后 `&xxe;` |
| **盲 XXE** | 无回显 | 外带：把内容拼进请求发到自己的服务器，或写进 DTD 再引 |
| **报错型** | 无回显但会显示报错 | 用不存在的实体名把内容带进错误信息 |

**判断顺序**（现场可直接照做）：

```
① 先试有回显：能不能读到 /etc/passwd
② 读不到就试报错：看返回里有没有解析错误
③ 都没有就盲打：外带
```

**PHP 环境的特殊点**：默认不解析外部实体（`libxml_disable_entity_loader`），但很多老版本和特殊函数（`simplexml_load_string` 等）还可以。**PHP 8 之后默认关闭，打之前先确认版本。**

### 4. 二维码在 CTF 里的八种玩法

从整理的文档里抽出来的分类：

```
① 直接扫              最基础
② 挖掉定位图案        要按版本重建
③ 反色 / 镜像         翻转后重扫
④ 分片拼接            多块拼成一张
⑤ 频域藏码            音频/图片频谱里出现二维码
⑥ 数据区藏码          二维码的某些模块被替换成数据
⑦ 手工重建            尺寸太小/噪点多，人眼读格、程序生成
⑧ 纠错码挖空          利用 RS 纠错规则恢复部分缺失
```

**⑦ 是我这几天实际用的**：频谱切出来的二维码扫不出，只能数格子（29×29 = Version 3）手工敲成矩阵，再重新生成。

## 三、案例 / 命令

### 1. 多图异或

```python
from PIL import Image, ImageChops
a = Image.open("1.jpg").convert("RGB")
b = Image.open("6.jpg").convert("RGB")
ImageChops.xor(a, b).save("xor_1_6.png")
```

**前提：两张图尺寸必须一致。**

### 2. emoji 编码

```python
# base100：emoji 每个字符代表一个字节
# 解出来通常是 hex，再 fromhex 转二进制
bytes.fromhex(decoded_hex)
```

### 3. docx 里找隐藏文件

```powershell
Expand-Archive -LiteralPath "chall.docx" -DestinationPath ".\docx_x"
Get-ChildItem ".\docx_x\word\media"     # 图片都在这
Get-ChildItem ".\docx_x" -Recurse | Where-Object { $_.Name -match 'SYC|flag|blind' }
```

**文件名本身就是线索**：`SYC-blind.BMP` 直接把考点写在名字里。

### 4. 后缀绕过的验证

```powershell
# 上传后看响应头，不要只看内容
curl.exe -i "http://目标/uploads/shell.jsp;.jpg"
# 判断：Content-Type 是 text/html 还是 image/jpeg
```

## 四、踩坑

| 坑 | 现象 | 原因 / 解决 |
|---|---|---|
| 只看页面内容判断绕过 | 以为是源码泄露 | 要看响应头 `Content-Type` |
| 六张图没先看尺寸 | 不知道怎么组合 | 尺寸一致是异或的前提，先确认 |
| 把 `blind` 当"看不见" | 猜错方向 | blind 指**盲水印**，要频域提取 |
| 二维码扫不出就放弃 | 卡住 | 手工数格子重建，29×29 = Version 3 |
| 面试只讲"它修好了" | 被追问卡住 | 主动讲修复的局限 |
