## 二、知识点

### 1. CVE-2025-68664：根因是「序列化格式自描述」

LangChain 的 `dumps/loads` 不是普通 JSON，它带**自描述标记**：

```json
{"lc": 1, "type": "constructor", "id": ["langchain_core", "messages", "HumanMessage"], "kwargs": {...}}
```

三个关键字段：

| 字段 | 含义 |
|---|---|
| `lc: 1` | 「我是 LangChain 对象」，不是普通字典 |
| `type` | `constructor`（实例化对象）或 `secret`（读环境变量） |
| `id` | 类路径 / 密钥名 |

**问题就在这里**：反序列化时，`loads()` 用 `json.loads(text, object_hook=Reviver(...))`，`Reviver` 看到 `value["lc"] == 1` 就**照 `type` 去执行动作**。

而 `dumps()` 是 `json.dumps(obj, default=default)`——**只要字典里有 `lc: 1`，它和真对象长得一模一样**，`loads` 分不出来。

**核心一句**：**格式里带着"该怎么解释我"的指令，而这个指令来自不可信输入。**

### 2. 两个攻击分支

**分支一：`secret`（读环境变量）**

```json
{"lc": 1, "type": "secret", "id": ["OPENAI_API_KEY"]}
```

→ 反序列化时把环境变量的值读出来，塞进对象里。攻击者只要能让这段 JSON 进 `loads()`，就能把 API Key、数据库密码带出来。

**分支二：`constructor`（实例化任意类）**

```json
{"lc": 1, "type": "constructor", "id": ["...", "类名"], "kwargs": {...}}
```

→ 走白名单实例化。白名单没管全的时候，就能实例化到危险类（比如能触发模板渲染、文件写入的类）。

### 3. 修复（1.2.5）：两处改动

| 改动 | 做法 |
|---|---|
| **新增转义机制**（核心） | 用户数据里如果出现 `lc` 这类字面量，序列化时**转义掉**，让它不再被当成指令 |
| **白名单升级** | 从「命名空间级」收紧到「完整类路径级」——`langchain_core` 整个放行 → 只放行具体那几个类 |

**思路值得记**：问题的本质是「数据和指令混在同一个通道」，修复就是**加一个转义层把两者分开**。这和 SQL 注入里「参数化」是同一个道理。

### 4. 怎么在同一环境里对比两个版本

不要装两次包。用 `PYTHONPATH` 指向不同目录：


### 5. 三种 SSRF payload 的字节骨架

今天把三套协议拆到字节级，对照如下：

| 协议 | 总字节 | 结构 |
|---|---|---|
| **FastCGI** | 362 | 4 条记录（BEGIN_REQUEST 8B + PARAMS 260B + 空 PARAMS + STDIN 54B） |
| **Redis** | 174 | 5 条 RESP 命令，**缺少 QUIT**（残缺骨架） |
| **MySQL** | 193 | 3 个包（登录包 163B + COM_QUERY + **COM_QUIT**） |

**三条协议共同点**：都有「包头 + 长度 + 载荷」的结构，长度字段错了整个包就废。

**Redis 那套是残缺的**——没有 `QUIT` 就会挂住连接。这个细节在 11-09 踩过坑（靶场被打死），今天专门写进了骨架拆解。

### 6. 四个验证实验的结论

| 实验 | 验证什么 | 结论 |
|---|---|---|
| **一** php-fpm 进程池超时 | worker 被占满后多久恢复 | 挂住的请求会占住 worker，期间新请求排队；恢复要等超时 |
| **二** 十六进制抓包头 | 抓到的字节怎么读 | 按「包头 + 长度 + 内容」切，长度字段是字节数不是字符数 |
| **三** L6 UDF 提权 | 为什么能提权 | 插件目录 `chmod 777` → 可写 .so → `CREATE FUNCTION` 加载 |
| **四** 原生 gopher 的 QUIT | 不加 QUIT 会怎样 | 连接挂住不释放，单线程服务器被打死 |

**实验四是今天最有用的**：它解释了「为什么明明打通了，后面所有请求都超时」。

### 1. 拆一条 RESP 命令的字节

```
SET x hello
→ *3\r\n$3\r\nSET\r\n$1\r\nx\r\n$5\r\nhello\r\n
```

逐段读：

```
*3        参数个数 3
$3 SET    第 1 个参数，长度 3
$1 x      第 2 个参数，长度 1
$5 hello  第 3 个参数，长度 5
```

**每个 `\r\n` 在 gopher URL 里写成 `%0d%0a`。**
