# 第三部分 · 极客大挑战2024 · ez_http

## 一、今日做了什么

### 🚩 通关 geekchallenge2024（SYC）六级链

> 当时的 flag 是 `SYC{b06d1f4d-2a07-4226-868f-43afbe6f3a5e}`（**该实例的**）。
> ctfplus 的 flag **每个实例随机生成**，换实例必变 —— 所以记 flag 没意义，方法才是重点。

**六关要求**（串行 AND 关系，必须一次全带）：

| 关卡 | 要求 | 位置 |
|---|---|---|
| L1 | `welcome=geekchallenge2024` | GET 参数 |
| L2 | `username=Starven` & `password=qwert123456` | POST body |
| L3 | `Referer: https://www.sycsec.com` | 请求头 |
| L4 | **`X-Real-IP: 127.0.0.1`** | 请求头 |
| L5 | **`Starven: I_Want_Flag`** | 请求头 |
| L6 | **JWT：改 `hasFlag` 为 true 并重签** | Cookie |

**过程要点**：

- L2 凭据是**报错直接给**的（`nonono, username=Starven , password=qwert123456`）
- L3 通过后响应里**打印出 L5 的 PHP 源码** → 直接读出要发的头
- L4 的关键是 `X-Real-IP` 而非 `X-Forwarded-For`（**枚举试出来的**）
- L6 是全题核心：JWT 伪造 —— 改 `hasFlag` 要在**字节层面**改，然后**重签**（长度不用管）

**顺带**：摸清 PHP `$_SERVER` 头的映射规则（`HTTP_` 前缀 + 大写 + `-`→`_`）；建立 JWT 处理工具集（base64url 编解码 / HS256 签名 / 验签 / 结构体检）；并做了一次判定实验确认服务端**只解码不验签** —— 但**正式解法仍走 HS256 重新签名**。

> 完整分析已归档 → [writeups/极客大挑战SYC/2024-ez_http.md](../writeups/极客大挑战SYC/2024-ez_http.md)
