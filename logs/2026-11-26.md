## 二、知识点

### 1. 「内网」和「局域网」不是按范围分的

以前把这两个词当同义词用，今天理清：

| 词 | 按什么分 | 判据 |
|---|---|---|
| 局域网 / 城域网 / 广域网 | **覆盖范围** | 一栋楼 / 一座城 / 跨国 |
| 内网 / 外网 | **路由与访问控制边界** | 能不能被公网直接路由到 |

```
家里的 WiFi 是局域网，也确实构成内网
机房里的网可能有公网地址、没做隔离 → 是局域网，但不是内网
```

**同一个词不能同时按两个维度分**，这是最容易讲混的一处。

顺带把特殊网段记牢了：`10/8`、`172.16/12`（只有 16–31）、`192.168/16` 是私有；`127/8` 整段都是回环，不只是 `127.0.0.1`；`169.254/16` 是拿不到 DHCP 时自分配的 link-local，云元数据就在 `169.254.169.254`；`100.64/10` 是运营商级 NAT。

### 2. 代理 / 加速器 / 梯子 / VPN：四条判据

这四个词日常混着叫，其实只要问四个问题就能分开：

| 问 | 是 | 否 |
|---|---|---|
| 系统里多了一张虚拟网卡、路由表多一条吗 | **VPN** | 代理（含梯子、加速器） |
| 是客户端自己填的地址吗 | **正向代理** | 反向代理（客户端不知道有代理） |
| 只代理某一个应用的流量吗 | **加速器、梯子** | VPN（整机） |
| 目标是「能出去」还是「进了哪个网」 | **梯子**：能出去 | **VPN**：进了哪个网 |

**一句话**：梯子让流量从隧道出去，机器没进任何新网络；VPN 把机器接进另一张网，接进去之后能访问 `10.x` 的内网打印机。

**加速器的内核就是 UDP 代理**：只接管游戏的 UDP 包，卖的是线路质量和低延迟，不承诺加密。

### 3. 请求头到 `$_SERVER` 的三步变换

| 步骤 | 变换 | 例 |
|---|---|---|
| ① 头名转大写 | — | `Starven` → `STARVEN` |
| ② `-` 换成 `_` | — | `X-Real-IP` → `X_REAL_IP` |
| ③ 前面加 `HTTP_` | — | → `HTTP_X_REAL_IP` |

**只有两个例外**：`Content-Type` → `$_SERVER['CONTENT_TYPE']`、`Content-Length` → `$_SERVER['CONTENT_LENGTH']`，都没有 `HTTP_` 前缀。

有了这个映射，**看源码读哪个键就能反推该发什么头**——这比一个个试头快得多。

### 4. 大小写：头名不敏感，参数名和值敏感

| 层 | 敏感? | 实测 |
|---|---|---|
| HTTP 头名 | **不敏感** | `Starven` / `starven` / `sTaRvEn` 全 PASS |
| 媒体类型值 | 不敏感 | `APPLICATION/X-WWW-FORM-URLENCODED` 也认 |
| 头**值** | **敏感** | `I_Want_Flag` 精确，大小写变体全挂 |
| Cookie 名 | 敏感 | `token` PASS，`Token` 挂 |
| GET/POST 参数名 | 敏感 | `welcome` PASS，`Welcome` 卡第一关 |
| JSON / JWT 字段名 | 敏感 | `hasFlag` PASS，`hasflag` 挂 |

**根因**：头名不敏感是协议规定（服务器先规范化再映射），参数名敏感是因为数组键本身区分大小写。

### 5. 冒号前面多一个空格，Apache 也收

| 位置 | 规范 | 实测 |
|---|---|---|
| 冒号**后**空格 | 可有可无（OWS） | 0/1/3 个都行 |
| 冒号**前**空格 | 规范禁止，应回 400 | Apache 2.4.10 接受 → **CVE-2016-8743**，2.2.0–2.4.23 受影响，2.4.25 才修 |

**这是 WAF 绕过的土壤**：WAF 按规范解析、后端按宽容实现解析，两边看到的是不同的头。

### 6. 状态码只要记三组判据

| 别混 | 判据 |
|---|---|
| 401 vs 403 | 401 = 没登录/凭据不对；403 = 登录了但没权限 |
| 400 vs 500 | 400 = 请求本身不合规范（你发错的）；500 = 服务端自己炸的 |
| 502 vs 504 | 502 = 上游返回了非法内容；504 = 上游超时没回 |

**做 SSRF / LFI 特别有用**：看到 502/504 说明请求已经打到上游那一层了，比 404 有信息量得多。

### 7. IP 头要枚举，不能只试 XFF

```
X-Forwarded-For   X-Real-IP   Client-IP   X-Client-IP   Remote-Addr
X-Remote-Addr     X-Remote-IP X-Originating-IP   True-Client-IP
Forwarded: for=127.0.0.1
```

值也要枚举：`127.0.0.1` / `localhost` / `::1` / `0.0.0.0` / `192.168.*` / `10.*`。

**实测对照**（同一目标）：

| 尝试 | 结果 |
|---|---|
| `X-Forwarded-For: 127.0.0.1` | `nonono,you're not from local ip` |
| `X-Real-IP: 127.0.0.1` | 过关 |

**全部无效**说明代码校验的是 TCP 层 `REMOTE_ADDR`（内核填的，改不了），只能走 SSRF。

**为什么出题人喜欢 `X-Real-IP`**：单值，`$_SERVER['HTTP_X_REAL_IP'] == '127.0.0.1'` 一行就够；XFF 是列表，还得 `explode` 取第几段。

### 8. Burp Intruder 的顺序坑：先加前缀，再 base64

Basic Auth 爆破时，`Authorization: Basic base64(user:pass)` 的构造顺序不能反：

```
字典值 123456
  → Rule 1: Add prefix "admin:"   →  admin:123456
  → Rule 2: Base64-encode         →  YWRtaW46MTIzNDU2
```

**反了会怎样**：

```
123456 → Base64 → MTIzNDU2 → 加前缀 → admin:MTIzNDU2
Authorization: Basic admin:MTIzNDU2   ← 不是合法 base64，全 401
```

**还有第二个坑**：Payload options 里默认开着 URL-encoding，`=` 被编成 `%3D` 之后服务端解不出 base64。本机实测 100 条字典里 **44 条会被编码破坏**，所以「全 401」九成是这两个坑之一。

排错口诀：

```
① 值以 YWRtaW46 开头吗？  不是 → 前缀错/顺序反
② 值里有 %3D / %2B / %2F 吗？ 有 → URL 编码没关
③ 值结尾有 = 吗？          有 → 回查 ②
④ 都不对 → 用 Repeater 手动发一条已知凭据，先验证服务端
```

### 9. HTTP 头题六级链：一次带齐

这类题服务器是**逐层判断、遇错即停**，所以要么一次全带，要么靠「卡在第几关」反推。

| 卡在 | 缺什么 |
|---|---|
| L1 | `welcome` 参数名或值 |
| L2 | `username` / `password` |
| L3 | `Referer`（要 `https`、全小写） |
| L4 | `X-Real-IP` |
| **L5** | `Starven` 头，**或者 Cookie 里的 token** |

**L5 这条最值钱**：它是最后一个会报错的关卡，所以 token 出错也表现成卡 L5——头都带齐了还卡 L5，直接去查 token（丢段、字段名、`hasFlag` 没改、过期）。

### 10. sqli-labs 绑 PHP 5，upload-labs 看 Apache 配置

| 靶场 | 关键 |
|---|---|
| **sqli-labs** | 用 `mysql_*` 函数族，**PHP 7 起已移除**，必须切 PHP 5.x，否则 `Call to undefined function mysql_connect()` |
| **upload-labs** | 不需要数据库，但要配 `extension=exif`（Pass-16 用 `exif_imagetype()`，没开是 **Fatal** 不是判空）、`short_open_tag`、上传大小 |

**「哪个后缀会被执行」由 Apache 的 `AddType` 决定，不是 PHP 决定的**。本机实测：

| 后缀 | 结果 |
|---|---|
| `.php` | 执行 |
| `.php5` `.phtml` `.pht` `.phar` | 全部返回源码 |

所以「换后缀绕过」能不能成，**每台机器结论不同，必须实测不能背**。

**上传 ≠ 执行**：`.gif` 直连是静态文件，要走包含入口 `include.php?file=upload/x.gif`。01–13 关落盘保留后缀，14–17 关落盘被写死成图片后缀——这就是两组关卡的分界。

### 2. Burp Intruder 的配置顺序

```
Positions: Clear → 手动框选整段 base64 → Add（只有这一处标记）
Payloads:  Simple list → load pass.txt
Rules:     Add prefix "admin:"  →  Base64-encode
Options:   关掉 URL-encoding
```

### 3. 抓不到包的四步排查

```
① 浏览器代理端口对不对（Burp 默认 8080）
② Burp 里 Proxy → Options 的拦截域名有没有把目标排掉
③ HTTPS 要装 CA 证书（http://burp 下载后导入「受信任的根」）
④ 有的站点走 QUIC/HTTP3，得在浏览器里关掉
```

### 4. 靶场自检的两步

```
① 先访问首页，看关卡列表在不在
② 拿最简单的一关（upload Pass-01 / sqli Less-1）用已知手法打一遍
   通了 → 环境没问题，问题在手法
   不通 → 环境/版本问题，先修环境
```

**在没确认环境之前先怀疑自己，是最浪费的一种排查。**

## 四、踩坑

| 坑 | 现象 | 原因 / 解决 |
|---|---|---|
| 「内网」当「局域网」讲 | 讲不清为什么机房不算内网 | 一个按范围、一个按路由边界 |
| `172.16.0.0/12` 写成整个 172 | 掩码算错 | 只有 172.16–172.31 |
| 以为改 XFF 就能过 | 一直 `nonono` | 代码读的是 `HTTP_X_REAL_IP`；头要枚举 |
| 头名大小写乱试 | 白试 | 头名不敏感，**值**才敏感 |
| `Content-Type` 也加 `HTTP_` 前缀 | 取不到值 | 它和 `Content-Length` 是唯二例外 |
| Intruder 顺序反了 | 全 401 | 先 Add prefix 再 Base64 |
| 没关 URL-encoding | 全 401 | `=` → `%3D`，base64 解不出 |
| sqli-labs 用 PHP 8 起 | `mysql_connect()` 未定义 | 切 PHP 5.x |
| 以为 `short_open_tag` 无所谓 | 某些关卡一句输出都没有 | 真图里随机撞出 `<?` → Parse error |
| 以为 `.phtml` 会被执行 | 返回源码 | 只有 Apache 配了 `AddType` 才会；实测为准 |
| 上传成功就以为 getshell | 访问 `.gif` 是静态文件 | 要走 include 入口 |
