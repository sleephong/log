## 二、知识点

### 1. phar 的结构与反序列化

一个 165 字节的 phar 拆开看：

```
0000  <?php __HALT_COMPILER(); ?>     stub（入口）
001c  manifest 长度
0020  文件数 / API 版本 / 全局标志 / alias
002c  ★ metadata 长度 + metadata（明文序列化串）
0056  文件条目（名字、大小、时间戳、校验和）
0080  文件内容
00a0  签名（GBMB）
```

`metadata` 是**明文序列化字符串**，phar 被打开时会反序列化它。

### 2. 版本差异（实测）

同一份 phar，只做 `file_exists` / `file_get_contents`：

| PHP | 文件操作是否触发 `__wakeup` | 显式 `getMetadata()` |
|---|---|---|
| 5.3.29 | 触发 | 触发 |
| 5.4.45 | 触发 | 触发 |
| 7.4.3 | 触发 | 触发 |
| 8.2.9 | **不触发** | 触发 |

**结论**：PHP 8 取消了自动反序列化，只有代码显式调 `getMetadata()` 才有洞。

### 3. phar 改名仍可用

把 `p.phar` 复制成 `p.jpg`，在 5.3 / 5.4 / 7.4 下 `phar://…/p.jpg/x.txt` 依然能读、依然触发。

因为 **phar 的识别靠内容不靠后缀**；`new Phar()` 创建时才要求 `.phar` 后缀。

### 4. 文件上传的错误归成五类

| 类型 | 代表 | 说明 |
|---|---|---|
| 术语拼写 | `AddType` 写成 AppType / AbbType；`auto_prepend_file` 写成 auto_append_file | 会但写错，直接导致失效 |
| 概念串味 | 把 `allow_url_include` 当成上传的条件 | 把别的模块的开关搬过来了 |
| 判据缺失 | 五层校验、四条件、二次渲染三处 | 能说个大概，落笔只剩一两条 |
| 场景推理空白 | 给源码不会绕、给现象不会排查 | `strtolower` 缺失、403/404 排查 |
| 答偏 | 问"为什么不能执行"，答成"会被拦截" | 没复述问题就开始答 |

### 5. 文件包含的核心判据

| 项 | 结论 |
|---|---|
| `include` vs `file_get_contents` | 前者**执行**，后者只读 |
| 失败行为 | `include` Warning 继续；`require` Fatal 停止 |
| `_once` | 防重复包含，不影响失败行为 |
| `php://filter` | **不受 `allow_url_include` 限制**（本地流封装，不走 URL） |
| 读源码为什么 base64 | 直接 include 会被当 PHP 解析执行，看不到源码 |
| 后缀检查怎么绕 | `substr($f,-4)==='.php'` 挡不住 `php://filter/.../resource=index.php`——它本来就以 `.php` 结尾 |
| 过滤 `php://` | wrapper 名不区分大小写，用 `PHP://filter` |
| 过滤 `..` | `....//` 无效（自身含 `..`），改用绝对路径 |

### 6. 两种"点"的过滤不是一回事

```php
str_replace('../', '', $f)   // 删"点+点+斜杠" → 用 ....// 绕
str_replace('..', '', $f)    // 删所有"点+点" → ....// 也会被删，只能用绝对路径
```

## 四、踩坑

| 坑 | 现象 | 原因 / 解决 |
|---|---|---|
| `AddType` 拼错 | 配置整条失效 | 写成 AppType、AbbType 各一次；写错一个字母全废 |
| `auto_append_file` | 包含不生效 | append 是脚本结束后包含，遇 `exit` 就不执行；要用 `prepend` |
| 把 `..` 过滤和 `../` 过滤混为一谈 | `....//` 绕不过 | 前者只能靠绝对路径 |
| phar 在 PHP 8 上不触发 | 以为是构造错了 | 8.x 取消自动反序列化，得看目标版本 |
| 利用链整块空白 | 13 题里后 3 题没答 | 这块最容易出综合题，不能只背单点 |
