## 二、知识点

### 1. 音频 LSB：16 bit 的最低位就是一条字节流

```python
# 每个采样点取最低位，攒 8 位成一个字节
bits = [samples[i] & 1 for i in range(len(samples))]
data = bytes(int(''.join(map(str, bits[i:i+8])), 2) for i in range(0, len(bits), 8))
```

**判据**：音频能正常听、没有明显杂音，但 `strings` 或 LSB 提取能看到 `SYC{`。

**为什么要"MSB/LSB 都试"**：位序（先高位还是先低位）不同，拼出来的字节完全不同。`lsb_msb.bin` 这个名字就是记这个。

### 2. 频谱图里可以藏二维码

把二维码画进频谱（高频段），导出的频谱图就是一张二维码。**所以"看频谱"不只为了找文字，也可能直接得到一张码**。

判断：频谱里有明显的方块状结构（不是文字笔画）。

### 3. 二维码必须留 quiet zone（四周白边）

规范要求**码的四周至少留 4 个模块宽的白边**。截图/频谱图里的码经常紧贴边界，解码器就直接失败。

```python
img = cv2.copyMakeBorder(img, 40, 40, 40, 40, cv2.BORDER_CONSTANT, value=255)
```

这一条单独就能救回不少题。

### 4. 暴力修复的六个维度

`qr_fix.py` 枚举的是组合，不是单点：

```
二值化：灰度 / Otsu / 自适应 / 固定阈值 ×3
反色：  正 / 反
缩放：  1~8 倍（最近邻）
旋转：  0 / 90 / 180 / 270
镜像：  水平
边距：  补白边 / 不补
```

本题命中的是 **`threshold 35 + invert 1`**——即"固定低阈值 + 反色"。这类题**必须枚举**，靠猜没用。

### 5. 缩放要用最近邻

二维码是**二值方块图**，用 LANCZOS 之类的插值会在格子边界产生灰阶过渡，二值化后边界漂移，采样就错位。

```python
cv2.resize(img, None, fx=4, fy=4, interpolation=cv2.INTER_NEAREST)
```

### 6. zbar / ZXing 解不出的原因：它们依赖标准定位图案

标准解码器的流程是：找三个定位角（finder pattern）→ 算透视变换 → 按网格采样 → 纠错。

一旦出现下面任一情况就失败：

| 情况 | 后果 |
|---|---|
| 透视变形（斜拍/截图缩放） | 定位角位置算错，网格全歪 |
| 模糊 | 定位角检测不到 |
| 缺 quiet zone | 边界判定失败 |
| 只有部分码 | 直接放弃 |

**所以"解不出"不等于"码坏了"**，可能是解码器的前置条件不满足。

### 7. 自己重建网格：用定位角 + 时序图案拟合

`qr_auto_decode.py` 的思路：

```
① 估计深色区域范围
② 用三个定位角 + 时序图案（timing pattern，黑白交替那条）
   拟合出网格参数：x0, y0, sx, sy（起点 + 每格宽高）
③ 按网格采样出 29×29 矩阵（版本 3）
④ 二值化阈值单独估计
⑤ 按版本 + EC 等级的块表做 Reed-Solomon 纠错
```

本题拟合结果是 **定位角+时序匹配 = 100%**，说明网格估得非常准；后面的错误全靠 RS 纠错吃掉：

```
🎉 EC=L mask=3 纠错 6 个码字
   SYC{mia0Miaom1ao_mi4O_mIaoMiao_mi4om1a0}
```

### 8. 版本与纠错块表是硬编码的

版本 3 的码是 **29×29** 个模块。不同 EC 等级的数据块划分不同：

```python
EC_TABLE = {
    "L": (15, [(1, 55)]),      # 15 个纠错码字，1 块 55 数据码字
    "M": (26, [(1, 44)]),
    ...
}
```

**不知道 EC 等级怎么办**：枚举。L/M/Q/H 各试一遍，能过 RS 校验的那个就是对的。

### 9. "只标不确定的格子"是个好设计

`qr_assist.py` 不让人工从头画，而是：

```
程序采样出 29×29
→ 算出每格的"确定度"（灰阶离阈值多远）
→ 只把最不确定的 N 格标黄框/红框
→ 人只看这几个格子
```

**这是"人机分工"**：机器做确定性工作，人只处理模糊的那几格。本题最后就是靠人工修正 `cell92`、`uncertain` 那几个格子才过的。

## 四、踩坑

| 问题 | 原因 | 解决 |
|---|---|---|
| zbar / ZXing 全部返回空 | 透视变形 + 模糊 + 贴边无 quiet zone | 先补白边，再枚举阈值和反色 |
| 放大后反而更解不出 | 用了 LANCZOS 插值，格子边界糊了 | 改 `INTER_NEAREST` |
| 网格估偏 1~2 像素，采样错一片 | 手工量 `x0/y0/sx/sy` 不准 | 用定位角 + 时序图案自动拟合（本题匹配率 100%） |
| 纠错救不回来 | 采样错太多，超出 RS 能力 | 用 `qr_assist.py` 只修"最不确定"的几格，再重解 |
| 试了很多组合不知道哪步有效 | 六个维度一起枚举，日志不记 | 每个命中都打印 `threshold / invert / scale`，命中后能复现 |
| 版本猜错 | 29×29 是版本 3，别的版本尺寸不同 | 按像素密度反推版本，或直接从定位角间距算 |
