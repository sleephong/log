## 二、知识点

### 1. 间接提示注入：知识库内容被当成指令

实验设置：本机 qwen3.5:4b，一个「先检索知识库再回答」的助手。

| 组 | 输入 | 结果 |
|---|---|---|
| 对照 | 正常问题 | 正常回答 |
| 注入 | 知识库返回的文本里夹了一句指令 | **模型把这句话当成指令执行了** |

**根因**：系统指令、用户问题、检索到的资料，**全都拼在同一个上下文里**。模型分不清哪句是"要遵守的规则"、哪句是"要看的内容"。

**这和 SQL 注入、命令注入是同一个病**：

```
SQL    → 数据和语句混在一条字符串里
Shell  → 数据和命令混在一行里
Prompt → 资料和指令混在一个上下文里
```

**防御思路也一样**：加边界标记（相当于引号/参数化），或者让资料只走"只读通道"。

### 2. 工具越权（Excessive Agency）

第三组实验：用户只问「年假还剩几天」，模型却**主动调用了与任务无关的 `read_file`**，还把读到的敏感内容写进了回答。

**这类问题的名字叫「过度代理」**：

| 问题 | 表现 |
|---|---|
| 工具过多 | 模型手里有读文件、发请求、执行命令的能力 |
| 缺少用途限定 | 没有告诉它「只准用查年假的那个工具」 |
| 缺少人工确认 | 危险操作直接执行，没人拦 |

**三条修法**：
1. **最小工具集**：按场景只挂当前需要的工具
2. **副作用确认**：读文件、发请求、写数据这类动作要人点确认
3. **输出隔离**：工具返回的内容不回灌进上下文（否则又变成第 1 条的注入源）

### 3. XXE 排查的正确顺序（从「打码」那题学到的）

这题的排查过程很典型，值得记下来：

```
① 看到「模板预览」→ 先猜 XXE
② 写不完整的 XML 试探 → 还是 OK（说明没有严格解析）
③ 写完整 XML → 还是 OK（说明可能不是 XXE，或者回显不在这里）
④ 看响应头确认 server 是 nginx → 排除了 Apache 特有的一些思路
⑤ 试 www.zip / .git/HEAD → 都是 OK（说明有路由兜底，不是静态目录）
⑥ 抓包 → 发现真实接口是 POST /preview，参数名 tpl
```

**关键在第 ⑥ 步**：前面五步都在猜，**抓包一看就知道参数名和请求方法**。

**教训**：页面上的表单不一定是真实接口。JS 发起的请求经常和看到的表单不一样，**先抓包再猜**。

## 四、踩坑

| 坑 | 现象 | 原因 / 解决 |
|---|---|---|
| 按页面表单猜参数 | 一直 OK，没有反应 | 真实接口是 JS 发的 `POST /preview`，参数 `tpl`；**先抓包** |
