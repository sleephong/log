## 二、知识点

### 1. AES-CTR 的 nonce 复用（今天最核心的一条）

题目代码只有 9 行：

```python
key   = os.urandom(16)
nonce = b"dormitory"                      # 固定不变
c1 = AES.new(key, AES.MODE_CTR, nonce=nonce).encrypt(romio)
c2 = AES.new(key, AES.MODE_CTR, nonce=nonce).encrypt(juliet)
```

**问题就在这里**：nonce 固定、key 相同 → 两次加密用的是**同一条密钥流**。

CTR 模式的加密本质是：

```
密文 = 明文 XOR 密钥流
```

两段密文一异或，密钥流就消掉了：

```
C1 XOR C2 = (P1 XOR KS) XOR (P2 XOR KS) = P1 XOR P2
```

**结论：拿到 C1 XOR C2，就等于拿到两段明文的异或。** 这叫 many-time pad 攻击。

**为什么 nonce 必须唯一**：CTR 把分组密码变成流密码，安全性完全依赖「同一条密钥流只用一次」。nonce 复用等于把一次性密码本用了两次。

### 2. many-time pad 攻击的前置检查

拿到 `C1 XOR C2` 之后能不能破，先要判断**明文类型**。

**如果是可打印 ASCII**，可以用「空格异或法」：

```
字母 XOR 空格(0x20) = 该字母的大小写翻转
例：'a' ^ 0x20 = 'A'（0x61 ^ 0x20 = 0x41）
```

对每个位置，如果 `(C1 XOR C2)[i] ^ 0x20` 落在字母范围内，说明这个位置**可能有一个空格**。两段明文中空格最频繁，所以能猜出大量位置。

**判定方法（我今天用的）**：

```python
# 对每个位置，找所有能让两段密文都变成可打印 ASCII 的密钥流字节 K
cand = [k for k in range(256)
        if 0x20 <= (c1[i] ^ k) <= 0x7e and 0x20 <= (c2[i] ^ k) <= 0x7e]
```

**如果每个位置都有候选，说明两段明文可能都是 ASCII，可以继续破。**
**如果某些位置一个候选都没有，说明明文不是纯 ASCII**（可能是中文 UTF-8 或二进制）。

### 3. 这道题的实测结果（还没解出来，但结构摸清了）

```
c1 = 117 字节
c2 = 89 字节
共同前缀 = 89 字节
```

**前 24 字节的异或值**：

```
0c 3b 0b 03 05 2a 03 38 0c 0f 01 00 0a 2c 02 09 26 1b 0d 0f 36 03 04 1f
```

**全部是小于 0x40 的小值** → 说明两段明文**前 24 字节非常相似**（只差低几位）。

**第 24 字节之后**：

```
c6 c5 e0 a4 e1 e6 89 f7 d4 8d ec ed 87 d9 e6 8e d2 e8 b9 ff f9 8f e8 ec
```

**高位全部被置起** → 至少有一段明文**不再是 ASCII**。

**ASCII 可行性检查**：89 个位置里只有 60 个能同时满足「两段都是可打印 ASCII」，24 字节之后的 29 个位置**无解**。

**推断**：这两段明文很可能是「**ASCII 前缀 + 中文（UTF-8）或二进制**」。`romio` / `juliet` 这两个名字暗示是罗密欧与朱丽叶相关的文本，可能是中英混排。

**下一步方向**：
