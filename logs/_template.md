# YYYY-MM-DD

> 复制本文件 → 改名成当天日期（如 `2026-09-29.md`）

## ⚠️ 日期归属规则（**先看这条再动笔**）

| 情况 | 记在哪天 |
|---|---|
| 事情发生在当天 00:00~23:59 之间 | **当天**，文件名就是当天日期 |
| **一件事跨了零点**（如 22:59 开始、次日 01:47 结束） | **记在它【开始】的那一天**，整件事写在一起，**不要拆成两半** |
| 第二天**重新开始**做的东西 | 记在**第二天** —— 不许回填到前一天 |

**唯一判据：这件事是从哪天开始动手的。**
例：10-02 晚上 22:59 开始做「字符白名单命令执行」，做到 10-03 凌晨 01:47 →
**整段记在 `2026-10-02.md`**，开头注明「本日跨到凌晨（22:59 → 次日 01:47），全部记在 10-02」。

**写文件名之前，先跑一次 `Get-Date -Format 'yyyy-MM-dd'`**，不要凭记忆、不要顺着上一篇往下写。

> 如果一篇日志里有跨零点的内容，**在开头用一句 `>` 引文写清楚**（起止时间 + 归属说明），
> 这样以后回看不会疑惑「这条为什么不在第二天」。

## ⚠️ 三层结构：内容该放哪（**动笔前先定层**）

| 内容 | 放哪 | 组织方式 |
|---|---|---|
| **当天干了什么**（流水 + 结论一句话） | 本篇 `logs/YYYY-MM-DD.md` | 按**日期** |
| **新学到的知识点**（跨题复用） | `notes/` | 按**知识点** |
| **某道题的完整分析**（payload / 踩坑 / 复盘） | `writeups/<赛事>/` | 按**赛事**，一题一篇 |

```
writeups/
├── README.md          ← 赛事总索引
├── 极客大挑战SYC/      ← 一个赛事一个文件夹
│   ├── README.md      ←   赛事总览（题目清单 / 考点分布 / 复盘）
│   └── 2024-ez_http.md ←  一题一篇
├── PolarCTF/  0xGame/  NSSCTF/
└── 靶场/               ← 非赛事（公开练习平台）单独一类
```

### ⭐ 两条硬规矩

1. **题目细节不要写进日志。** 日志里只留「当天做了什么 + 链接」，
   例如：`> 完整分析已归档 → [writeups/0xGame/](../writeups/0xGame/README.md)`
2. **一道题只存在于一个地方。** 如果题目已经在某个 `writeups/<赛事>/` 里了，
   **链接过去，不要重写一遍** —— 以前就是重复记录导致同一道题被写进两天。

> **判断标准**：知识点提炼进 `notes/` 就够了；
> 只有**过程本身值得复述**的题才单独写 WP（如 un9 的协议层原理），刷量类的靶场不用逐关写。
