## 二、知识点 [`notes/17-信息泄露漏洞.md`](../notes/17-信息泄露漏洞.md)

### 1. `.bak` 为什么能泄露源码 —— 服务器按扩展名决定解析

```
/index.php      → .php → 交给 PHP-FPM → 只返回 echo 的输出
/index.php.bak  → .bak → 当静态文件    → 原封不动吐出来
```

**位置很重要**：`index.php.bak` 泄露，`index.bak.php` 不泄露。

### 2. git 对象：哈希既是内容，也是路径

```
哈希 = b738565f48bf18dc6efbf574834a7586bb75820a
路径 = .git/objects/b7/38565f48bf18dc6efbf574834a7586bb75820a
                    └┬┘└──────────────┬─────────────┘
                   前2位            后38位
```

**所以：知道哈希 → 不需要列目录也能精确取。**

这就是 `.git/objects/` 返回 403 时，`wget -r` 全废但 GitHack 仍能干活的原因 —— 它从 `logs/HEAD` 和 `index` 里拿哈希。

### 3. reflog 是 git 里最难删干净的东西

`.git/logs/HEAD` 记录**每一次引用移动**，只追加不清理。即使提交已从所有分支消失，reflog 里还有哈希。

**今天的 Git Log 题就是靠它一步定位到 `add flag` 那次提交。**

### 4. `git rm` 删不掉对象

```
git rm secret.txt → 工作区删掉、index 删掉、新 tree 不再指向它
                  → 但 .git/objects/ 里的 blob 原封不动
```

彻底删要两步：`git reflog expire --expire=now --all` + `git gc --prune=now`。
**绝大多数人只会 `git rm`** —— 这就是 99% 的 Git 泄露还有货的原因。

### 5. `.DS_Store` 的记录结构，以及"value 是诱饵"

```
┌─────────────┬──────────┬──────────┬──────────────┐
│  filename   │   code   │   type   │    value     │
│ 74430ae6... │  'note'  │  'ustr'  │ 'flag here!' │  ← 假 flag
└─────────────┴──────────┴──────────┴──────────────┘
```

**只取 `filename`，永远不看 `value`。** 出题人把假 flag 写在 Finder 注释里专门骗人。

### 6. vim swap 的三种取法，`vim -r` 不是首选

实测同一份 swap：

| 方法 | 结果 |
|---|---|
| `grep -ao "flag{[^}]*}"` | 完整 |
| `strings` | 完整，还多给服务器绝对路径 `/tmp/skill_web_.../src/index.php` |
| `vim -r` | **截断**（`// ctfhub{1bbffdd2cca2` 断在半路） |

**原因**：swap 按块异步写，崩溃时可能只写了一半数据块，`vim -r` 按块结构恢复就残缺。

### 7. Cookie 伪造：改"存储"和改"请求"是两件事

| 方式 | 改什么 | 会被服务器 `Set-Cookie` 覆盖吗 |
|---|---|---|
| 浏览器 F12 | **本地存储** | 看服务器 |
| Burp 拦截 | **发出的请求头** | 不会 |
| `curl -H` | **发出的请求头** | 不会 |

### 8. 重定向题：`Location` 和 body 是两个独立信息源

浏览器跟随后会**丢弃 302 的 body**，所以「No Flag here!」页面之外，flag 其实一直在 302 响应体里。

```bash
curl -s -i "$T/index.php"    #  看得到 302 + body
curl -s -L "$T/index.php"    #  等于浏览器，flag 被丢掉
```

### 9. HTTP Basic Auth 弱口令爆破

**题目给了 100 个密码的字典**（rockyou Top 100），没有用户名。

- **目标从首页源码拿**：`<a href="/flag.html">` → 打 `/flag.html`
- **用户名从 `realm` 拿**：`WWW-Authenticate: Basic realm="Do u know admin ?"` → `admin`
- **判据**：`Authorization: Basic base64(admin:密码)`，`200` 成功 / `401` 失败
- **爆破**：`curl -u "admin:$pw"` 循环 100 个，第 50 个 `sunshine` 命中（约 20 秒）

**坑：**

| 坑 | 现象 | 原因 |
|---|---|---|
| **B. base64 结尾的 `=` 被 URL 编码** | 全 401 | 字典里 44 个密码带 `=`，含正确答案 `sunshine`（`...c3Vuc2hpbmU=` → `...%3D`） |

**排错锚点：值必须以 `YWRtaW46` 开头（= `base64("admin:")`），且不能出现 `%3D`。**

**每实例密码不同**：实例1 = `987654321`（第 96 个），实例2 = `sunshine`（第 50 个）；用户名恒为 `admin`，同一实例内密码不变。

## 三、踩坑

### 1. `apt` 突然全挂：镜像只有 IPv6、没有 A 记录

`http.kali.org` 重定向到 `mirrors.neusoft.edu.cn`，那个域名**只有 IPv6**，导致 `E: Cannot initiate the connection ... (2001:da8:a807::25)`。

**修法**：换成 `https://mirrors.ustc.edu.cn/kali`（实测 200）。

### 2. PowerShell → wsl → bash 三层引号，嵌套必翻车

今天至少 7 次因为 `bash -c '... "..." ...'` 里的 `$()`、`|`、`"` 被 PowerShell 提前展开，导致命令变成乱码或 `syntax error`。

**教训：在 Windows 上给 WSL 传复杂命令，一律写成 `.sh` 文件，`bash /mnt/d/.../x.sh` 执行。**

### 3. `python3` 跑 GitHack 直接崩

```
ModuleNotFoundError: No module named 'urlparse'
```

GitHack 是 2017 年 Python 2 代码。Kali 源里还有 `python2 2.7.18-3`，装上即可。

### 4. GitHub 全线不通，但 `ghproxy` 通

| 源 | 结果 |
|---|---|
| `github.com` / `raw.githubusercontent.com` | HTTP 000（被墙） |
| `cdn.jsdelivr.net` | 000 |
| **`ghproxy.net`** | 200 |

### 5. WSL 变量/编码的坑

- **`$T` 只在当前终端窗口有效** —— 换窗口就没了，报错"明明刚才还能用"
- PowerShell 的 `>` 重定向默认写 **UTF-16LE**，导致文件名显示成 `7 4 4 3 0 a e ...`（每字符后跟一个 `00` 字节）
- 修法：`iconv -f UTF-16LE -t UTF-8`、或 `tr -d ' \000'`

### 6. WSL 默认发行版是 Ubuntu，`wsl` 会触发 Ubuntu 初始化

打开终端敲 `wsl` → 出现 `Provisioning the new WSL instance Ubuntu` → `Create a default Unix user account:`。

**修法**：`wsl --set-default kali-linux`。

### 7. Windows Terminal 默认 profile 是 PowerShell

我改成了 kali-linux，但用户要求恢复原样（已用备份 `settings.json.bak-*` 还原）。

**正确做法**：不动默认，用 **下拉箭头选 `kali-linux`** 或 **`Ctrl+Shift+5`**。

### 8. 自造 DS_Store 时，vim 不写数据块

第一次用「伪终端 + SIGKILL」造 `.swp`，结果 `strings` 什么都搜不到 —— 因为 **vim 只在缓冲区被修改过时才写数据块**。

**修法**：`normal! Go` 改一行 + `:preserve` 强制落盘，再 SIGKILL。

### 9. 一次"误判"值得单独记：CTFHub 的假 flag 陷阱

`.DS_Store` 题里我先用 UTF-16 启发式扫描，扫出 `flag here!` —— 以为是答案，其实那是 `value` 字段的诱饵，真文件名被漏掉了。

**换成 `ds_store` 库正式解析，一次就出。**

### 10. 又一次误判：把重定向题的 flag 当假的

看到"任意路径都返回同一个 flag"，我判断是假的。**错了** —— 出题人就是设计了 catch-all，flag 在 302 响应体里，浏览器跟随就看不到。

**教训：`Location` 头和响应体是两个独立信息源，"重定向了"不等于"body 没意义"。**

### 11. Basic Auth 爆破的两个坑（100 条全 401）

**坑 A：前缀照抄了抓包里的用户名**

浏览器登录框随手填了 `11111` / `111111`，抓到的请求是：

```http
Authorization: Basic MTExMTE6MTExMTEx          ← base64("11111:111111")
```

如果 Payload Processing 照抄 `11111:` 当前缀 → 全部 401。

| 前缀写成 | 密码 `123456` 时发出去的值 | 结果 |
|---|---|---|
| `11111:` | `MTExMTE6MTIzNDU2` | 401（用户名错） |
| `admin:` | `YWRtaW46MTIzNDU2` | 格式对（密码错也 401） |

**判断口诀：值必须 `YWRtaW46` 开头。**

**坑 B：base64 结尾的 `=` 被 URL 编码**

字典里有 **44 个**密码的 base64 带 `=`，包括**正确答案 `sunshine`**：

```
不编码:  YWRtaW46c3Vuc2hpbmU=      → 200 
被编码:  YWRtaW46c3Vuc2hpbmU%3D    → 401 
```

**这造成了最恶心的一种现象：**

```
第 1~49 条   格式正常，密码不对  → 401（正常失败）
第 50 条     sunshine 被编码毁掉 → 401（假失败）
第 51~100 条 格式正常，密码不对  → 401（正常失败）
        ↓
      100 条全 401
        ↓
看起来像"配置全错"，其实是"唯一正确答案被编码毁了"
```

**修法**：`Payloads → Payload options → 取消勾选 URL-encode these characters`。

**验证**：在结果里 Ctrl+F 搜 `%3D`，搜到就说明编码没关。

### 12. 抓包时的"随便填"会变成后面的默认值

Web 环境变量（比如上面那个 `11111`）看着无所谓，但**它会进入你的 Burp 配置**。
后面照着抓包内容配置，就把错误的值当成了"正确模板"。

**改成：抓包时用户名就填真用户名（`realm` 里已经给了），密码随便填。**

## 四、复盘

### 今天最有价值的三个认知

**① 信息泄露的本质是"目录结构泄露"，不是"漏洞"**

不需要绕过逻辑、不需要构造 payload，只要会发 HTTP 请求 + 有一个路径字典。
它的危害不在自身，在于**它是整条攻击链的起点**：源码 → 硬编码密钥 → 数据库 → 服务器。

**② "隐藏"骗的是眼睛，不是 HTTP**

`.git` `.env` `.DS_Store` 都以点开头，`ls` 看不见 —— 人就以为不存在。
但 **HTTP 请求不看你的 `ls`**。一个 `GET /.git/HEAD` 就够了。

**③ 工具是"手写循环"的打包，理解原理比会用工具重要**

GitHack 跑的时候输出：

```
[*] Try to Clone with Directory Listing
[*] ... is not support Directory Listing
[*] Try to clone with Cache          
```

**从 reflog 拿哈希 → 按哈希取对象 → zlib 解压**。
**理解了这条链，工具用不用都无所谓；不理解，工具报错就束手无策。**
