## 二、知识点

### 1. 模型的采样轨迹本身可以当隐写载体

这道题的新东西：**附件不是图、不是包、不是流量，是一份「模型每一步的候选表」**。

```json
[ { "candidates": [ {"token": "每次", "weight": 1099511627776, "logprob": -0.0001},
                    {"token": "集训", "weight": 812345678901,   "logprob": -2.41}, ... 共 20 个 ] },
  ... 共 123 步 ]
```

三个字段的含义：

| 字段 | 含义 | 谁给的 |
|---|---|---|
| `token` | 这一步的候选词 | 模型词表 |
| `logprob` | 该候选的对数概率 | 推理 API |
| `weight` | **归一化后的整数权重** | 出题人算的 |

**关键发现**：每一步的 20 个候选里，**恰好有一个 weight 等于 `2^40 = 1099511627776`，而且永远在下标 0**。这就是出题人留的「被选中」标记：

```
weight_i = round(2^40 × exp(logprob_i − logprob_0))
```

下标 0 的 `exp(0) = 1`，所以它的 weight 正好是 2^40；其余按比例缩下去。

**为什么是 2^40**：

```
太小 → 后面的候选全被 round 成 0，信息丢了
太大 → 超出 64 位整数安全范围，JSON 解析容易掉精度
2^40 ≈ 1e12 → 给「第三、第四名」也留了 8~10 位有效数字
```

### 2. 还原文本只要一行

既然「被采样」的那一步 weight 恒为 2^40，那还原生成文本就退化成取下标 0：

```python
chosen = [e['candidates'][0]['token'] for e in trace]
text = ''.join(chosen)          # 176 字
```

**得到的不是 flag，是 carrier 的「改写 + 摘要 + 截断」**：开头还在讲集训后要做的三件事，讲到第 123 步「先检查跳道边没有」就断了——典型的「模型写完就停」。

### 3. 先验真，再往下拆

这一步最值得记：**如果 trace 是编的，后面所有统计都是假的**。所以先做五项校验。

| 校验 | 判断标准 | 实测 | 结论 |
|---|---|---|---|
| 每步 top20 概率和 | 必须 ≤ 1 | max 0.999995，min 0.574 | 是真实 softmax（top20 截断，和不到 1 正常） |
| weight 与 `2^40·exp(Δlp)` 的一致性 | 误差应 < 0.5 | 最大 0.500 | 纯四舍五入，weight 没夹带 |
| logprob 是否 float32 | 能被 float32 精确表示 | 2460 个全部可以 | 来自真实推理 API |
| 相邻 rank 概率 gap | 应平滑衰减（Zipf） | −1.99 → −0.07 | 没有「硬塞进来的候选」 |
| 每步是否唯一一个 2^40、是否严格递减 | 唯一且单调 | 全部满足 | 没有「强制采样/打乱顺序」 |

**五项全过 → 载体是真的**。这一步的价值在于：把「作者动了手脚」这个可能性排掉，剩下的就只能从「内容差异」里找。

### 4. 和 carrier 的差异：谁被换了

用 `difflib` 做字符级对齐，把 123 步的生成文本和原文的 253 字对起来，得到替换清单。挑几条关键的：

```
训练           → 集训          （第 1 步）
在十五          → 十分钟        （第 8 步，后面紧跟「分钟内」，形成「十分钟分钟内」）
收浮板          → 清齐板        （第 14–15 步）
俯卧撑          → 弹卧撑        （第 101 步，「俯」是候选表第 6 名）
深蹲            → 弹蹲          （第 105 步，「深」是候选表第 1 名）
沿。            → （删除）
```

**两个证据说明这是人为设计的，不是模型幻觉**：

```
① 「俯」和「深」两个毫不相干的字，都被换成了同一个「弹」
   —— 真实模型改写不会这样，只有「按表挑字」才会
② 「十分钟分钟内」这种硬塞，语义上说不通
   —— 模型不会主动造病句，除非被要求照某个列表输出
```

**所以 payload 在「哪一步被替换了」和「替换成候选表的第几名」里。**

### 5. 20 个候选 = 一个天然的数字系统

这题的编码容量可以算出来：

```
每步 20 个候选 → 每次能编 log2(20) ≈ 4.32 bit
123 步         → 123 × 4.32 ≈ 531 bit ≈ 66 字节
```

**66 字节足够装 `SYC{...}`。** 所以「base-20」不是瞎猜，是**先算容量、再看够不够**：

| 进制选择 | 依据 |
|---|---|
| **base-20** | 候选刚好 20 个，rank 0–19 一一对应 |
| base-15 / base-3 | 题面里出现过「十五」「三」，可能是提示 |
| base-2 | rank 的奇偶 |

**先算容量再枚举进制**，比无脑试要快得多。

### 6. 通道枚举的思维方式

51 个脚本里大半是「换一个特征当比特源」，本质是一个二维穷举：

| 维度 | 都试过什么 |
|---|---|
| **取哪个数** | `logprob[0]`、`weight[1]`、`gap01`、`ratio`、`len(token)`、`sum(weight)`、`count(>25%)` |
| **怎么变成字节** | 取模 256/128/95/26/20、阈值二值化成比特、三进制、base-5（声调）、base-27（拼音首字母） |
| **怎么分组** | 按 8 位拼字节、奇偶分组、模 k 分组、按 15/3 步长抽取、倒序 |
| **怎么排布** | 直接拼、reshape 成矩阵（41×60 / 60×41 / 20×123）再渲染成图看 |

**负结果也写进报告**——「已系统性排除的通道」这一节有 9 条，下次接手的人不用重跑。

### 4. 比特流拼字节

```python
def bits2bytes(bits, lsb=False):
    bits = list(bits)[:len(bits) // 8 * 8]
    out = bytearray()
    for i in range(0, len(bits), 8):
        ch = bits[i:i + 8]
        if lsb:
            ch = ch[::-1]
        v = 0
        for b in ch:
            v = v * 2 + b
        out.append(v)
    return bytes(out)
```

### 5. 任意进制转字节

```python
def base_n_to_bytes(digs, base):
    n = 0
    for x in digs:
        n = n * base + x
    return n.to_bytes((n.bit_length() + 7) // 8, 'big')
```

## 四、踩坑

| 坑 | 现象 | 原因 / 解决 |
|---|---|---|
| 输出文件全是乱码 | `a4.txt` 按 UTF-8 打不开，`姣忔` 一路到底 | Python 输出被重定向时按系统 ANSI（GBK）写字节；要么 `-X utf8`，要么直接写 UTF-8 文件 |
| 以为 weight 是概率 | 数值大得离谱 | weight 是**归一化到 2^40 的整数**，比例才是概率 |
| 看到 top20 概率和 0.574 就怀疑被篡改 | 差点推翻整条思路 | top20 只覆盖分布的一部分，和小于 1 是正常的 |
| 把「十分钟分钟内」当模型胡话 | 一开始略过了 | 这是**硬塞**，是人为设计的证据 |
| `difflib` 把替换拆成「删+插」 | 差异表比预期长 | 中文按字符对齐，改两个字常被识别成一段 replace，看 opcode 的区间更准 |
| 只解一层就以为拿到答案 | 得到一段通顺的改写文本 | 那一层就是「载体」，flag 在下一层（rank 序列） |
| 51 个脚本全是枚举 | 时间都花在通道上 | 缺少「作者规则」假设；应该先锁定「rank + 替换位置」再枚举，而不是先枚举 |
| 候选表里找不到原文词 | `a51` 一堆 `None` | 原文词常常不在 top20 里，需要换锚点（用相邻步的候选交集） |
