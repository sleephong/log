## 二、知识点

### 1. JPEG 的文件结构：段 + 熵编码数据

以前对 JPEG 只有「一个压缩过的图」这个印象，今天拆开看，它是**一串以 `FF xx` 开头的段，加最后一段裸数据**。

实测的段表（378 KB 的附件，700×852）：

```
[2]    APP0/JFIF   长度=16
[20]   APP1/EXIF   长度=34
[56]   DQT         长度=67
[125]  DQT         长度=67
[194]  SOF0        长度=17
[213]  DHT         长度=31
[246]  DHT         长度=78
[326]  DHT         长度=28
[356]  DHT         长度=67
[425]  SOS         长度=12
[439]  之后是 386882 字节的扫描数据，一直到 EOI
```

**两个要点**：

| 要点 | 说明 |
|---|---|
| **段 = `FF` + 标记 + 2 字节长度 + 内容** | 长度字段包含它自己那 2 字节，所以下一段偏移是 `i + 2 + length` |
| **SOS 之后不再是段** | SOS 后面是熵编码的裸数据，不能再用「读长度跳下一段」的循环，否则会读飞 |

**判断「有没有藏东西」的第一刀**：

```
EOI（FF D9）之后还有字节   → 大概率是追加的文件（zip/7z/png），先看尾巴
EOI 就是文件末尾（0 字节） → 尾部没藏东西，回到结构内部找
```

今天这道题属于后者：**EOI 之后 0 字节**，尾部藏包这条路直接排除。

### 2. Huffman 表能不能藏数据

DHT 段里存的是 Huffman 表，格式是 **16 个计数 + 若干符号**：

```
[表信息 1 字节][16 字节计数][符号表 N 字节]
N = 16 个计数之和
```

**藏数据的空间就在这里**：符号表是任意字节，理论上可以塞东西。

**但解码器不宽容**：符号数和计数之和必须严格相等，多一个字节解码器就会错位，图片直接花掉或者打不开。所以能藏的只有「合法但看起来奇怪」的表——比如塞进没被用到的符号、或者把计数顺序排得很反常。

今天四张表的实测结果：

| 表 | 类型 | 符号数 | 计数之和 | 是否自洽 |
|---|---|---|---|---|
| DHT 0 | DC 表 0 | 12 | 12 | 是 |
| DHT 1 | AC 表 0 | 59 | 59 | 是 |
| DHT 2 | DC 表 1 | 9 | 9 | 是 |
| DHT 3 | AC 表 1 | 48 | 48 | 是 |

**四张全部自洽，符号表也是按大小顺序常规排列，没有多余符号**——这条路也排除。

顺带记一个常识：**标准 AC 表有 162 个符号，这里只有 59 个并不是异常**。编码器可以只写「这张图实际用到的符号」，表小反而说明是正常优化。

### 3. 位平面、通道差、增强：为什么要按这个顺序跑

结构上找不到东西，就只能回到像素。三个脚本按「成本从低到高」排：

| 步骤 | 做什么 | 能抓到什么 |
|---|---|---|
| **位平面** | `(v >> n) & 1`，n 取 0/1/2，R/G/B 各三张 | 最低位 LSB 隐写（最常见） |
| **通道差** | `R-G`、`G-B`、`R-B` 归一化到 0-255 | 只改了一个通道的痕迹（肉眼看不出色差） |
| **增强** | `autocontrast` / `equalize` | 对比度极低的暗纹、浅色文字 |

**为什么先跑位平面**：代码三行、出图秒级，覆盖了 CTF 里八成的图片隐写。**通道差和增强是补漏**，因为有些题不在 LSB 里，而是把信息藏在「颜色微微不一样」的地方。

### 4. 双层编码：解出一串 hex 不代表到头了

「好多骆驼」那题的教训今天又过了一遍：**解码层数要一直解到「不像编码」为止**。

```
emoji（base100）→ 3533353934333742...（hex 字符串）
              → 5359437B7768595F...（还是 hex）
              → SYC{whY_n0t_b45364_b3c4us3_100_1s_b1gg3r}
```

**判据很简单**：

```
解出来的内容全是 0-9 和 a-f、长度是偶数 → 它就是 hex，再解一次
解出来的内容里有 { } _ 这种 flag 字符 → 到头了
```

第一层解完看到一串纯 hex，很容易以为「这一层是密文」，其实它只是**另一层 hex 的 ASCII 表示**。

### 5. 布尔盲注的通用骨架

`丹特丽安の書架` 的过滤挺狠：`-`、`and`、`select` 全被拦。最后的骨架是

```
0' OR (条件) OR '1'='2
```

**三个设计都有原因**：

| 设计 | 为什么 |
|---|---|
| 用 `OR` 不用 `and` | `and` 被过滤了；而且 `OR` 更宽容，条件错了也不影响前半段 |
| `0'` 开头 | 把前半句变成恒假，整个结果完全由 `(条件)` 决定 |
| 末尾 `OR '1'='2` + 保留 `id=6` | 让「条件为真」和「条件为假」返回**不同**的页面，否则二分没有区分度 |

**`select` 用 `/*!select*/` 绕**：这是 MySQL 的「版本注释」，`/*! ... */` 里的内容 MySQL 会当 SQL 执行，而 WAF 只当成注释。**同样的字符，一边是注释一边是指令**——又是一次解析差异。

### 6. 参数注入：`cp -P *` 里的 `-L`

`术之尽头` 最后那步，服务器在循环执行

```bash
cd /var/www/html/primary
while :; do
    cp -P * /var/www/html/marstream/ 2>/dev/null || true
    chmod 755 -R /var/www/html/marstream/ 2>/dev/null || true
    sleep 5s
done
```

`-P` 的意思是「遇到软链接不跟随」，所以我们建的软链接 `z -> /tmp/flag` 会被原样复制，读不到内容。

**思路是让 `-P` 失效**：在目录里建一个**名字就叫 `-L` 的文件**。`*` 展开后命令变成

```bash
cp -P -L z /var/www/html/marstream/
```

`cp` 会把 `-L` 当成选项（跟随软链接），**排在后面的选项覆盖前面的**，于是 `-P` 被顶掉，`z` 被当成真文件复制过去——`/tmp/flag` 的内容就这么进了我们可写的目录。

**这类漏洞的通用形态**：程序把用户的输入拼进命令行，而输入以 `-` 开头就会被当成选项。**和 SQL 注入是同一件事，只是注入点是命令行。**

### 7. 后缀绕过成功与否：看三样，不看状态码

判断「绕过成功」的标准（`春天之路` 用的就是这套）：

| 观察 | 含义 |
|---|---|
| **响应内容** | 是文件原文 → 源码泄露；是执行结果 → RCE |
| **Content-Type** | `application/octet-stream` / `text/plain` → 被当静态文件直出 |
| **响应长度** | 和直接访问原文件对比，能判断返回的是哪个文件 |

对照法：

```
/flag.php        → 403（被拦）
/flag.php/.jpg   → 200 + 源码   → nginx 直出，WAF 被绕
/flag.php;.jpg   → 200 + 执行结果 → 后端仍按 .php 执行
```

### 1. 遍历 JPEG 段（顺序读，SOS 之后要停）

```python
i = 2
while i < len(data) - 1:
    if data[i] != 0xFF:
        print("非标记字节", hex(data[i]))
        break
    marker = data[i+1]
    if marker == 0xD9:            # EOI，结束
        break
    length = struct.unpack(">H", data[i+2:i+4])[0]
    print(i, hex(marker), length)
    i += 2 + length
```

**注意 `0xD9` 必须先判**：EOI 没有长度字段，按「读长度」处理会读飞。

## 四、踩坑

| 坑 | 现象 | 原因 / 解决 |
|---|---|---|
| 拿位平面当第一选择 | 14 张图跑完什么都没有 | 位平面只覆盖 LSB 类；先确认容器结构（段表 / EOI 之后）再决定方向 |
| 以为 `EOI` 之后一定有东西 | 白找半天 | 结构干净的图，尾巴就是 0 字节；排除要果断 |
| 把符号数少当异常 | 差点误判表被改过 | 编码器只写用到的符号，AC 表 59 个符号是正常的 |
| Python 输出重定向就乱码 | 控制台全是 `?` 和繁体字 | 管道下 Python 按系统 ANSI（GBK）写字节；加 `-X utf8` 或设 `PYTHONIOENCODING=utf-8` |
| 路径里有空格和括号 | 复制粘贴的路径跑不起来 | `罪恶王冠 (1)` 这种路径要整串加引号或用 raw string |
| `curl` 不加 `-k` | 请求像没发出去 | HTTPS 证书错误，加 `-k` |
| `.htaccess` 一行写完 | 被 WAF 拦 | 拆成多行 + 反斜杠续行，让它拼回一行 |
| 压缩 docx 套娃 | 上传解析失败 | 进到目录里选中子文件压缩，不要把外层文件夹一起压 |
| JWT 密钥爆破 | 「大蒜哥」还没完 | 字典里没有就换思路（`app.js` 里的注释、`vault` 里的字段都可能是提示） |
