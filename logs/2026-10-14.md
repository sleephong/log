## 二、知识点（今天搞懂的「信号怎么读」）

- **四种响应就是四种信号**：
  - `Hello <内容>` → 渲染成功，结果可见（外层拼接后渲染）
  - `Hello WAF` → 被黑名单拦（关卡函数返回 `"WAF"`）
  - `Hello No this level` → 模板报错，语法或运行时异常（外层 try/except）
  - `Hello correct` / `Hello wrong` → 只回 1 bit（第 3 关专属，丢弃渲染结果）
- **「被拦」和「报错」要分清**：`WAF` 是黑名单命中；`No this level` 说明放行了但运行失败 —— 比如未定义对象取属性才会报错，所以它反而是「这个字符能写」的证据
- **探针要一次只问一个问题**：`{{7*7}}` 问「输入进模板了吗」，`{{7*'7'}}` 问「是哪种引擎」（Jinja2 给 `7777777`，Twig 给 `49`），`{% print(7*7) %}` 问「语句块容器能用吗」
- **交叉对照才能定论**：`{{ 'a'~'b' }}` 返回 `WAF` 时说不清是被 `~` 拦还是被引号拦，必须换一条只带拼接、不带引号的探针再测

## 三、案例 / payload

探查阶段最有价值的是「同一条探针，三种现象」：

```jinja
{{7*7}}            -> 49            进模板了
                   -> WAF           这个容器被黑名单拦
                   -> Hello correct 进了，但输出被关卡丢弃
                   -> {{7*7}} 原样   根本没进模板

{{7*'7'}}          -> 7777777       Jinja2（字符串重复）
                   -> 49            Twig（按 PHP 语义算乘法）

{% print(7*7) %}   -> 49            语句块容器可用
```
