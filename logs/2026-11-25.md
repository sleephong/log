## 二、知识点

### 1. FOFA 有两种额度，不是一种

这是今天最大的意外。一直以为「FOFA 有 300 次」，实测发现是两套账：

```
cookie 里的 data_limit:  web_query=300, web_data=3000, api_query=0, api_data=0
```

| 额度 | 走哪个入口 | 能用什么 |
|---|---|---|
| **web_query 300** | 网页版搜索框 | 页面内那个内部接口 |
| **api_query 0** | `/api/v1/search/all` 这类开放 API | 无 |

所以 `GET /api/v1/info/my` 返回 `[-700] 账号无效` 并不代表「没登录」，而是**这个账号没有 API 权限**。

**判断依据**：`-700` 配 200 状态码 = 凭据/权限问题，不是网络问题。**先去看额度字段，再去猜路径。**

### 2. 猜 API 路径是最浪费时间的一种做法

试过 18 个常见路径（`/api/v1/search`、`/search/next`、`/aggregate`、`/result`…），全部 404。

**正确做法**：在已登录的页面里**钩住页面自己的 `fetch`**，然后手动搜一次，把真实请求抓下来。

```javascript
const orig = window.fetch;
window.fetch = function (u, o) {
  const s = typeof u === 'string' ? u : u.url;
  if (/search|query|result|asset/.test(s)) console.log('[FOFA] 捕获', s);
  return orig.apply(this, arguments);
};
```

**为什么这样对**：网页版走的是页面内部接口，参数可能还有签名/加密，与其逆向不如让它自己发一次、自己接住。**接口的真相在流量里，不在文档里。**

### 3. `/api/v1/...` 之外，还有「合并查询」省额度

57 条单查 = 57 点。用 FOFA 的 `||`（OR）把同组组件压成一条：

```
app="Apache-Solr" || app="Grafana" || app="Kibana" || ...
```

57 条压成 7 组，第一轮只花 7 点，剩下的额度按 `total` 决定翻不翻页。

| 策略 | 消耗 | 适合 |
|---|---|---|
| 合并优先（7 组 × 1 页，再挑着翻） | ≤ 62 | 先拿广度 |
| 精确优先（57 条逐条） | 184 | 已知要打哪几个组件 |
| 只打高价值（`--only-rank high`） | 73 | 额度紧、只要 RCE 面 |

**先跑 `--dry-run` 看计划再花额度**——额度是有限的，`dry-run` 是免费的。

### 4. 没有 key 时的替代源（实测过）

| 源 | 要不要 key | 实测 | 适合 |
|---|---|---|---|
| **urlscan.io** | 免费（限流） | `page.title:"Grafana"` → 1729 条 | 按页面标题/URL 路径找 |
| **netlas.io** | 免费（匿名限流） | `http.title:"Solr Admin"` → 20 条，第 4 次 429 | 标题/响应体指纹 |
| **crt.sh** | 免费 | 只给证书和子域 | 资产发现，要再扫 |
| Google / Bing | 免费 | `intitle:"Solr Admin"` | 少量高价值补充 |

**限流不是失败**：429 就退避（间隔 ≥3s），别硬刚——硬刚的结果是 IP 被拉黑，连 20 条都没了。

### 5. 从「搜到」到「确认」是两件事

搜索结果给的是**指纹候选**，不是漏洞。标准链路：

```
候选 host
  → httpx 确认存活 + 指纹 + 版本线索
  → 对比 CVE 目录里受影响版本区间
  → nuclei -t <对应模板>
  → 人工复核回显（命令执行/文件读取结果）
```

**中间任何一步跳过，都会得出「扫到一堆洞」的假结论。**

### 6. 归属校验要写成硬门槛

79 个候选里剔掉 1 个（Tencent 的 CN 段），剩 78 个（US 25 / SE 11 / DE 6 / JP 4 / BR 4…）。

**做法**：每个 host 先查 IP 归属（国家 + ASN），命中禁止区域直接进排除表，**不靠人眼看**——79 条能看，790 条就看漏了。

```
生成 targets_checked.md：总数 / 合格 / 排除 + 排除理由 + 国家分布
```

**可审计**比「我记得筛过了」值钱。

### 7. 额度要记账

`fofa-usage.json` 每条查询记：query 的 hash、消耗、total、错误、时间戳。

三个作用：

```
① 可审计 —— 报告里能说清「花了多少、换回多少」
② 可续跑 —— --resume 靠 hash 跳过已完成的查询（失败不扣点，重跑不重复扣）
③ 可复盘 —— 哪条查询 total 为 0，说明这条指纹写错了
```

## 四、踩坑

| 坑 | 现象 | 原因 / 解决 |
|---|---|---|
| 以为 `-700` 是没登录 | 反复换 key、换邮箱 | 账号只有网页额度，API 额度为 0；看 `data_limit` 字段 |
| 猜了 18 个 API 路径 | 全 404 | 干脆别猜，钩 `fetch` 抓真实端点 |
| 合并查询写成 `&&` | 结果 0 条 | FOFA 里 `&&` 是「同时满足」，`||` 才是并集 |
| netlas 第 4 次就 429 | 后面全是空 | 匿名限流，必须退避 |
| urlscan 也 429 | 前几条正常 | 同样要间隔 ≥3s |
| `nmap` 报找不到网卡 | 扫不了 | 缺 Npcap，装 `npcap-1.90.exe` |
| Defender 把工具当木马删 | 二进制直接消失 | 加排除目录，别关实时防护 |
| 目标清单里混进不该打的段 | 差点越界 | 归属校验做成硬门槛，命中就进排除表 |
| 只记「扫到多少」 | 报告写不出细节 | 额度台账 + 每条的 total 都要留 |
