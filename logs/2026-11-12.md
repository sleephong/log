## 二、知识点

### 1. 签到题：hex 编码一眼认

`cipher.txt` 内容：

```
666c61677b6833785f31735f73305f653473797d
```

`66 6c 61 67` 就是 `flag` 的 ASCII。解码得到：

```
flag{h3x_1s_s0_e4sy}
```

**判据**：整串只由 `0-9a-f` 组成、长度是偶数 → 先试 hex。

常见的几个 ASCII 十六进制前缀，记住能秒判：

| 明文开头 | hex |
|---|---|
| `flag` | `666c6167` |
| `SYC` | `535943` |
| `ctf` | `637466` |

### 2. Base36 / Base52 这类编码怎么辨认

附件 `basehome.html` 的标题是「Base36 / Base52 加解密工具」。

标准 base 家族的特征：

| 编码 | 字符集 | 特征 |
|---|---|---|
| Base16(hex) | `0-9a-f` | 只有 16 个字符 |
| Base32 | `A-Z2-7` | 大写字母 + 2-7，结尾常有 `=` |
| Base36 | `0-9a-z` | 字母数字混合，无大小写区分 |
| Base52 | `a-zA-Z` | **只有字母，没有数字** |
| Base62 | `0-9a-zA-Z` | 全字母数字 |
| Base64 | `A-Za-z0-9+/` | 结尾常有 `=` |
| Base58 | 去掉 `0OIl` | 比特币用，无 `0` `O` `I` `l` |
| Base85/91 | 含符号 | 密度更高 |

**判据顺序**：看字符集（有哪些字符）→ 看长度（是不是 4 的倍数）→ 看结尾有没有 `=`。

### 3. docx 本质是 zip，先解压再看

`lighthouse.docx` 的十六进制头是 `50 4b 03 04`（`PK`），就是 zip。

解压后的结构：

```
[Content_Types].xml
_rels/.rels
docProps/core.xml          ← 作者、创建时间，可能泄露信息
word/document.xml          ← 正文（34 KB）
word/styles.xml            ← 样式（341 KB）
word/stylesWithEffects.xml
word/settings.xml
```

**文档类隐写的常见藏点**：

| 位置 | 藏法 |
|---|---|
| `document.xml` | 白字（字体颜色 = FFFFFF）、字号 1、隐藏文字（`w:vanish`） |
| `core.xml` | 作者名、备注、修订记录 |
| `word/media/` | 夹带的图片 |
| 文档末尾 | 追加的二进制（zip 结构之外） |
| 修订/批注 | `w:ins` `w:del` 里的旧内容 |

**操作**：改后缀为 `.zip` 解压，或直接看末尾有没有多余字节。

### 4. png 图片隐写的排查顺序

`aurora.png` 是 1.2 MB，`aurora.xcf` 是 1.5 MB——**说明当时用 GIMP 打开手动折腾过**。

**固定排查顺序**（从快到慢）：

```
① 文件末尾追加    binwalk / 看 EOF 之后有没有东西
② 元数据          exiftool / pngcheck -v
③ 文本块          PNG 的 tEXt / zTXt / iTXt
④ 图层/通道       GIMP 逐通道看，或 zsteg
⑤ LSB             最低位提取，看是不是灰度图/文字
⑥ 宽高异常        改 IHDR 里的宽高，看是否有隐藏区域
⑦ 调色板          GIF 的 GCT、PNG 的 PLTE
⑧ 频域            DCT/DFT 分析（jsteg、F5）
```

**教训**：这题当时靠 GIMP 手动看，慢且不可复现。晚上才补了 StegoTool（bmp_lab / img_probe / jpeg_lab / exif_lab / zip_probe / dft_read），**比赛暴露的短板，当天就该补工具**。

### 5. pcapng 流量分析看三件事

`bigshark.pcapng` 25 KB，很小，说明题不难。

```
① 协议分层    统计 → 协议分级，先看有没有 HTTP/FTP/DNS
② 导出对象    File → Export Objects → HTTP，看有没有传文件
③ 追踪流      右键 → Follow → TCP Stream，看完整对话
```

**常见藏点**：HTTP 传的文件、DNS 查询里的域名编码、ICMP 载荷、USB 流量（键盘/鼠标）。

### 6. ELF 逆向的第一步不是看汇编

`chall` 是 ELF 64 位，而且下载了 6 个副本（`chall` 到 `chall (5)`）——**说明反复试过，卡住了**。

**正确的起手顺序**：

```
① file / strings      先看它是什么、有什么字符串
② strings | grep flag 看有没有直接写死的 flag 或提示
③ 动态跑一次          看它要什么输入
④ 再看 main 的反汇编
```

**卡住的典型原因**：一上来就开 IDA 看 `main`，但没先 `strings`，漏掉了明文字符串或错误提示（错误提示能反推校验逻辑）。

### 7. 比赛工具化的三条经验

**① 一键启动 > 分步操作**

比赛时手忙脚乱，`打开界面.bat` 双击起服务 + 开界面，比记五条命令可靠。

**② 输出判读比工具本身重要**

`输出判读手册` 解决的问题是：扫描器打印了一堆东西，**哪个是线索、哪个是噪音**。

比如签到扫描的三种符号：`★` 疑似 flag、`?` 有差异值得看、`✓` 有这个东西。

**③ 非 Web 题要有「30 秒判断表」**

Web 题有固定套路，非 Web（Misc/Crypto/Reverse）容易一上来就懵。

判断表的作用：看附件长什么样 → 归到哪一类 → 走哪个模板 → 或者**直接放弃**（三个放弃信号）。

## 三、案例 / 命令

### 1. 签到题 hex 解码

```powershell
$hex = (Get-Content cipher.txt -Raw) -replace '[^0-9a-fA-F]',''
-join ([byte[]]($hex -split '(..)' | Where-Object {$_} | ForEach-Object { [Convert]::ToByte($_,16) }) | ForEach-Object { [char]$_ })
```

或者直接 CyberChef 的 `From Hex`。

### 2. 判断文件真实类型（看头 4~8 字节）

```
50 4b 03 04   →  zip（docx/xlsx/pptx 都是）
89 50 4e 47   →  png
7f 45 4c 46   →  ELF
0a 0d 0d 0a   →  pcapng
3c 21 44 4f   →  <!DO（html）
```

### 3. docx 解压看结构

```powershell
Add-Type -AssemblyName System.IO.Compression.FileSystem
$z = [IO.Compression.ZipFile]::OpenRead("lighthouse.docx")
$z.Entries | Select-Object FullName, Length
```
