## 二、知识点

### 1. CTR 已知明文攻击：比空格异或法更直接

昨天判断出「不能套空格异或法」，但没找到突破口。今天换了个思路。

CTR 复用得到的核心等式：

```
C1 XOR C2 = P1 XOR P2
```

**如果知道其中一段明文**，另一段就直接出来了：

```
P2 = C1 XOR C2 XOR P1
```

代码只有一行：

```python
k = "今晚宵禁后，老地方的喷泉边，我有话想跟你说。别让白猫的人发现，我会甩开黑犬的".encode()
print(bytes(a ^ b ^ c for a, b, c in zip(c1, c2, k)).decode())
```

**输出**：

```
老地方见，暗号是 SYC{black_dog_and_white_cat}。让我们一起改变这个世界
```

**为什么这条路通**：题目里的两段明文是**中文 UTF-8**，不是英文。中文每个字占 3 字节、首字节高位是 1，所以：

- 空格异或法（`XOR 0x20` 翻转大小写）**完全不适用**
- 但只要有任意一段明文，异或就能反推另一段——**这条路和明文语言无关**

**两种攻击的适用条件对比**：

| 攻击 | 前提 | 适用明文 |
|---|---|---|
| 空格异或 / crib dragging | 明文是自然语言（英文为主） | ASCII |
| **已知明文** | 知道任意一段 | **任何类型**，包括中文、二进制 |

### 2. 为什么中文让空格异或法失效（昨天的实测数据）

昨天做过一个可行性检查：对每个位置，找所有能让两段密文都变成可打印 ASCII 的密钥流字节。

```
89 个位置里只有 60 个有解，24 字节之后全部无解
```

**再看异或值**：

```
前 24 字节：0c 3b 0b 03 05 2a ...     ← 都是小值，说明前缀相似
24 字节后： c6 c5 e0 a4 e1 e6 ...     ← 高位全置起
```

**现在回头看就通了**：中文 UTF-8 的字节都在 `0xE4`~`0xE9` 区间，高位天然是 1。所以只要明文里出现中文，异或值就必然带高位。

**这条判断标准值得记**：`C1 XOR C2` 里出现大量高位为 1 的字节 → **明文大概率不是纯 ASCII**，别浪费时间在空格异或法上。

### 3. BMP 隐写的排查动作

今天写的脚本基本覆盖了 BMP 的所有常规藏点：

| 脚本 | 查什么 |
|---|---|
| `bmp_probe.py` | 先看文件结构（头、位深、调色板） |
| `bmp_split.py` | **通道分离**：R / G / B / A 分别提出来看 |
| `bmp_lsb.py` | 各通道的最低有效位 |
| `bmp_mask.py` | 按位掩码（第 n 位单独提出来） |
| `bmp_lshape.py` | L 形区域（有些题把数据藏在特定形状里） |
| `bmp_fft.py` | **频域**：FFT 之后看幅度谱 |
| `fft_crop.py` | 频谱的四个角分别裁出来，再做水平/垂直翻转 |
| `fft_rot.py` | 频谱旋转 |

**关键在 FFT 那一步**：很多题把文字或二维码藏在频域，而频域图必须**裁四个角 + 翻转**才看得清（因为 FFT 结果原点在中心，四个角是高频区，且有对称性）。

### 4. 音频频谱藏二维码

| 脚本 | 作用 |
|---|---|
| `audio_probe.py` | 看音频基本信息（采样率、声道、时长） |
| `audio_stft.py` | **短时傅里叶变换** → 生成频谱图 |
| `audio_bands.py` | 分频段看 |
| `audio_hi.py` | 只看高频段（藏东西常在高频） |
| `audio_rms.py` | 看能量包络（摩斯码常用） |
| `audio_qr.py` | 从频谱里找二维码 |

**流程**：

```
音频 → STFT → 频谱图（spec_full.png）→ 切出二维码区域（spec_qr.png）→ 网格重建 → 解码
```

**为什么频谱能藏二维码**：把二维码的像素当成"某个频率上有没有能量"，人耳听不出来，但 STFT 画出来就是一张图。

### 5. 二维码网格重建（为什么需要一串脚本）

`qr_grid.py` / `qr_grid2.py` / `qr_grid3.py` / `qr_area.py` / `qr_try_th.py` / `qr_from_shot.py`

**因为从频谱里切出来的二维码通常不能直接扫**：

| 问题 | 原因 |
|---|---|
| 尺寸不对 | 频谱分辨率低，二维码可能只有几十像素 |
| 有噪点 | 频谱图不是纯黑白，需要二值化 |
| 边界不准 | 切出来的框可能偏几个像素 |
| 缺定位图案 | 三个角上的"回"字定位符被切掉或干扰 |

**所以要「网格重建」**：先确定模块大小（每个小方格几像素），再按网格重新采样成标准二维码，最后解码。有时候还要按二维码的纠错规则补一部分缺失的模块。

### 1. CTR 已知明文攻击（最终解法）

```python
import re
t = open("output.txt").read()
c1, c2 = [bytes.fromhex(x) for x in re.findall(r"c[12] = (\w+)", t)]
known = "已知的那段明文".encode()
print(bytes(a ^ b ^ c for a, b, c in zip(c1, c2, known)).decode())
```

**注意用 `zip` 只跑到最短的长度**，长的那段要另外处理（拿已知明文和密钥流继续解）。

### 2. 判断明文是不是 ASCII

```python
for i in range(n):
    cand = [k for k in range(256)
            if 0x20 <= (c1[i] ^ k) <= 0x7e and 0x20 <= (c2[i] ^ k) <= 0x7e]
    if not cand:
        print("位置", i, "不可能两段都是 ASCII")
        break
```

### 3. BMP 通道分离 + LSB

```python
from PIL import Image
im = Image.open("x.bmp").convert("RGBA")
for i, name in enumerate("RGBA"):
    ch = im.split()[i]
    ch.save(f"out_{name.lower()}.png")
    # LSB
    lsb = ch.point(lambda v: (v & 1) * 255)
    lsb.save(f"out_{name.lower()}_lsb.png")
```

### 4. 频谱图

```python
import numpy as np
from scipy import signal
from PIL import Image

rate, data = wavfile.read("x.wav")
```

## 五、bugscan 的三个设计原则（今天写的工具）

写这个工具不是为了"一键挖洞"，README 开头就写了三个要解决的问题：

| 问题 | 做法 |
|---|---|
| **别手抖打错站** | 所有请求前强制过授权清单，越界直接抛 `ScopeError`，**不是靠自觉** |
| **别把工具输出当结论** | 每条发现必须写清「主张 / 理由 / 限制」，并附原始报文 |
| **别重复劳动** | 信息泄露、未授权访问这类低危中危交给机器跑 |

**scope.py 的强制校验**（不是提示，是直接拒绝运行）：

```
scope 文件不是 UTF-8          → 抛 ScopeError
不是合法 TOML                 → 抛 ScopeError
没有任何 [[targets]] 条目      → 拒绝运行
[authorization] 写成字符串     → 抛 ScopeError
```

**report.py 强制三段式**：

```
**主张**：是什么问题
**理由**：为什么认为是
**限制**：什么情况下结论不成立
```

**这一点值得单独记**：工具输出 ≠ 漏洞。报告里标「需人工确认」的就只是线索，提交前必须手工复现。
