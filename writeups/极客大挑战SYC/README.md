## 三届横向对比

| 维度 | 2023 · unsign | 2024 · ez_http | 2025 · popself |
|---|---|---|---|
| **类型** | PHP 反序列化（POP 链） | HTTP 请求层级 + JWT | PHP 反序列化（POP 链） |
| **链长** | **3 跳** | **6 级**（L1~L6 串行 AND） | **6 跳** |
| **入口** | POST `url`（`unserialize($_POST['url'])`） | GET 参数 / POST body / 请求头 / Cookie **六处同时** | GET `?24[SYC.zip=`（**未闭合方括号**绕参数名点号） |
| **链子形状** | `__destruct → __invoke → __get` | 无魔术方法，六层 `if` 逐关 `die()` | `__destruct → __set → __call → __toString → __invoke` |
| **终点** | `$eva1($interesting)` → `system` / `readfile` | 六项全带后 `echo $flag` | `$f($arg)` → `system("env")` |
| **前置门禁** | 无 | 无 | **双 md5 魔术哈希**（`179122048` / `240610708`，双层是 18.6 s 爆破出来的） |
| **最贵的坑** | **属性名逐字节一致**：`eva1`（数字 `1`）写成 `eval`（字母 `l`），长度都是 4 所以 `unserialize` 不报错 | `false`→`true` 少 1 字节，**手工在 base64 里原地改会错位** → 正解是**解码成字节再改、然后重签** | **每个对象都要补齐** `KiraKiraAyu`/`K4per`，否则它自己的 `__destruct` 先把你 `die` 掉 |
| **第二贵的坑** | `yxx` 不接线 → `null->QW` 只报 notice，**静默断链** | `X-Forwarded-For` 无效，得**枚举**出 `X-Real-IP` | `requests` 的 `params=` 会把 `[` 和 `.` 编坏 |
| **调试手段** | 源码自带 3 个 `echo` → **`echo` 断点法** | 「**卡在第几关**」反推错在哪一层 | `split("</code>")[-1]` 切掉 `highlight_file` 源码 |
| **难度递进** | 入门：只有 3 跳，一次就推通 | 中：单点都不难，难在**六项必须一次全带** + 一次判掉「要不要重签」 | 难：6 跳 + 门禁 + 参数名绕过，三个坑叠在一起 |
| **状态** | 链子已推通 | 已通关 | 已通关 |

### 难度递进怎么看

```
2023 unsign   3 跳，无门禁，无绕参  ──▶  练「怎么读链」
2024 ez_http  6 层，无链子，要绕编码 ──▶  练「怎么一次带齐 + 判服务端验不验签」
2025 popself  6 跳 + 门禁 + 绕参    ──▶  练「链子 + 弱类型 + HTTP 参数三层叠加」
```

**顺序上刚好互补**：
- 2023 教 **POP 链的读法**（对象图 / 魔术方法触发时机 / `echo` 断点法）；
- 2024 教 **HTTP 层的完整性**（六项一次全带 / 「卡在第几关」诊断法 / JWT 重签）；
- 2025 是两者的**叠加**，并且多了一层**弱类型门禁**（双 md5 魔术哈希）和一层**参数名绕过**。

## 复盘

### 反序列化是绝对主力

三届里 **两届（2023、2025）是纯反序列化**；2024 虽然考的是 HTTP + JWT，但**解题套路完全同源**：

| 阶段 | 反序列化题（2023 / 2025） | HTTP 题（2024） |
|---|---|---|
| ① 读源码 | 找 `unserialize()` 入口 + 起点魔术方法 | 找六层 `if` 和各自的判断位置 |
| ② 定位触发点 | 逐跳抄关键行（属性填什么） | 逐关列出要带什么（参数/头/Cookie） |
| ③ 拼利用物 | 造对象图 → 序列化串 | 造 JWT → 改字节 + 重签 |
| ④ 发出去 | POST / GET | 六项一次全带 |
| ⑤ 断点定位 | `echo` 停在哪 | 卡在第几关 |

**结论**：三届考的是**同一套方法论的两种皮**。把「读源码 → 定触发点 → 拼 payload → 发 → 用断点定位」这五步练熟，比背 payload 有用得多。

> 需要说准确的一点：**严格讲不是「三届都考反序列化」** —— 2024 的 ez_http 里没有任何 `unserialize`。
> 共同点是**方法论**，不是知识点。

### 最大收获

1. **`echo` 断点法**（2023）—— 源码里的 `echo` 是出题人免费送的进度条，「输出停在哪 = 断在后一跳」。
 没有 echo 就退化成二分法：从中间截断链子看报错位置。
2. **从里往外搭 payload**（2025）—— 读链子从起点到终点，**搭 payload 必须从终点倒回来**。
3. **改字节不改字符串**（2024）—— base64 是「3 字节 → 4 字符」的定宽映射，
 **在 base64 串里原地改中间字段**会让后面全部错位；**先解码成字节再改，然后重签**。
 `false`→`true` 补空格、丢点、双重 URL 编码，本质是同一条规律。
4. **分层题自带诊断**（2024）—— 「卡在第几关」直接告诉你错在哪一层（且 Cookie 出错也表现为卡 L5）。

### 踩过的坑（按贵程度排）

| # | 坑 | 教训 |
|---|---|---|
| ① | `eva1`（数字 `1`）写成 `eval`（字母 `l`） | **长度都是 4，`unserialize` 不报错**，只在终点 `Fatal error`。→ **类定义从靶机复制，别手打**；本地跑一次 `unserialize` 是唯一能抓到它的方法。**数长度没用。** |
| ② | 链上某个对象漏了 `KiraKiraAyu`/`K4per` | 每个对象的 `__destruct` 都会跑 → **前置校验属性要每个对象都补齐**（用 `base()` 统一包） |
| ③ | 在 base64 字符串里原地改 `false`→`true` | 改动点**在末尾**时没事（实测四种做法全过）；**改中间 + 长度变了**才会错位 → **先解码成字节再改，然后重签** |
| ④ | `requests` 的 `params=` 编坏了 `[` 和 `.` | 参数名**手拼查询串**，值才用 `quote(v, safe="")` |
| ⑤ | `json.dumps()` 改了 payload 字节 → 误判「密钥不对」 | **先解码打印一眼**再动手：段数 → 解码 → 字段名 → 编码 → 最后才怀疑签名 |
| ⑥ | 回显混着 `highlight_file` 的源码 | 固定收尾 `split("</code>")[-1]` |
