## 复盘

### 最大收获

1. **「钓」而不是「拼」** —— 字符白名单只限制**我能输入的字符**，限制不了 **shell glob 展开之后的字符串**。磁盘上本来就有 `/bin/nl` 和 `flag.php`，我只需要写出**能匹配它们的模式**（`/???/?l fla?.???`）。这是本次认知升级最大的一条。
2. **形状 + 排序第一** 判定法 —— 一个形状能匹配到一串程序，`system` 拿到的是**字典序最前**那个。于是「这个命令能不能用」变成一个**可枚举、可判死**的问题（9 个候选 → 3 个可用）。
3. **只依赖正向证据** —— 用 `file` 让「不存在」也开口说话（`cannot open`），用**哨兵**（payload 后加 `/`）让「命令位有没有上场」可判定。**空响应是多义的**（至少 4 种成因），没有正向证据就只能在空白里瞎猜。
4. **前端 JS 是最好的接口文档** —— ATP 平台那题，`submit.js` 把路径、方法、`Content-Type`、字段名全送了；客户端那套"防 DevTools"的保护对脚本**零影响**。
5. **提示要翻译成数据流** —— 「美丽的汤」= BeautifulSoup，等于直接告诉你「别用正则啃 HTML」；这一句同时解决了**实体解码**和**诱饵排除**两个坑。
6. **业务逻辑题找「判重键」** —— 投票题的服务端只拿 `sid` 判「投过没有」，`voter` 完全不看；固定有效 `sid`、每轮换 `voter`，就能无限投票。**判重字段是逐个换掉、逐个保留试出来的**，不是猜的。
7. **先打印，再写路径** —— 不知道返回结构时不要凭感觉写 `r["data"]["flag"]`；`print(r.text)` → `print(list(j.keys()))` → 逐层钻。本次两次 `TypeError`/`KeyError` 都是「先写路径、后看结构」造成的。

### 踩过的坑

| 坑 | 教训 |
|---|---|
| **空响应当成「没钓到」** | 空响应至少有 4 种成因：glob 没匹配 / 命令无输出 / **命令位被目录抢走** / 参数个数错 |
| **`/????/f???` 抢位事故** | 输出 `fsck from util-linux` —— **形状命中 ≠ 身份正确**，要看输出里的**真实路径** |
| **`/???/???/f???` 被 `/sys/bus/faux` 抢** | 深度候选会**随实例变化**，必须并列穷举 + 哨兵 |
| **实体没解码拼出 136 字符** | 长度不对先怀疑**编码**（3 片 `&#43;` → 每片多 4 字符），不是怀疑自己漏收片段 |
| **ATP 用表单编码提交** | 200 但返回 5611 字节 HTML —— 判据是**响应体形状**，不是状态码 |
| **实例销毁 vs URL 写错** | 两种都是 404，但**页不同**（网关页 4681 字节 vs Apache 页）→ 一个换域名，一个补 `?c=` |
| **靶机换了 3 次实例** | **缓存原始数据**；动态靶机的「命令候选表」不是全局常量，换实例后要重跑形状判定 |
| **投票脚本静默跑 49 秒，像卡死** | 循环里一句 `print` 都没有，输出还攒在缓冲区 → 加进度 print + **`flush=True`**；flag 第 1 次就给，根本不必循环 200 次 |
| **`r["data"]["flag"]` 报 `TypeError`** | `r` 还是 `Response` 对象，没 `.json()` 就下标访问；`r["data"]["votes"]` 之后又下标同理（那是 int） |
