## 一句话

> flag 被**打散成 124 个片段**散在博客页面上，每片都不是明文：**flag 原文 → gzip → base64 → 拆成 124 片**。把 124 片按 `id` 收全 → 拼成 base64 → 解出 gzip → 得到 flag。坑在于**有 3 片是 HTML 实体**，以及**页面上还挂着一条同样合法的「诱饵链」**。

## 一、还原链

```
flag 原文 → gzip（魔数 1f 8b 08）→ base64（必以 "H4sI" 开头 ← 校验锚点）→ 拆成 124 片
```

**方向是反着爬回来的**：

```
124 个 span.flag-fragment（按 id=1..124）
        ↓  拼接
base64 串（124 字符）
        ↓  b64decode + gunzip
gzip 数据（魔数 1f 8b 08）
        ↓
flag 原文
```

| 锚点 | 值 | 作用 |
|---|---|---|
| gzip 魔数 | `1f 8b 08` | 证明「解出来的东西该 gunzip 了」 |
| base64 前缀 | **`H4sI`** | base64(gzip) 的特征开头 —— **不用解压就能判断链路对没对** |
| 片段数 | **124** | 有索引就枚举（`id=1..124`），**不要顺着链接爬** |
| flag 格式 | `0xGame{...}` | 终点校验 |

## 二、两个坑

### 2.1 HTML 实体：3 片是 `&#43;` 而不是裸字符

| 片段 | 形态 |
|---|---|
| 121 片 | 裸字符 |
| **3 片（39 / 104 / 111）** | **`&#43;`**（= `+`） |

```
纯正则提取  →  &#43; 被当成 5 个字符照抄 → 拼出 136 字符 → base64 报错
HTML 解析器 →  自动解码成 1 个 '+'      → 拼出 124 字符 → 解压成功
```

**账算得平**：3 片各多 4 个字符（5 − 1），`124 + 3×4 = 136` —— 这正好是「纯正则路线」拼出来的长度。

> 如果**只按长度校验**（「应该是 124 啊」）会一直以为自己少收了 12 片，其实是**该解码的实体没解码**。

### 2.2 诱饵链也是合法 base64

页面上不只有一条链：**诱饵链在「单块」这个层面上永远分不出来** —— 每一片都长得像正常的 base64 片段。

> **只有「全链 + gzip 魔数」能裁决**：拼完 `H4sI` 开头、解压成功的那条才是真的。

### 2.3 提示「美丽的汤」= BeautifulSoup

提示词 **「美丽的汤」= BeautifulSoup** —— 它在告诉你**别用正则啃 HTML**：

```python
soup.select_one("span.flag-fragment").get_text()
#                ↑ 按 class 选元素 → 天然排除诱饵（不属于这个 class 的不进来）
#                                    ↑ get_text() 自动解码 HTML 实体（&#43; → +）
```

一次调用同时解决两个坑：**class 选择器排除诱饵 + `get_text()` 解码实体**。

## 三、可直接抄的代码

日志原文（就这两行）：

```python
frag = soup.select_one("span.flag-fragment").get_text(strip=True)   # 自动解码实体 + 排除诱饵
# 按 id=1..124 拼接 → base64 解码 → gunzip → flag
```

**推论**：把上面两步展开成可运行的脚本（**不是日志原文**，路由/字段名按题目实际填）：

```python
import base64, gzip, re, requests
from bs4 import BeautifulSoup

# 路径按题目实际填；关键点是按 id 枚举，不顺着链接爬
URL = "<题目页面>?id={}"

parts = []
for i in range(1, 125):                       # id=1..124
    html = requests.get(URL.format(i)).text
    soup = BeautifulSoup(html, "html.parser")
    parts.append(soup.select_one("span.flag-fragment").get_text(strip=True))
    print(i, len("".join(parts)))             # 每步打印可验证中间量（长度）

b64 = "".join(parts)
print(len(b64), b64[:4])                      # 期望 124 和 "H4sI"  ← 校验锚点
raw = base64.b64decode(b64)
print(raw[:3].hex())                          # 期望 1f8b08        ← gzip 魔数
print(gzip.decompress(raw).decode())
```

**三个可验证中间量**（每个都能提前判死）：

| 打印什么 | 期望值 | 不对说明什么 |
|---|---|---|
| 拼接长度 | `124` | 有实体没解码（会变 136）/ 片段没收全 |
| 前 4 个字符 | `H4sI` | 拼错顺序 / 收错链（诱饵） |
| 前 3 字节 | `1f8b08` | 不是 gzip 数据 |

## 四、判据速记

| 现象 | 结论 |
|---|---|
| base64 串以 **`H4sI`** 开头 | 是 `base64(gzip)`，可以解压 |
| 解出的前 3 字节 = **`1f 8b 08`** | gzip 魔数确认 |
| 拼接长度 **136** 而不是 124 | 有 HTML 实体（`&#43;`）被当字面量抄了 |
| 单块看不出真假 | **必须全链 + 魔数裁决**（诱饵链单块层面合法） |
| `id=1..124` 有索引 | **枚举**，不要顺着链接爬 |

## 五、踩坑点

| 问题 | 原因 | 解决 |
|---|---|---|
| **奶蛙用纯正则提取** | 3 页是 `&#43;` 实体，没解码 → 拼接长度 136 | 用 HTML 解析器（`get_text` 自动解码） |
| 单块层面分不出诱饵 | 诱饵链每片也是合法 base64 | 收全链，用开头 `H4sI` + gzip 魔数裁决 |

> **一句话收尾**：**编码链题的解法是「把提示翻译成数据流」** —— 方向（gzip → base64 → 分片）+ 校验锚点（`H4sI`、`1f8b08`、`0xGame{}`）+ **有索引就枚举**；而 HTML 一定要交给解析器，**正则解不了实体，也认不出诱饵**。
