## 复盘

### 最大收获

| # | 收获 | 出处 |
|---|---|---|
| 1 | **"绕过校验"不止一条路** —— 除了让判断为假（`0`），还能让函数**报错**（`false`）；`preg_match` 的三态返回值就是入口 | swp |
| 2 | **回溯爆炸的条件是"必须回退足够多次"，不是"字符串够长"** —— 填充位置（前 vs 后）直接决定成败 | swp |
| 3 | **穷举常规路是在"排除一整个类别"** —— 把 1–255 分隔符/双重编码/数组全测死，才会想到"让函数报错" | swp |
| 4 | **信息面是"整个报文"** —— flag 可以同时藏在响应头、`robots.txt`、Cookie 里；flag 不完整就要想到**分段** | seek flag |
| 5 | **数字型身份参数 = 可枚举** —— `Set-Cookie: id=0` 是三条危险信号一次集齐；**值可形变（`01`/`1.0`/`1e0`），名不可改（大小写敏感）** | seek flag |

### 踩过的坑

| # | 坑 | 教训 |
|---|---|---|
| 1 | `"sys" + "a"*1e6 + " nb"` 打不通 | 贪婪 `.*` 吞完就找到 `nb`，回溯次数不够 → **填充放后面**：`"sys nb" + "a"*1e6` |
| 2 | 思路锁在"让正则不匹配" | 真正的出路是**让正则出错**（返回 `false`） |
| 3 | 2 万个 `a` 不够 | 未达 `backtrack_limit`（默认 `1000000`）→ 需要 ≥ 100 万 |
| 4 | `id=2` / `id=9` 没反应就放弃 | **试一个值没反应 ≠ 这条路不通**，照候选表穷举，看响应长度 |
| 5 | 只盯着页面正文找 flag | 侦察优先级：**响应头 > 静态资源 > Cookie > 正文/注释** |
| 6 | 三段 flag 拼错顺序 | 先看**长度**（5+15+12=32）和 `}` 的位置再拼 |
| 7 | 工具踩坑（非题目）：`Format-Hex` 无参无输出、PowerShell `R` 撞 `Invoke-History` 别名、`Select-Object -First` 截断中文响应 | 验证二进制 / 抓响应统一改用 **Python + `PYTHONIOENCODING=utf-8`** |

### 一句话总结

> **"没反应"是多义的** —— 正则匹配了 / 参数没进去 / 分支走错 / 编码被吃。
> 必须靠**基线对照**（`abc` vs `sys nb`）和**可验证中间量**（响应长度、Content-Length）来定位，而不是靠猜。
